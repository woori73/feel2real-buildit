## 1. 편집 철학 — "꽉 채운다" ≠ "빽빽하게 붙인다"

목표는 문항 사이에 충분한 시각적 호흡이 있으면서 페이지 하단에는 불필요한 큰 공백이 남지 않는 **실제 시중 문제집 수준**이다.

- 실패 A: 문항들이 위쪽에 다닥다닥 붙고 페이지 아래가 넓게 빔.
- 실패 B: 문항마다 큰 고정 margin으로 하단이 과도하게 비거나 다음 페이지로 불필요하게 밀림.
- 정답: 각 column의 실제 콘텐츠 양을 기준으로 남는 세로 공간을 문항 사이 간격에 자연 분배하여 **"문항 간격 확보 + 하단 공간 활용" 동시 만족**.

## 2. FORMAT 사진 원칙 (내용이 아니라 리듬만 참조)

사진 속 문제는 출제 Source로 사용하지 않는다. 추출 원칙:

1. 공통지문/대화문은 하나의 시각적 Group이다.
2. 지문과 첫 문항은 너무 멀리 떨어뜨리지 않는다.
3. 같은 Group 안 문항끼리도 최소한의 명확한 시각적 간격을 둔다.
4. 다음 독립 문항·다음 Group으로 넘어갈 때는 더 분명한 여백을 둔다.
5. 문제 번호·발문·보기·선택지는 하나의 문제 block으로 인식되어야 한다.
6. 문항 block끼리 붙어 보여서는 안 된다.
7. 표/보기/서답공간 등 높이가 달라도 다음 문항과 충돌 금지.
8. 페이지 하단까지 자연스럽게 사용한다.
9. 페이지를 채우려고 글자 크기를 과도하게 줄이지 않는다.
10. 페이지를 채우려고 문제끼리 억지로 붙이지 않는다.

관찰 근거(사진): 좌단 07~09 공유 대화문 box → Q07 → 충분한 공간 → Q08 → 충분한 공간 → Q09, 하단 과잉 공백 없음. 우단 10~12 공유 대화문 → Q10(ⓐⓑⓒ 표 포함, Q11과 명확히 구분) → 공간 → Q11 → 공간 → Q12.

## 3. 기술 규칙 (A4 인쇄·기본 2단)

- 좌우 column의 문항 간격을 **독립 계산**한다. 페이지 전체 단일 qgap 강제 금지.
- 각 column은 (실제 콘텐츠 높이, 하단 안전영역, 남은 세로 공간, 문항 block 개수) 기준으로 간격 결정.
- 문항 사이 기본 최소 간격은 반드시 존재. 남은 공간은 문항 사이에 자연 분배.
- `justify-content: space-between` 등을 써도 콘텐츠 높이·column 높이가 정상 정의됐는지 확인. **CSS를 넣었다는 이유로 간격 적용 판정 금지.**

## 4. 하단 안전영역

- 페이지 하단 잘림 절대 금지. 특히 긴 선택지 ⑤, 표 마지막 행, 보기 box 하단, 공통지문 마지막 줄, column·페이지 마지막 문항.
- 절대 금지: `overflow:hidden` 숨기기, 과도 축소로 억지 삽입, 일부 잘라 다음 페이지에서 소실.
- 공간 부족 해결 순서: ① column 내 간격 재조정 → ② 문항 block 전체를 다음 column으로 이동 → ③ 다음 페이지로 자연 이동 → ④ 주변 column 여유 재배치.

## 5. 문항 이동 규칙

- column 하단 잘림 시 문항 일부만 넘기지 않고 **qblock 전체 이동**. 공통지문 Group은 함께 유지(예: [31~33] 구조를 31/다른 문제/32/33처럼 분리 금지).
- 번호 변경 시 문제지·정답·해설·빠른 정답·검수 MD의 번호를 **같은 작업에서 동시 동기화**. 위치만 바뀌고 내용 동일하면 정답값 유지 + 검수 기록에 위치 변경 명기.

## 6. 공통지문 편집

- 공통지문/대화문 + 2~3 연결문항 구조 적극 활용. 순서: Group title → 전체 지문/대화 → Q1 → Q2 → Q3. 같은 지문을 문항마다 반복 출력 금지.
- `[공통지문]` 같은 AI 제작 표시는 학생용 문제지에 노출 금지. 실제 시험지형: `[11~13] 다음 글을 읽고 물음에 답하시오.`

## 7. 보기/표/밑줄

- `<보기>` 내용은 반드시 box 내부. `<보기>` 제목은 박스 상단, a/b/c/d/e는 다음 줄부터. 박스 밖 텍스트·번호는 실패. 보기-선택지 간격 확보. 보기 글씨만 과도 축소 금지.
- ⓐⓑⓒ/(A)(B)/복수 조건 조합은 `/` 나열이 아니라 **table**(또는 정렬 보장 DOM). 5회 Q5·Q27·Q30 조합표 형식 우선 참고. 열 머리글-선택지 단어 시작선 일치.
- `밑줄 친` 발문이면 실제 지문에 solid underline이 있어야 하며 번호는 단어 바로 옆. 선택지에서도 본문과 같은 밑줄 표현 유지. 발문이 요구하지 않는 밑줄은 제거.

## 8. Browser Print QA (최종 기준 = Print)

- HTML/DOM 계산만으로 PASS 금지. 반드시 실제 Chrome/Chromium A4 Print 결과 확인. 실행 못 했으면 `BROWSER PRINT QA = NOT VERIFIED` 기록, 추측 VERIFIED 금지.
- 페이지별 확인: 상·하단 잘림, 좌/우단 마지막 문항, ⑤ 선택지, 긴 보기, 표, 공통지문, column 전환 지점, footer 침범, 과도 하단 공백, 문항 다닥다닥 여부.
- **"하단은 많이 비었는데 위 문항들이 서로 붙어 있음"이면 FAIL** → 남는 공간을 문항 간격에 재분배.
