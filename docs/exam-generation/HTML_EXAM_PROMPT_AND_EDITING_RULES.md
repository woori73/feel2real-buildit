# BuildIt 내신 시험지 HTML 출제·편집 필수 규칙

> **MANDATORY — OpenCode/AI Agent는 문제 제작 전에 반드시 읽는다.**

## FORMAT MASTER

현재 기준 문제지는 다음 파일이다.

`신구중2_2026_2학기_중간고사_4회_70문항_문제지_8PAGE_FINAL_v15_BROWSER_VERIFIED.html`

이 파일을 같은 작업공간/저장소에서 사용할 수 있으면 반드시 먼저 열어 DOM, CSS, A4 2단, 문항 블록, 선택지, 보기, 편집 기능을 읽고 **이 파일을 FORMAT MASTER로 복제하여 제작**한다. 새 디자인을 만들지 않는다.

문항 길이가 달라지므로 MASTER의 문항 위치를 기계적으로 복제하지 않는다. 실제 Chrome/Chromium 렌더 높이를 측정하여 단과 페이지를 재배치한다.

상단 학생 정보는 `반/번호` 행을 쓰지 않고 `이름 / 요일 / 점수` 한 줄을 사용한다.

## 발문

- 새 긴 지문: `다음 글 ...`
- 바로 위 공통지문 참조: 실제 공통지문이 있을 때만 `윗글 ...`
- 독립 한 문장: `다음 문장의 ...`
- 새 대화: `다음 대화를 ...`
- 문자열 일괄치환 금지. Q1~끝까지 의미를 읽고 판단한다.
- 실제 오류 사례: `The movie is so ____ that ...` 같은 독립 문장을 `윗글`로 지칭하면 안 된다.

## <보기>

- `<보기>`는 박스 상단 가운데.
- a가 `<보기>` 옆에서 시작하면 안 된다. 다음 줄부터 a, b, c, d를 시작한다.
- 보기 박스와 그 아래 선택지는 붙이지 말고 충분한 세로 간격을 둔다.
- 7, 12, 22, 30, 40, 62, 66, 70번 같은 유형에 공통 적용한다.

## 선택지

짧다고 무조건 ①~⑤를 한 줄에 압축하지 않는다. 독립된 문장/내용이면 **한 선택지당 한 줄**이 기본이다. 단어 하나나 매우 짧은 표현처럼 실제 시험지에서 자연스러운 경우에만 가로 배치할 수 있다.

DOM 순서는 반드시 `① → ② → ③ → ④ → ⑤`이다. CSS로 보이는 순서만 바꾸지 않는다. 이번 수정에서 29, 30, 35, 36, 38, 39, 40, 41, 55 등에서 순서 뒤틀림이 실제 발생했으므로 전 문항 검사한다.

두 줄 이상 선택지는 둘째 줄이 동그라미 번호 아래로 들어가지 않게 hanging indent를 적용한다.

- 15, 17, 29: 일반 세로 선택지와 동일한 시작선/줄 간격.
- 19: 불필요한 ⑧·⑨ 반복 표시 삭제. 공간이 있으면 한 선택지당 한 줄.
- 55: (a)(b)(c) 조합은 위에 (a)(b)(c)를 두고 아래에 ①~⑤와 단어가 정렬되는 표 구조 권장.
- 57: 문장 자체에 이미 ①~⑤가 있으면 아래에 `①① / ②② ...` 같은 중복 선택지를 절대 만들지 않는다.

## 밑줄/특수 발문

`밑줄 친`이라고 물으면 실제 지문의 해당 표현에 `<u>`가 있어야 한다. 4번처럼 발문만 있고 실제 밑줄이 없는 상태는 실패다.

41번처럼 인물 지칭이 모호하면 `스코필드 박사`처럼 명확히 한다.

52번 사례처럼 불필요한 배열 재료와 빈칸 문장을 중복 제시하지 말고 실제 선택지 구조에 맞춰 `다음 중 어법상 가장 적절한 문장을 고르시오.`처럼 발문을 맞춘다.

## A4 2단 FORMAT — 가장 중요

첨부 실제 문제집처럼 **페이지 전체를 가독성에 사용**한다.

금지:
- `한 페이지 몇 문항`, `왼쪽 5개/오른쪽 5개`처럼 개수만 보고 배치
- 왼쪽 단 하단을 침범하면서 문항을 억지로 넣기
- 한쪽 단만 지나치게 길고 반대쪽은 크게 비우기
- 페이지 아래가 크게 비는데 문항을 위쪽에 몰아넣기
- overflow:hidden으로 잘린 문항을 숨기기
- 문제를 고칠 때마다 nth-of-type/page별 임시 CSS를 계속 덧붙이기

올바른 방식:
1. 왼쪽 단을 위→아래로 읽고 오른쪽 단으로 이동한다.
2. 다음 문항 전체가 safe bottom을 넘으면 문항 블록 전체를 다음 단으로 넘긴다.
3. 문항을 단/페이지 중간에서 자르지 않는다.
4. 좌우 단의 **실제 렌더 높이**를 비교한다.
5. 한쪽이 너무 길면 마지막 문항을 다음 단/페이지로 옮긴다.
6. 하단 여유가 많으면 글씨를 억지로 키우지 말고 문항↔문항, 지문↔선택지, 보기↔선택지 간격을 넓혀 실제 문제집처럼 사용한다.
7. 하단 침범 시 글씨부터 줄이지 말고 문항을 다음 단/페이지로 이동한다.

20·21번, 31번 등이 과거 화면에서 사라진 원인은 개수 기준 배치와 overflow였다. 반드시 브라우저에서 각 qblock의 실제 bottom을 측정한다.

완료 조건: **모든 qblock.bottom이 column/page safe bottom 안에 있어야 한다.**

`space-between` 하나로 페이지 전체를 기계적으로 벌리는 방식도 금지한다. 공통 spacing 규칙을 사용한다.

## HTML 편집 가능성

문제 번호/발문/지문/보기/선택지를 이미지로 만들지 않는다. 실제 HTML 텍스트로 유지하고 모든 문항에 `data-qnum`을 둔다. 가능하면 `편집모드 켜기`와 `수정 HTML 저장`을 유지하며 toolbar는 인쇄 시 숨긴다.

## 브라우저/인쇄 QA

눈대중과 grep만으로 PASS하지 않는다. Chrome/Chromium으로 1~마지막 페이지를 실제 렌더링하고 페이지별 스크린샷 또는 DOM 측정을 수행한다.

반드시 확인:
- 목표 페이지 수
- Q1~끝 번호 누락/중복 0
- 하단 침범 0
- 문항 잘림 0
- 좌우 단 심한 불균형 없음
- 2단 유지
- footer 겹침 없음
- 선택지 ①~⑤ DOM 순서 정상
- 중복 선택지 없음
- hanging indent 정상
- `<보기>` 정렬/간격 정상
- 밑줄/빈칸/발문 대응 정상

## 정답·해설은 레이아웃 수정 후 다시 대조

선택지를 재정렬/삭제한 뒤에는 반드시 정답해설지를 다시 비교한다.

- 빠른 정답과 문항별 정답 일치
- 현재 문제지 ①~⑤ 내용과 정답 번호 일치
- `옳은/옳지 않은` 발문과 해설 논리 일치
- 선택지 순서를 고친 뒤 과거 번호를 정답이 계속 가리키지 않는지 확인
- 57번처럼 별도 선택지를 삭제해도 정답 번호가 실제 문장 번호를 가리키는지 확인
