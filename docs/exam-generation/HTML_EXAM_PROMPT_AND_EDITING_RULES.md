# BuildIt 내신 시험지 HTML 출제·발문·인쇄·편집 필수 규칙

> **상태: MANDATORY / 문제 제작 전 반드시 읽을 것**
>
> OpenCode 및 AI Agent가 학교별 시험 문제지 HTML을 신규 제작하거나 수정할 때 이 문서를 먼저 읽고 준수한다.
> 문항 내용만 맞는 것으로 완료 처리하지 않는다. 발문-제시자료 관계, HTML 인쇄, 직접 편집 가능성까지 최종 산출물의 일부다.

## 1. 작업 시작 전 필수 절차

1. 학교/학년/연도/학기/시험/회차/문항 수를 확인한다.
2. 해당 학교의 기출, 학교 학습지·필기, Digital Twin, 기존 승인 시험지/제작 원칙을 먼저 읽는다.
3. 기존 승인 포맷이 있으면 새 디자인을 만들지 말고 최대한 재사용한다.
4. 문제를 만든 뒤 **전 문항을 1번부터 마지막 번호까지 순서대로 다시 읽는다.**
5. 특히 발문을 별도 검수한다. 문자열 검색/일괄 치환만으로 검수 완료 처리하지 않는다.

---

## 2. 발문은 제시 자료와 반드시 일치해야 한다

### A. 해당 문항에서 긴 지문을 처음 제시하는 경우

사용:
- `다음 글의 흐름상 빈칸에 들어갈 말로 가장 적절한 것은?`
- `다음 글의 내용과 일치하는 것은?`
- `다음 글의 주제로 가장 적절한 것은?`

금지:
- 새 지문을 문항 안에 제시하면서 `윗글`이라고 쓰는 것.

### B. 바로 앞 문항에서 제시한 공통 지문을 계속 사용하는 경우

사용:
- `윗글의 내용과 일치하는 것은?`
- `윗글에서 밑줄 친 it이 가리키는 것은?`
- `윗글의 밑줄 친 표현과 의미가 가장 가까운 것은?`

즉, **실제로 위에 공유 지문이 존재할 때만 `윗글`을 사용한다.**

### C. 독립된 한 문장/예문을 해당 문항 안에 제시하는 경우

사용:
- `다음 문장의 빈칸에 들어갈 말로 가장 적절한 것은?`
- `다음 문장에서 밑줄 친 표현의 쓰임으로 적절한 것은?`

금지:
- `윗글의 흐름상 빈칸에 ...`
- `다음 글의 흐름상 ...`

한 문장은 `글`이 아니라 **`문장`**으로 지칭한다.

#### 실제 오류 사례

잘못:
`49. 윗글의 흐름상 빈칸에 들어갈 말로 가장 적절한 것은?`

제시 자료:
`The movie is so ______ that I want to cry.`

수정:
`49. 다음 문장의 빈칸에 들어갈 말로 가장 적절한 것은?`

이 오류는 정답이 맞더라도 최종 검수 실패로 처리한다.

### D. 대화를 새로 제시하는 경우

사용:
- `다음 대화를 읽고, ...`
- `다음 대화의 내용과 일치하는 것은?`

독립 대화인데 `윗글`이라고 하지 않는다.

### E. <보기>를 기준으로 묻는 경우

사용:
- `다음 보기의 진술 중 옳은 것을 모두 고르면?`
- 필요한 경우 `<보기>`를 명확히 제시한다.

### F. 두 문장 이상을 (A), (B)로 제시하는 경우

사용:
- `다음 두 문장의 빈칸에 공통으로 들어갈 말은?`
- `다음 (A), (B)에 들어갈 말을 바르게 짝지은 것은?`

(A), (B)는 가독성을 위해 각각 별도 줄에 둔다.

---

## 3. 금지: 발문 문자열 단순 일괄 치환

`윗글`을 모두 `다음 글`로 바꾸는 방식은 금지한다.

이유:
- 공통 지문 후속 문제에서는 `윗글`이 맞다.
- 새 긴 지문에서는 `다음 글`이 맞다.
- 독립 한 문장에서는 `다음 문장`이 맞다.
- 대화에서는 `다음 대화`가 맞다.

따라서 각 문항의 DOM 구조와 실제 제시자료를 읽어 의미적으로 판단한다.

## 4. 전 문항 발문 QA 체크

최종 저장 전에 1번부터 마지막 문항까지 다음을 검사한다.

- [ ] `윗글`이라고 했는데 실제 바로 위에 공유 지문이 있는가?
- [ ] 새 지문이면 `다음 글`이라고 했는가?
- [ ] 한 문장만 제시했으면 `다음 문장`이라고 했는가?
- [ ] 대화문이면 `다음 대화`라고 했는가?
- [ ] `<보기>` 문제는 보기와 발문이 실제로 대응하는가?
- [ ] `(A)`, `(B)`, `(a)`, `(b)` 표기와 발문이 일치하는가?
- [ ] `밑줄 친`이라고 했으면 실제 해당 표현에 밑줄이 존재하는가?
- [ ] `빈칸`이라고 했으면 실제 지문/문장에 빈칸이 존재하는가?
- [ ] `옳지 않은 것` / `옳은 것`과 정답이 뒤바뀌지 않았는가?
- [ ] `모두 고르면` 유형에서 보기와 선택지 조합이 일치하는가?

**grep 결과만으로 PASS하지 말고 브라우저 렌더링과 문항 의미를 함께 확인한다.**

## 5. HTML은 나중에 사람이 직접 고칠 수 있게 만든다

시험지 HTML은 AI에게 다시 요청하지 않아도 교사가 사소한 오타를 직접 수정할 수 있는 구조를 권장한다.

### 필수 원칙

- 문제 번호, 발문, 지문, 보기, 선택지를 이미지로 만들지 않는다.
- 실제 HTML 텍스트로 유지한다.
- 문항마다 안정적인 식별자를 둔다.

예:

```html
<div class="qblock" data-qnum="49">
  <div class="qhead">
    <span class="qnum">49.</span>
    <span class="qprompt">다음 문장의 빈칸에 들어갈 말로 가장 적절한 것은?</span>
  </div>
  <div class="passage prose">The movie is so ______ that I want to cry.</div>
</div>
```

- 가능하면 화면의 `편집모드`에서 발문/지문/보기/선택지를 직접 수정할 수 있게 한다.
- 편집 UI는 `@media print`에서 반드시 숨긴다.
- `수정 HTML 저장` 기능을 둘 경우 수정된 텍스트가 실제 저장 파일에 반영되어야 한다.
- 편집 기능 때문에 인쇄 레이아웃이 변하면 안 된다.

---

## 6. A4 인쇄는 브라우저 화면과 별도로 반드시 검증한다

화면에서 7페이지처럼 보여도 Chrome 인쇄에서 14페이지가 되면 실패다.

기본:

```css
@page {
  size: A4 portrait;
  margin: 0;
}

* { box-sizing: border-box; }
```

주의:
- `.page { height: 297mm; }`와 padding/border/flex/page-break 조합은 브라우저 인쇄 반올림 때문에 빈 추가 페이지를 만들 수 있다.
- A4의 이론적 최대 높이에 딱 맞추는 것보다 인쇄 안전영역을 둔다.
- `page-break-after` / `break-after`를 함께 점검한다.
- 마지막 페이지는 불필요한 강제 page break를 만들지 않는다.
- `overflow:hidden`으로 문항이 잘린 상태를 페이지 수 성공으로 오판하지 않는다.

### 인쇄 QA

Chrome print 또는 headless Chromium/PDF 렌더링으로 확인한다.

- [ ] 목표 페이지 수와 실제 PDF 페이지 수가 같은가?
- [ ] 화면의 2단 구조가 인쇄에서도 유지되는가?
- [ ] 문항이 다음 페이지로 잘리거나 사라지지 않는가?
- [ ] 페이지 하단 문항/선택지가 잘리지 않는가?
- [ ] 빈 페이지가 생기지 않는가?
- [ ] footer가 본문과 겹치지 않는가?
- [ ] 편집 버튼 등 화면 UI가 인쇄되지 않는가?

## 7. BuildIt 시험지 공통 편집 원칙

- A4 인쇄 기준을 우선한다.
- 기존 승인 시험지의 2단 포맷을 임의로 변경하지 않는다.
- 여백은 낭비하지 않되 가독성을 해치지 않는다.
- 문항 블록은 가능하면 페이지/단 중간에서 찢어지지 않게 한다.
- 선택지는 번호와 내용이 붙어 읽히도록 한다.
- 밑줄 번호가 필요한 경우 번호는 해당 밑줄 단어 바로 옆에 둔다.
- 지문 빈칸이 2개 이상이고 구분이 필요한 경우 (a), (b) 등과 발문을 정확히 대응시킨다.
- 빠른 정답/해설 등 별도 산출물이 있다면 문제 번호와 1:1 대응을 검증한다.

---

## 8. OpenCode/Agent 완료 보고에 반드시 포함할 것

문제 제작 후 단순히 `완료`라고 보고하지 않는다. 최소 다음을 보고한다.

1. 생성/수정한 파일 경로
2. 총 문항 수 및 번호 연속성
3. 발문-제시자료 QA 결과
   - `윗글` 사용 문항
   - `다음 글` 사용 문항
   - `다음 문장` 사용 문항
   - `다음 대화` 사용 문항
4. 밑줄/빈칸/보기 표기 QA 결과
5. Chrome/PDF 실제 인쇄 페이지 수
6. 잘림/빈 페이지 여부
7. 직접 편집 기능 정상 여부(적용한 파일일 경우)
8. 발견한 오류와 수정 내역

---

## 9. 최종 Gate

다음 중 하나라도 해당하면 FINAL로 이름 붙이지 않는다.

- 발문이 실제 제시자료와 맞지 않음
- 독립 문장을 `윗글`이라고 지칭함
- 새 지문을 `윗글`이라고 지칭함
- 공통 지문 후속 문항인데 `다음 글`로 잘못 지칭함
- `밑줄 친`이라고 했으나 밑줄 없음
- 빈칸 발문인데 빈칸 없음
- 정답/선택지와 발문 조건 불일치
- 목표 인쇄 페이지 수와 실제 페이지 수 불일치
- 인쇄 시 문항 잘림/빈 페이지 발생

**핵심 원칙: 문제의 정답만 맞으면 끝이 아니다. 학생이 실제로 읽는 발문과 인쇄 결과까지 시험 문제의 일부다.**
