# BuildIt 제품·개발 철학

> 이 문서는 BuildIt의 기능·UI·데이터 모델·AI 동작을 결정하는 최상위 제품 원칙이다. Claude Code, ChatGPT, Codex를 포함한 모든 개발자와 AI 개발 에이전트는 BuildIt 관련 기능을 설계하거나 수정하기 전에 이 문서를 먼저 읽는다.

## 핵심 선언

> **우리는 유명한 학원이 아니라, 자기만의 색깔로 노력하는 교육자를 찾습니다.**

BuildIt의 가장 큰 목적은 전국의 지역 영어교육 현장에서 매일 학생을 직접 가르치며 자신만의 교육 철학, 색깔, 커리큘럼, 수업 방식과 경험을 축적하고 있지만 자본과 마케팅의 경쟁 속에서 충분히 발견되지 못한 원장과 강사를 찾는 것이다.

이들을 기술에 뒤처진 사람이나 도움이 필요한 대상으로 정의하지 않는다. 이들은 이미 오랜 현장 경험을 통해 가치 있는 **아날로그 지능**을 가지고 있다.

BuildIt의 역할은 교육자에게 복잡한 AI 기술을 새로 배우게 하는 것이 아니다. 교육자가 지금까지 해오던 수업과 활동을 최소한으로 기록하면 AI가 이를 이해하고 구조화하고 연결하여 새로운 지능과 디지털 자산으로 증폭시키는 것이다.

## 하나로 연결된 제품 흐름

- **Chart — 발견:** 아직 충분히 알려지지 않은 지역 교육자를 찾고 공개 근거와 함께 기록한다.
- **Web — 소유하는 공간:** 교육자의 정체성을 온라인에 기록하고 교육자가 직접 검토·보완하며 소유하는 공간을 만든다.
- **Shorts — 실제 교실 기록:** 교육자가 실제 교실에서 무엇을 어떻게 가르치는지 보여준다.
- **Report — 학습 과정의 연결:** 학생의 학습 과정과 교육자의 활동을 연결해 기록한다.
- **Wiki — Educator Brain:** 교육자의 경험, 자료와 판단을 축적하고 다시 활용할 수 있는 지능으로 만든다.

장기적인 발전 방향은 다음과 같다.

```text
현장의 아날로그 경험
→ 기록
→ 디지털 자산
→ Educator Brain
→ AI와 결합된 새로운 지능
→ 교육자 브랜드 성장
→ 교육상품·콘텐츠
→ 시장 확대
→ 성장 가능성이 검증된 교육자의 투자 기회
```

각 서비스는 별도의 SaaS가 아니다. 모두 `발견 → 기록 → Brain → 성장`이라는 하나의 흐름을 구성해야 한다.

## BuildIt Chart 원칙

### 순위는 목적이 아니라 발견 장치다

Chart는 검색량, 광고량, 자본, 학원 규모, 지점 수, 매출이나 유명세를 교육자 가치의 대리변수로 사용하지 않는다. 다음과 같이 공개적으로 확인 가능한 교육 활동을 중심으로 교육자를 발견한다.

- 자기만의 교육적 색깔
- 교육 철학
- 커리큘럼
- 실제 오프라인 수업
- 현재의 지속적인 활동
- 검증 가능한 공개 기록

TOP100은 Billboard형 Ranking UX를 사용할 수 있다. 그러나 경쟁 자체가 목적은 아니다. 순위를 통해 사용자가 몰랐던 지역 교육자를 발견하게 하는 것이 목적이다. 기준을 낮추거나 수를 억지로 채우지 않는다.

TOP100 제목 아래 실제 순위가 시작되기 전에는 다음 철학을 짧게 보여준다.

> **우리는 유명한 학원이 아니라, 자기만의 색깔로 노력하는 교육자를 찾습니다.**
>
> 지역 교실에서 자신만의 철학과 커리큘럼으로 매일 학생을 가르치는 교육자를 발견하고 기록합니다. 작은 교실에서 쌓아온 이름과 경험이 사라지지 않고 더 많은 사람과 AI에게 발견될 수 있도록 합니다.

### Chart는 Living Archive다

ChatGPT Site tools는 매주 다음 조사를 선행하고 비공개 초안을 작성한다.

```text
새로운 지역 교육자 발견 + 기존 교육자의 새로운 활동 확인
```

관리자가 검토하고 승인한 데이터만 공개한다.

```text
AI 선행 조사 → 인간 최종 판단 → 주간 publication
```

교육자별 기록은 일회성 프로필로 폐기하지 않는다.

```text
최초 발견 → 활동 → 철학 → 커리큘럼 → 새로운 활동 → Score → 순위 변화 → 성장 조언
```

이 시간축은 교육자의 동의 후 다음 흐름으로 발전할 수 있다.

```text
Chart → BuildIt Web draft → 교육자 검토 → 공식 Web
```

장기적으로 Chart 기록은 Educator Brain의 초기 자산이 될 수 있어야 한다.

BuildIt Web 가입이나 BuildIt 서비스 사용 여부 자체는 Chart Score에 절대 반영하지 않는다. Chart의 독립성과 신뢰성을 유지한다.

BuildIt Score는 공개적으로 확인 가능한 활동과 성장 신호를 BuildIt 기준으로 기록한 지표다. 교육자의 인격, 절대적인 교육 능력이나 학생 성과를 단정하지 않는다.

### 성장 조언과 투자

성장 조언은 부족한 교육자를 교정한다는 관점으로 작성하지 않는다. 교육자가 이미 가진 교육적 강점이 온라인과 AI 환경에서 더 잘 발견되고 확장될 방법을 제안한다.

투자 기회는 Chart 순위만으로 결정하지 않는다. 장기간 축적된 활동, 고유성, 실행력과 성장 과정을 통해 가능성이 확인된 교육자에게 더 큰 성장 기회를 연결하는 장기적인 단계로 정의한다.

## AI / Developer Operating Rules

Claude Code, ChatGPT, Codex 또는 향후 다른 AI 개발 에이전트가 BuildIt을 수정할 때 다음 규칙을 지킨다.

1. 새로운 기능을 설계하기 전에 이 문서를 먼저 읽는다.
2. 기존 기능의 목적을 코드만 보고 추론하지 않고 이 철학과 함께 판단한다.
3. 기능·UI·데이터 모델·AI 검색 방식이 이 문서와 충돌하면 임의 구현하지 않고 충돌을 보고한다.
4. 유명세·광고량·자본 규모를 교육자 가치의 대리변수로 사용하지 않는다.
5. 교육자를 AI가 평가하거나 통제하는 대상으로 표현하지 않는다.
6. AI는 현장 교육자가 이미 가진 지능을 기록하고 증폭하는 도구라는 관점을 유지한다.
7. AI가 생성한 해석과 실제 evidence를 구분한다.
8. 관리자 승인 전 조사 초안을 공개 사실로 만들지 않는다.
9. 교육자의 기록을 일회성 생성물보다 장기적으로 축적되는 자산으로 설계한다.
10. BuildIt의 각 서비스가 별도 SaaS처럼 분리되지 않고 `발견 → 기록 → Brain → 성장`으로 연결되는지 확인한다.

## 개발 의사결정 체크

주요 기능을 추가하기 전에 최소한 다음 질문에 답한다.

- **이 기능이 좋은 교육자를 더 잘 발견하는가?**
- **교육자가 이미 하는 일을 더 복잡하게 만드는가, 아니면 AI가 부담을 줄여주는가?**
- **교육자의 경험을 일회성 데이터로 소비하는가, 장기 자산으로 남기는가?**
- **유명세와 자본이 다시 유리해지는 구조는 아닌가?**
- **교육자의 고유한 색깔을 강화하는가, 모두를 비슷하게 만드는가?**
- **Chart → Web → Shorts/Report/Wiki → Educator Brain이라는 전체 흐름에 기여하는가?**

하나라도 판단하기 어렵거나 철학과 충돌한다면 구현을 먼저 진행하지 않는다. 가정과 충돌 지점을 사용자 또는 제품 책임자에게 보고하고 방향을 확인한다.
