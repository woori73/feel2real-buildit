## 로컬 검증

- Java `bootJar` 성공; 컨트롤러·실제 Thymeleaf 계약 **33/33 PASS**.
- 기존 비서/신청 안내/연락처와 영상 JS 회귀 **50/50 PASS**.
- Chromium 최종 **33/33 PASS**: 승인 트레일러 격리 스트리밍6, 홍보 영상/게임 이동10, 세븐7, 기존 신청 안내6, 정책 링크4. PC1440·모바일360/390/430(기존 신청 안내는768추가).
- 트레일러6건은 로컬 MySQL에 합성 MP4/승인 fixture를 넣고 실제 신규 endpoint·기존 SecurityConfig를 통해 검증했다. 200/206, 원본 API 비로그인 차단, 임의 파일 선택 거부, 수동 재생·정지·실패 대체 화면, 승인 해제 즉시404/영역 숨김, 조회 전후 파일/감사 건수 보존 PASS. fixture는 finally에서 정리했다. 운영 작품 원본 테스트가 아니다.
- 게임 새 탭 전달은 목적지 HTTP를 격리 fixture로 대체했으므로 실제 Nimble 게임 실행 증거가 아니다.
- 최초 트레일러 오류 주입 검사에서 load() 오류로 숨겨진 버튼을 다시 클릭하려던 테스트가 시간 초과됐다. 실패 증거를 로컬 보존하고 주입 절차를 수정해 최종 재검증했다. 5초 기준을 늘리거나 실제 재생 assertion을 제거하지 않았다.
- 승인 MP4 실제 디코딩(1920×1080, 약20초), 5초 이내 재생, 무음·소리 버튼·재생 종료/실패/자동재생 거부·reduced-motion, HTTP206 범위 요청, 가로 넘침0 확인.

## 배포 실행 연결과 남은 차단 항목

- `.github/workflows/deploy-ec2.yml`은 `workflow_dispatch` 전용. PR/CI/병합만으로 배포되지 않는다. 이번 변경은 모바일 CI에 신규 JS 테스트와 트레일러 캡처 보존을 추가하며 배포/IAM/SSM 워크플로를 변경하지 않는다.
- 현재 GitHub 연결은 조회·PR·병합·기존 job 재실행을 제공하지만 **신규 dispatch를 제공하지 않는다**. Work 브라우저 제어 도구도 없다. 로그인된 Actions 브라우저 또는 신규 workflow_dispatch를 지원하는 연결이 필요하다. 예전 배포 작업 재실행으로 대체하지 않는다.
- 기존 정상 버전 관측은 `38f40090`; [기존 기준 문서](../../DEPLOYED_BASELINE.md)와 백업 영수증을 보존한다. `app.jar.previous`는 df425588이므로 현재 버전 복구본으로 오인하지 않는다. 현재 독립 백업 읽기/해시·복구 실행 권한, 새 배포 직전 JAR/미디어 무결성은 아직 확인되지 않았다.
- 운영 신청·계좌 공개 실제값 OFF를 보여 주는 제한된 읽기 증거가 필요하다. 현재 `F2R-ReadOnlyStatus`는 해당 플래그를 읽지 않아 재실행하지 않았다. 연결된 담당자의 제한된 진단 또는 검토된 고정 조회가 필요하며 인증정보는 보고서에 넣지 않는다.
- 홈페이지 우선 배포와 신청 서비스 활성화는 분리한다. 기존 정책 문서의 검토안 표기는 유지하며 신청용 정책·계좌 승인/알림을 홈페이지의 완료 증거로 바꾸지 않는다. 이번에 신청 활성화는 승인·실행하지 않는다.
- 사용자 지정 트레일러의 실제 운영 메타데이터·승인·재생과 실제 Nimble 실행을 확인할 수 있는 브라우저/읽기 연결이 필요하다. 합성 MP4 재생을 실제 AI AGENT 작품 재생 완료로 보고하지 않는다.

신규 코드 CI 결과는 PR checks에서 최종 HEAD 기준으로 확인한다. 운영 배포 커밋은 **없음**이다.
