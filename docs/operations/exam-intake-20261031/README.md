# 사이트 신청 운영 연결 준비와 로컬 검증 — 2026-10-31

기준 GitHub main `8cb9259a3b0c70e5aee4cf7434ec2f074e6dfbaa`. 기존 신청/자료/관리자/법정대리인 도메인을 보완한다. **실제 운영 접수·배포 완료 보고가 아니다.** 이번 사용자 지시는 신규 신청 테이블 설치·설정·배포·합성 신청까지 승인하지만 기존 고객 데이터 변경·DB 전체 복원·권한 확대는 제외한다.

## 반영한 변경

- 홈페이지 첫 신청 버튼도 기존 `examIntakeEnabled` 값에 따라 `/exam-service`로 연결한다. OFF일 때 카카오톡·이메일과 기존 준비 안내 유지. 기존 공개 사업자/계좌 정보·영상·게임·Studio/NewStart 코드는 보존한다.
- 폼에서 선택 자료를 첨부하고 동의한 뒤 신청을 저장한다. 접수번호를 먼저 보존하고 같은 접수에 자료를 제출한다. 자료 실패는 성공 문구로 덮지 않고 실패 자료 재시도를 제공한다. 신청/파일이 모두 하나의 DB 트랜잭션이라는 뜻은 아니다.
- 응답 유실·목록 조회 실패 후 같은 신청을 다시 만들지 않는다. 브라우저에는 무작위 접수 재시도 키만 보관하고 서버에서 **본인 소유의** 저장 결과를 복구한다. 개인정보/본문/파일/인증정보는 브라우저 저장소에 추가하지 않는다. URL에 접수 ID만 들어가는 본인 조회 링크 제공.
- 신청 저장과 알림 상태를 분리한다. SMTP 서버 수락 `SENT`는 수신 확인이 아니다. 관리자가 실제 수신함의 이벤트 ID를 확인한 뒤 별도 확인 이력을 남긴다. 소진된 실패 알림만 관리자 재전송 가능. 동일 접수/이벤트 중복 생성 방지 유지.
- 2026-10-30 시행 문서와 새 동의 버전을 맞춘다: `exam-intake-20261030-v1`, `exam-privacy-20261030-v1`, `exam-terms-20261030-v1`. 과거 동의·계약 스냅샷은 수정하지 않는다. 만14세 미만 보호자 전자동의→관리자 전화 확인→아동 정보 제출 흐름 유지.
- 30일 경과 미계약·미입금 건도 관리자 보존 검토 목록에 포함한다. 목적 달성·법적 유보 없음 확인 후 종결 및 학습자료 정리하며, 진행 중인 요청/분쟁·입금 확인 건은 임의 정리하지 않는다. 자동 환불·자동 송금·자동 고객 데이터 삭제는 추가하지 않는다.

## 운영 연결을 이번 환경에서 새로 확인한 결과

- GitHub API/브랜치 읽기 및 Git fetch/push 가능. main Build Check `41010605876`, 수동 Deploy to EC2 `41011029859` 성공 기록 확인. 이것은 이전 운영 버전의 결과이며 이번 신청 활성화 증거가 아니다.
- 현재 cloud 설정: `observations_current=true`, 연결 자체 정상, AWS outbound identity/secret/runtime binding 없음. VPN/TCP 운영 접근도 없음. 운영·AWS·GitHub API 호스트는 셸 네트워크 허용 목록에 없음. `gh api .../actions/workflows/deploy-ec2.yml` 실제 읽기 시도는 `Forbidden`.
- 연결 GitHub 도구는 읽기/PR/병합을 제공하지만 신규 `workflow_dispatch` 도구가 없다. 로그인된 Work 브라우저 제어 도구도 노출되지 않았다. 과거 실패한 SSM 감사나 배포 job을 재실행하지 않았다.
- 신규 운영 스키마 존재 여부·Flyway 이력·실행 플래그·비공개 볼륨·정의 파일·SMTP/수신함을 이 연결로 검증할 수 없다. 코드 기본값을 운영값으로 보고하지 않는다.

## 연결 후 실행할 절차 (기존 승인 범위)

1. 현재 운영 인스턴스에서 기존 접근 권한으로 `python3 scripts/operations/exam-intake-preflight.py --env-file /etc/f2r/env` 실행. 기존 `a1-precheck.py`의 비밀 MySQL 설정 전달을 재사용하며 DB는 READ ONLY. 접수 원문·계좌·주소·비밀번호는 출력하지 않는다. 실행 환경과 파일 설정을 구분하고 추가 속성 소스가 있으면 실제 Spring 우선순위를 확인한다.
2. **운영 보고서가 있어야** `python3 scripts/operations/prepare-exam-intake-migration.py <report.json> --output <검토용디렉터리>`로 후보 SQL을 만든다. 기존 테이블이 하나라도 있으면 생성을 거절하고 실제 열/인덱스/제약을 대조해야 한다. 최신 main 최고 V1096, 다음 후보 V1097은 운영 이력 확인 전 확정하지 않는다. 후보를 리뷰한 후 신규 Flyway 파일로 추가·CI. 적용된 파일/번호/기존 데이터는 수정하지 않는다.
3. 공개 미디어와 분리된 비공개 볼륨(소유 서비스 계정, 디렉터리0700/파일0600)을 준비하고 기존 백업 경로에서 복원 및 삭제 보존을 확인한다. 실제 ClamAV와 최신 운영 정의 파일, 정상 샘플 및 안전한 EICAR 검사 필요. 저장소의 시험 서명/로컬 래퍼를 운영 검사기로 사용하지 않는다.
4. 기존 비밀 설정 경로에서 SMTP 발신자·수신자를 등록하고 연결/읽기/쓰기 timeout을 설정한다. 필요한 키: `SPRING_MAIL_HOST/PORT/USERNAME/PASSWORD`, `APP_EXAM_INTAKE_NOTIFICATION_FROM/RECIPIENT`, `APP_EXAM_INTAKE_EMAIL_NOTIFICATIONS_ENABLED=true`. 인증값은 채팅/PR/CI 로그로 전달하지 않는다.
5. 현재 시행 정책 기준으로 `APP_EXAM_INTAKE_RETENTION_REVIEWED_POLICY_VERSION=exam-privacy-20261030-v1`, `APP_EXAM_INTAKE_REFUND_REVIEWED_POLICY_VERSION=exam-terms-20261030-v1` 설정. 관리자 검토/삭제 기능 및 30일 처리 담당·백업 파기 기준 확인. 법정대리인 전화 확인 담당 확보.
6. 기존 정상 JAR/환경파일 독립 백업·해시·복구 권한 확인 후 기존 수동 Deploy to EC2 경로 사용. 신규 테이블만 설치한다. 관리자 계좌 사전 등록/승인을 확인하고, 공개 계좌와 동일한 승인본인지 대조한다. `APP_EXAM_INTAKE_ENABLED=true`와 홈페이지 링크는 같은 설정에 연결되어 있다. 접수 내 계좌 공개는 승인된 관리자 계좌가 있을 때만 별도 `APP_EXAM_INTAKE_BANK_PUBLIC_ENABLED=true`. 홈페이지의 이미 공개된 계좌는 기존 `APP_HOME_BANK_TRANSFER_PUBLIC`을 보존한다.
7. 실제 학생/입금 없는 합성 신청 1건: 제출→DB 저장/접수번호→본인 조회→관리자 조회→파일 안전 검사→알림 실제 수신→수신 이력. PC/390 화면·권한·오류 재시도 및 기존 기능 확인. 성공 전 완료로 보고하지 않는다.
8. 실패 시 신규 접수 플래그 OFF, 환경/JAR을 검증된 보관본으로 복구. 추가한 테이블과 생성된 접수 기록은 보존하며 DB 전체 복원/삭제를 하지 않는다. 기존 Studio/미디어 경로는 변경하지 않는다.

## 필요한 연결 (권한 확대 요청 아님)

- 기존 운영 권한을 쓸 수 있는 AWS OIDC/SSM 또는 SSH 연결: 운영 스키마/플래그 조회, 승인된 신규 테이블·비공개 디렉터리·설정 적용에 필요. 새 IAM 권한 확대나 관리자 역할 생성은 이번 작업에 포함하지 않는다.
- `workflow_dispatch` 실행이 가능한 GitHub Actions 연결(기존 저장소 Actions write) 또는 로그인된 Actions 브라우저. 수동 배포 입력과 실행 SHA를 확인할 수 있어야 한다.
- 운영 HTTPS 접속 허용 및 운영 테스트용 고객/관리자 로그인, 담당 알림 수신함의 실제 확인 경로. 자격정보는 관리된 비밀 바인딩/로그인 세션으로 제공한다.

신규 유료 서비스/인프라, 실제 입금/환불, 기존 고객 데이터 수정은 실행하지 않았다.
