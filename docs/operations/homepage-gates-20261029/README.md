현재 SSM `predeploy-check`는 다른 설정 네 개의 **이름 존재 여부만** 확인한다. 신청 플래그 값, 계좌 상태, 미디어 경로·해시를 반환하지 않는다. 읽기 전용 IAM 정의도 `F2R-ReadOnlyStatus` 실행에 한정된다. 현재 설치된 IAM 정책 전체를 독립적으로 조회한 것은 아니다.

다음 증거 수집은 고정 읽기 전용 명령으로 허용된 키만 필터링하고 `enabled/disabled/unknown`과 근거 종류만 출력해야 한다. 운영 환경 파일 전체, `/proc/.../environ` 전체, JVM 옵션 전체, 계좌번호, 인증 토큰은 출력하지 않는다. 환경변수만 없다고 false로 확정하지 않는다. 실행 인수·JVM 속성·Spring JSON·프로파일/외부 설정의 우선순위까지 대조하고, 실행 중 값과 다음 JAR 시작에 적용할 값을 구분한다. 미지원 구버전이나 확인 불가능한 설정 출처는 unknown으로 남긴다. 공개 Actuator env를 새로 열지 않는다.

관리자 계좌 조회는 스키마 존재 확인 후 읽기 전용 트랜잭션에서 등록 존재/승인 여부만 집계하거나, 인증된 ADMIN 응답을 클라이언트에서 필터링한다. `SELECT *`와 원문 계좌 출력은 하지 않는다. 관리자 계좌 기능이 ON이어도 신청·계좌 공개 ON을 뜻하지 않으며, 고객 비노출과 관리자 접근 통제를 별도로 확인한다.

## 정책 및 사업자 정보의 적용 범위

현재 후보는 회원가입·로그인, 학습·콘텐츠·AI, 이메일·카카오 문의 링크를 유지한다. 신청 서버가 OFF이어도 이 기존 서비스들의 개인정보 처리는 사라지지 않는다. **NewStart 확장 프로그램 전용 정책으로 홈페이지 전체를 대체할 수 없다.**

- 전체 개인정보: 실제 수집 목적·항목·필수/선택, 보유/파기, 위탁·제3자 제공·국외 이전, 보호책임자·권리 행사 창구, 기존 미성년 이용자의 처리 절차가 확인돼야 한다. 현재 검토안의 미확정 항목을 법적 요건 충족으로 판정하지 않는다.
- 전체 이용약관/환불: 기존 계약과 서비스 범위의 적용 관계·책임 범위·법정 권리를 확인한다. 새 신청용 회차 정산표를 기존 모든 서비스에 소급 적용하지 않는다. 승인자·버전·시행일 증거는 미확보다.
- 사업자 정보: 기존 압구정에듀홀릭 출판사 정보를 보존했다. 최신 등록증·신고증 대조는 미검증이며 임의로 주소를 변경하지 않는다. 증명서 파일을 찾지 못했다는 사실만으로 주소가 틀렸다고 단정하지 않는다. 공개 법정 표시의 누락·오류가 확인되면 일반 배포에서도 해소해야 한다.
- 연결된 자료 검색에서 최종 승인 기록을 식별하지 못했다. 모든 외부 보관 자료에 승인 기록이 없다는 뜻은 아니다. 정책 PR 병합은 법적 검토·정책 최종 승인과 구분한다.

RDS 새 복원 인스턴스 생성도 이번 범위에 포함하지 않는다.
6. **실제 복구 권한:** 71개 로컬 assertion은 손상 백업 거부, 실패 후 JAR/env 복원, 순서·소유자·권한·비밀정보 미출력 로직을 확인했다. 실제 38f40090 JAR 부팅이나 현재 IAM 복원 권한 검증을 대신하지 않는다. 과거 PR914 복구 성공도 현재 일반 배포 권한의 증거로 대체하지 않는다.
7. **GitHub 실행:** 저장소 Actions → Deploy to EC2 → Run workflow가 일반 배포 경로다. 실제 사용은 필수 조건 PASS 후 승인 커밋을 가리키는 ref를 확인하고 `target=new`, 기능 스위치는 `unchanged`로 고정해야 한다. 모든 입력의 변경 영향을 사전 확인한다. 이 세션의 연결은 조회·기존 job 재실행만 노출하며 신규 dispatch 기능은 없다. 로그인된 Actions 브라우저 또는 지원되는 dispatch 연결이 필요하다. 예전 배포 job 재실행은 대안이 아니다.
8. **운영 브라우저:** Work 브라우저 제어 연결 또는 환경의 운영 호스트 네트워크 허용이 필요하다. 현재 세션에는 브라우저 도구가 없고 운영 호스트가 허용 목록에 없다. 도메인 접속 실패를 반복하지 않았다. 1440/360/390/430px, 4개 정책 링크, 기존 캐릭터/AI 비서/메뉴/로그인과 CDN·캐시 헤더를 확인한다. 새 MP4·PNG는 배포 전엔 로컬/CI 결과만 유지한다.

## 배포 재개 시 범위와 남은 승인

일반 배포 전의 필수 미검증은 실제 OFF 값, 기본 개인정보 고지 승인, 현재 미디어·38f40090 백업과 복구권한, 신규 dispatch/운영 검증 연결이다. 기존 홈페이지 배포 승인을 다시 요청하는 단계는 아니다. 필요한 정책 승인 기록·새 권한 설정 또는 DB/인프라 변경이 생기면 그 구체적인 범위만 분리한다. 신청 활성화·고객 계좌 공개·실제 입금/환불은 이번 승인에 포함되지 않는다.

복구 준비가 되더라도 일반 deploy workflow는 Spring JAR 외 Wiki 파일·환경 설정을 다룬다. 후보와 현재 배포의 차이를 검토하고 변경 없는 설정을 보존한다. JAR health 가드만으로 모든 공개 UI 실패가 자동 복구된다고 보장하지 않는다. 배포 후 UI 실패 시 **현재 정상 38f40090**과 검증된 환경 보관본으로 복구할 실행 주체/경로가 먼저 확보되어야 한다. DB 전체를 과거로 덮거나 미디어 원본을 교체하지 않는다.

조건 충족 후 실행하더라도 실제 화면·소리 버튼·자동재생 차단 대체·모바일 넘침·승인 이미지/영상·기존 기능을 확인하기 전까지 ‘운영 검증 완료’로 기록하지 않는다. 실제 CDN/모바일 회선·Safari·음향 출력은 이번 로컬 결과에 포함되지 않는다.
