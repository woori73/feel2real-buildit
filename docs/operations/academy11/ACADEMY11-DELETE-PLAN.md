## 현재 근거와 미확인

사용자 전달 운영 조회: 학원12 영상10·교재상품4·중간고사 캠페인1. 학원11에는 이 세 항목이 출력되지 않았다.
이는 기존 기준값이며 실행 전 재측정해야 한다. 전체 종속 행 건수와 백업의 현재 복구 가능성은 미확인이다.
AcademyCraft 학원·회원·원장0은 사용자가 확인했다. 초기 원장 생성은 삭제 및 보존 검증 이후 진행한다.

## 읽기 전용 사전 조사

개인 신규 EC2 SSM에서 academy11-preflight.py를 sudo로 실행한다.
STS 신규 계정425805163960 및 학원11 식별자 지문을 검사한다.
모든 SQL은 START TRANSACTION READ ONLY와 ROLLBACK으로 감싼다.
실제 information_schema에서 academy_id 보유 테이블과 FK 그래프를 발견한다.
간접 자식도 EXISTS 경로로 집계하며 FK DELETE_RULE을 출력한다.
출력 from_11/from_12/overlap/other_tenant_via_11은 삭제 확정 행 목록이 아닌 조사 후보 건수다.
공유 행·타 학원 행·순환 FK·교차 스키마 FK·조회 실패는 자동 실행 차단 사유다.
각 집계는 최대3초이며 서로 다른 읽기 트랜잭션이므로 실행 직전 잠금 아래 재검증해야 한다.
DB 외래키 밖의 논리 참조, JSON/본문의 학원·콘텐츠 참조, 공용 저장소 키는 코드와 원문 구조를 별도 점검한다.
계정53의 학생 연결 등 사용자 소유 데이터는 학원11 전용이라고 간주하지 않는다.

- 주제/지역 공용 사전, users, 학생 계정, 사업체, 저장소 공용 자산: 부모라는 이유로 삭제하지 않는다.
- 학원12에서 참조하거나 다른 테넌트 식별자가 붙은 행: 삭제 제외 및 관계 재검토. 임의 분리·재매핑 금지.
- S3/파일/미디어: 이번 DB 정리에서 삭제하지 않는다. 공유/비공유 확인과 별도 범위 승인 필요.

## 백업과 롤백

기존 RDS의 BackupRetentionPeriod·LatestRestorableTime·available snapshot ID/시각을 읽기 전용으로 확인한다.
메타데이터나 과거 AcademyCraft 복원 검증은 BuildIt 선택 복구 검증을 대신하지 않는다.
실행 전 현재 대상 PK/행과 관련 스키마·FK·트리거를 포함하는 일관된 복구 자료를 확보·검증해야 한다.
비밀번호·개인정보는 채팅/PR/CI 출력에 넣지 않고 승인된 기존 보안 백업 위치에 보관한다.
새 RDS/EC2 등 유료 리소스를 생성하지 않는다. 사용 가능한 격리 복구 경로가 없으면 중단하고 보고한다.
트랜잭션 안의 실패는 ROLLBACK한다. 커밋 후에는 백업을 격리된 기존 인프라에서 복원·검증한 뒤
삭제 manifest의 행만 원래 PK로 부모→자식 순서로 선택 복구한다. 운영 DB 전체 덮어쓰기 금지.
학원11의 원래 PK 복구는 롤백이며 신규 학원으로 ID11을 재사용하는 작업과 다르다.

## 최종 승인에 제출할 실행안

실제 테이블별 PK·행수·DELETE_RULE·공유행0 근거·백업 위치/시각/복구 근거와 SQL 실행안을 확정해 먼저 보고한다.
알려지지 않은 트리거 또는 애플리케이션 삭제 콜백이 있으면 영향까지 검토한다.
삭제 중 학원11에 신규 쓰기가 발생하지 않도록 제한된 작업 구간을 마련한다. 전체 서비스 중단은 피한다.
최종 승인 후 한 트랜잭션에서 대상 식별자와 보존 대상을 확인하고 필요한 행을 잠근다.
전용 자식→부모 순서로 명시적 PK·학원 조건을 걸어 삭제하고 예상 영향 행수를 엄격히 검사한다.
외래키 검사를 끄지 않으며 미검토 CASCADE에 의존하지 않는다. CASCADE가 남는 경로는 사전 manifest에 포함한다.
공유·교차 테넌트·예상 행수 불일치·보존 지문 변화는 커밋 전 ROLLBACK한다.
