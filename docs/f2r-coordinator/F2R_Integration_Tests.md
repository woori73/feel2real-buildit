# F2R AI Coordinator V1 — 통합 테스트

> **상태: 미실행.** 구현 전이라 이 문서는 시험 계획과 기록 양식만 담는다. 시험한 결과가 없는 항목은 완료라고 보고하지 않는다.
> 시험 환경: 로컬(또는 별도 시험 DB) + 원장 지정 PC 1대 + Galaxy Z Fold6. **테스트 학생은 가명 데이터만 쓴다**(예: `시험민수` 2명 — 동명이인 확인용).

## 필수 시험 5가지

### T1. "김민수 등원" → F2R DB 출결 기록

1. 앱에서 음성으로 "시험민수 학생 등원했어"라고 말한다(문자로도 한 번 더 시험).
2. 기대 결과
   - 동명이인 선택 화면이 나오고 한 명을 고를 수 있다.
   - 확인 화면에 이름·반·시간이 보인다.
   - 승인하면 `easy_attendance_events`에 `CHECK_IN` 1행이 생긴다.
   - "… 등원 기록했습니다"를 음성으로 읽어 준다.
3. 추가 시험: 같은 명령을 다시 하면 "이미 등원 처리됨"이 나오고 기록이 추가되지 않는다. 같은 `requestId`를 재전송해도 1행만 남는다.
4. 확인 SQL(읽기): `SELECT event_type, occurred_at, source FROM easy_attendance_events WHERE student_id=? AND DATE(occurred_at)=CURDATE();`

### T2. 학습지 촬영 → PC Claude 작업 → HTML 초안

1. 가명 학습지(공개 교재 예시나 직접 만든 시험지)를 촬영한다.
2. 기대 결과
   - 테두리·초점·흔들림 표시 후 촬영 → 업로드 → PC에서 `running`
   - `result.html`이 생기고 서버에서 정화된다.
   - 상태가 `review_required`가 되고, 앱에서 원본과 나란히 볼 수 있다.
   - 불확실한 부분이 표시된다.
   - 승인 전에는 게시되지 않는다(게시 주소 접근이 차단된다).
3. 원문 대조: 문항 번호·선택지 수가 원본과 일치하는지 사람이 확인한다.

### T3. "지피티, 복습 문제 5개" → 검토 대기 등록

1. 가명 학생에게 위키 오답과 학생 연결(`easy_student_links`)을 준비한다.
2. 기대 결과
   - CodexRunner가 생성하고, 별도 실행으로 검증한다.
   - 위키에 `AI_PROPOSED` 5문항이 생기고, `review_required`가 된다.
   - AI 입력에 실명이 없다(작업 `input.json` 확인).
   - 승인하기 전에는 학생에게 배정되지 않는다.
3. 추가 시험: 연결이 없는 학생이면 "학생 연결이 필요합니다"로 중단한다.

### T4. 학부모 안내문 → 승인 → 카카오톡 공유

1. "학부모에게 내일 수업 안내문 작성해서 보내"라고 명령한다.
2. 기대 결과
   - 초안이 `/dashboard/parent-notices`에 저장된다.
   - 앱에 대상(반·인원 수)과 본문이 보인다.
   - 승인하면 카카오톡 공유 화면이 열린다. 받는 사람은 사용자가 직접 고른다.
   - **자동 발송이 없다**(서버 로그에 외부 발송 기록이 없다).

### T5. PC 연결 해제 → 작업 대기 → 재연결 후 정상 처리

1. PC Agent를 끄거나 네트워크를 끊는다 → T2 작업을 접수한다.
2. 기대 결과
   - `queued`가 유지되고, 앱에 "PC 연결 끊김"이 표시된다.
   - Agent를 다시 켜면 1분 안에 작업을 가져가 완료한다.
   - 실행 도중에 끊으면 임대 시간(10분) 뒤 `retry_pending` → 재시도한다.
   - 3번 실패하면 `failed`와 오류 요약이 남는다.
