# F2R AI Coordinator V1 — Android 앱 설계

> 상태: **설계안(미구현).** 대상 기기는 Samsung Galaxy Z Fold6(Android 14 이상)다.

## 1. 기술 선택

- **언어·화면**: Kotlin, Jetpack Compose. 접힌 화면과 펼친 화면에 맞춰 배치를 바꾼다(WindowSizeClass).
  - 펼친 화면: 왼쪽에 작업 목록, 오른쪽에 상세·승인
- **저장소**: 별도 저장소를 권장한다(`f2r-coordinator-android`). Spring 저장소의 CI와 섞지 않기 위해서다.
- **사용하는 라이브러리**: 모두 공식 라이브러리이고 무료다.
  - 카메라: CameraX
  - 문서 테두리 검출: ML Kit Document Scanner(구글 공식, 기기 안에서 처리) 또는 직접 만든 윤곽 검출
  - 음성: Android `SpeechRecognizer`(한국어 `ko-KR`), `TextToSpeech`
  - 보안 저장: Android Keystore + Jetpack Security(또는 DataStore + Keystore 암호화)
  - 생체 인증(선택): BiometricPrompt
  - 통신: OkHttp/Retrofit, HTTPS만. 운영 도메인 인증서 고정(pinning)은 선택이다(인증서를 갱신할 때 위험이 있으니 검토 후 결정).

## 2. 로그인과 자동 로그인

1. 첫 실행 때 웹 로그인 화면(WebView 아님, 앱 화면)에서 기존 `/api/auth/login`으로 로그인한다. 대상은 ADMIN/TUTOR다.
2. 로그인한 상태에서 「이 기기 등록」을 누른다 → `POST /api/coord/devices/pair`(kind=MOBILE)로 기기 토큰을 받는다.
   - 이 토큰은 **Keystore로 암호화해서만** 저장한다.
3. 이후 앱을 열 때는 기기 토큰으로 `POST /api/coord/mobile/session`을 호출해 1시간짜리 접근 토큰을 받는다.
   - 비밀번호는 저장하지 않는다.
4. 토큰이 해지됐거나 비밀번호가 바뀌면(ADMIN stamp가 달라지면) 다시 로그인을 요구한다.
5. 임시 비밀번호 상태(`passwordChangeRequired`)면 앱에서 막고, 웹에서 비밀번호를 바꾸라고 안내한다.

## 3. 화면

| 화면 | 내용 |
|---|---|
| 홈 | PC 연결 상태(초록=최근 1분 안에 heartbeat, 회색=끊김), 실행 모드(클로드/지피티), 큰 마이크 버튼, 글 입력칸, 카메라 버튼 |
| 확인 | 받아 적은 글, 해석된 작업(예: "김민수(중2, 화목반) 등원 기록"), 동명이인 고르기, [승인]·[거절]·[수정] |
| 카메라 | 미리보기, 테두리·초점·흔들림 표시, 자동 촬영(3가지 조건을 모두 만족하면 1초 뒤) 또는 "찍어" 음성 명령, 다시 찍기 |
| 작업 목록 | 상태 배지(queued·running·review_required·approved·completed·failed·retry_pending), 5초마다 갱신 |
| 결과 상세 | 원본 사진과 HTML 미리보기를 나란히(펼친 화면), 불확실 표시 하이라이트, 문항 검증 경고, [승인]·[거절]·[수정 요청] |
| 학부모 안내 | 대상(반·인원 수), 본문, [승인 후 카카오톡 공유] |
| 설정 | 기기 이름, 등록 해지, 음성 응답 켜기·끄기, 사진 자동 삭제(기본: 업로드 후 기기에서 삭제) |

## 4. 음성

- V1은 **앱이 켜져 있는 동안 마이크 버튼을 누를 때만** 듣는다. 상시 대기 호출어는 다음 단계에서 한다(배터리·개인정보 검토 필요).
- 받아 적은 글만 서버로 보낸다. **음성 원본은 보내지도 저장하지도 않는다.**
- 첫 단어가 "클로드", "지피티"면 실행 환경을 고른다. 없으면 홈에서 고른 모드를 쓴다.
- 인식 신뢰도가 낮으면(confidence < 0.6) "○○라고 하셨나요?"로 다시 확인한다.
  - 이름이 들어간 명령(출결)은 항상 확인 화면을 거친다.
- 응답은 `TextToSpeech`로 읽는다. 예: "김민수 학생 16시 5분 등원 기록했습니다."

## 5. 카메라

- 후면 카메라를 쓰고 해상도는 4:3 최대로 찍는다. 업로드 전에 긴 변을 2,000px 정도로 줄이고, JPEG 품질은 85로 한다.
- **촬영 조건**
  - 문서 사각형이 검출될 것
  - 초점이 잡혔을 것(AF 상태)
  - 흔들림이 적을 것: 가속도 변화가 임계값 이하이고, 선명도(라플라시안 분산)가 기준 이상
- 폴드6를 반쯤 접어 세워 두는 자세(Flex 모드)를 지원한다. 위 화면에 미리보기, 아래 화면에 버튼을 둔다.
- 업로드에 성공하면 기기의 임시 파일을 지운다(설정으로 바꿀 수 있다).

## 6. 카카오톡 공유

```kotlin
val send = Intent(Intent.ACTION_SEND).apply {
    type = "text/plain"
    putExtra(Intent.EXTRA_TEXT, approvedBody)
    setPackage("com.kakao.talk") // 설치돼 있지 않으면 setPackage 없이 공유 시트
}
startActivity(send)
```

- 받는 사람 선택과 보내기는 **사용자가 카카오톡 안에서 직접** 한다.
- 친구 목록을 읽거나 자동으로 보내는 기능은 넣지 않는다.

## 7. 권한

- **요청하는 권한**: `CAMERA`, `RECORD_AUDIO`(사용할 때만 요청), `INTERNET`
- **요청하지 않는 권한**: 연락처·SMS·위치·저장소 전체 접근

## 8. 배포

- **V1 시험**: 서명한 APK를 원장 기기에 직접 설치한다(비용 0원).
- 다른 사람이 쓰게 되면 Play Console 내부 테스트 트랙을 검토한다.

## 9. 테스트

- **단위 테스트**(JUnit, given/when/then): 명령 분류(실행 환경·종류), 재확인 조건, 토큰 갱신, 상태 표시
- **계측 테스트**: 실제 폴드6에서 카메라·음성·공유 인텐트를 확인한다(수동 점검표는 `F2R_Integration_Tests.md`).
