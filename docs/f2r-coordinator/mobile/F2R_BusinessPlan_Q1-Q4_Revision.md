## Q1. 문제 인식 — 추가 문단

> **현장 업무와 AI 도구의 단절**
> F2R은 학원 운영(출결·장부), 학교별 내신위키, 문항 제작, 학부모 안내를 하나의 서버에서 관리합니다. 또 이 기능들을 AI가 직접 쓸 수 있도록 MCP(모델 컨텍스트 프로토콜) 서버로 열어 두었습니다(운영 중).
> 그러나 실제 교습 현장의 업무는 대부분 책상 위 PC가 아니라 **교실과 복도, 상담 자리에서 휴대폰으로** 일어납니다. 학생이 들어오면 출결을 남기고, 받은 학습지를 촬영하고, 수업 직후 학부모에게 안내를 보냅니다.
> 지금은 PC에서는 AI가 F2R 업무 도구를 써서 작업할 수 있지만, 휴대폰에서는 같은 작업을 자연스럽게 이어 갈 수 없습니다. AI가 휴대폰의 카메라·음성·승인·메신저 공유를 업무 흐름 안에서 쓸 방법이 없기 때문입니다.
> 그 결과 강사는 현장에서 메모하고, 나중에 PC 앞에서 다시 입력합니다. 이중 작업과 기록 누락이 생깁니다.

## Q2. 실현 가능성 — 핵심 기술 추가

> **F2R Mobile MCP 연동 체계**
> 기존 F2R MCP 서버를 교체하지 않고, 휴대폰을 AI의 현장 인터페이스로 연결하는 세 가지 요소를 추가합니다.
>
> 1. **F2R Android 앱(갤럭시 Z 폴드6 우선)**
>    - 처음 한 번 로그인한 뒤 기기 등록으로 자동 로그인합니다(기기 보안 저장소 사용).
>    - 한국어 음성·문자·카메라로 명령하고, 작업 상태를 확인합니다.
>    - 강사가 결과를 승인하고, 카카오톡 공유 화면을 엽니다.
> 2. **Mobile MCP 계층(기존 서버 안에 추가)**
>    - 기기 인증과 권한 관리를 합니다.
>    - 기존 업무 도구(학생 검색, 출결, 학습지 HTML, 내신위키, 오답 분석, 복습 문제)를 휴대폰과 PC에 똑같이 제공합니다.
>    - AI가 휴대폰에 촬영·음성 질문·읽어 주기·승인·공유를 **요청**하는 도구(`mobile_*`)를 둡니다. 실제 촬영·승인·발송은 **휴대폰에서 사람이 누를 때만** 실행됩니다.
> 3. **F2R PC Agent**
>    - 지정한 학원 PC에서 공식 개발 도구(Claude Code·Codex)를 실행해 HTML·교육 자료를 만듭니다.
>    - PC가 꺼져 있으면 작업을 서버에 대기시켰다가 다시 연결되면 처리합니다.
>    - PC는 외부에 포트를 열지 않고, 서버로 나가는 인증된 연결만 씁니다.
>
> **이미 갖춘 기반(운영 중)**
> - 원격 MCP 서버: HTTPS, OAuth 2.1, 도구별 동의·감사 기록
> - 학원 출결부, 학교별 내신위키와 문항 검토 상태, 학부모 안내문 초안 기능
> - Claude 계정의 F2R MCP 연결(커넥터)을 실제로 사용한 기록(운영 감사 로그)
> - PC 수집 프로그램(기기별 토큰, 아웃바운드 연결)
>
> 그래서 새로 만드는 부분은 **휴대폰 인증·기기 요청·앱 화면·PC 실행 연결**에 한정됩니다.
>
> **비용 구조(명시)**
> MCP는 AI가 F2R 도구를 쓰기 위한 연결 규격일 뿐이며, **AI 모델의 실행 비용을 대신 부담하지 않습니다.** 모델 실행 비용은 다음 중 하나가 부담합니다.
> - 사용자가 직접 가입한 AI 서비스 구독(공식 앱·공식 개발 도구의 사용 한도 안)
> - 사용량에 따라 과금되는 모델 API
>
> F2R 앱은 사용자의 유료 구독 계정을 자동으로 제어하지 않습니다. 공식적으로 지원되는 앱, 개발 도구, MCP, API 범위 안에서만 동작합니다. 여러 학원에 서비스로 제공할 때는 공식 권장 방식인 API 키로 운영하고, 사용량을 정산합니다.
>
> **안전장치**
> - 출결 기록·게시·과제 배정·학부모 발송은 모두 사람의 승인을 거칩니다.
> - 메신저 발송은 사용자가 카카오톡에서 직접 합니다.
> - AI에게는 학생 실명 대신 가명을 전달합니다.
> - 음성 원본은 서버로 보내지 않습니다.

## Q3. 성장전략 — 추가 문단

> **학원용 모바일 AI 코디네이터 서비스**
> 1. **1단계(자체 검증)**: F2R 교습소에서 출결·학습지 디지털화·복습 문제·학부모 안내를 휴대폰 중심으로 운영하며 효과를 측정합니다.
>    - 측정 항목: 기록 누락, 처리 시간, 강사 승인률
> 2. **2단계(학원 시범)**: 같은 기능을 BUILD IT 협력 학원에 제공합니다.
>    - 학원마다 사업체·권한을 분리하고, AI 사용량은 학원별로 측정해 정산합니다.
> 3. **3단계(서비스화)**: 학원 규모별 요금제로 제공합니다.
>    - 기본: 출결·안내
>    - 확장: 학습지 HTML·복습 문제·내신위키
> 4. **이후**: 같은 휴대폰 앱과 MCP 도구를 **로봇 장치에 탑재**하는 방향으로 확장합니다(Q4).
>    - 휴대폰이 로봇의 눈(카메라)·귀(마이크)·입(스피커)과 판단 연결 장치 역할을 합니다.
>    - 소프트웨어와 업무 도구는 그대로 재사용합니다.

## Q4. 향후 발전방안 — 단계적 발전 방향

> | 단계 | 내용 | 시기(안) | 상태 |
> |---|---|---|---|
> | ① PC MCP | AI가 PC에서 F2R 업무 도구(제작소·학생명단 집계·안내문 초안 등)를 사용 | 2026 | **운영 중** |
> | ② 모바일 MCP | 휴대폰 앱 + Mobile MCP 계층 + PC Agent: 음성·문자·카메라로 현장 업무 수행 | 2026.12~2027.06 | 개발 예정 |
> | ③ 스마트폰 탑재형 로봇 | 휴대폰을 거치형 로봇(회전 거치대·스피커)에 장착해 학습지 인식·발음 지도·출결 안내를 수행. 짧은 응답은 기기에서, 문항 생성·분석은 학원 PC 서버에서 처리. 학생 음성·영상은 학원 밖으로 보내지 않음 | 2027 하반기 | 계획(자체 LLM 계획 R1 소프트웨어 튜터와 연계) |
> | ④ 교육용 피지컬 AI 로봇 팔 | 학습지 넘기기·가리키기·교구 조작 등 물리 동작을 결합한 교육 보조. 안전 기준(속도·힘 제한, 비상 정지, 학생 접촉 금지 구역)을 먼저 정한 뒤 시제품 제작 | 2028 이후 | 연구 단계 |
>
> 각 단계는 앞 단계의 **업무 도구·권한·승인 체계를 그대로 재사용**합니다. 그래서 하드웨어만 바뀌어도 학원 업무 규칙과 안전장치는 유지됩니다.
