# F2R Mobile — 모바일 인증 및 보안 설계

> 상태: 설계안(미구현). 기존 인증(JWT 쿠키, MCP OAuth)은 바꾸지 않고 기기 인증을 **추가**한다.

## 1. 인증 주체와 방식

| 주체 | 방식 | 보관 위치 | 유효기간 | 해지 |
|---|---|---|---|---|
| 사람(웹) | 기존 `/api/auth/login` → JWT 쿠키 | 브라우저 | 24시간 | 로그아웃·비밀번호 변경 |
| F2R 앱(휴대폰) | **기기 토큰**: 처음 로그인 후 등록. 원문은 1번만 전달하고 서버에는 SHA-256만 저장 → **접근 토큰** 발급 | 기기 토큰: Android Keystore로 암호화, 접근 토큰: 메모리 | 기기 토큰: 해지 전까지(90일 미사용 시 자동 해지), 접근 토큰: 1시간 | 웹 기기 관리 화면, 앱 설정 |
| PC Agent | 기기 토큰(같은 테이블, kind=PC) | Windows DPAPI(사용자 범위) | 해지 전까지 | 웹 기기 관리 화면 |
| PC의 Claude Code·Codex(작업 중) | **작업 전용 MCP 토큰**(작업 1건, 15분, 해당 사업체·학생만) | 실행 인자·환경 변수(디스크 저장 안 함) | 15분 | 작업 종료 시 무효 |
| 공식 Claude/ChatGPT 앱 | 기존 MCP OAuth(DCR, PKCE) | 각 회사 서버 | 접근 15분 / 갱신 30일 | `/mcp/connections` |

- **기기 등록 절차**
  1. 앱에서 아이디·비밀번호로 로그인한다(ADMIN·TUTOR만).
  2. 「이 기기 등록」을 누르면 서버가 기기 토큰을 발급한다.
  3. 임시 비밀번호 상태(`pwc`)이거나 비밀번호 변경 전이면 등록을 막는다.
- **ADMIN 계정의 연결 고리**: 기기 토큰을 ADMIN 자격 증명 stamp(`AdminSessionValidator`)와 묶는다. 관리자 비밀번호를 바꾸면 모든 기기에서 다시 로그인해야 한다.
- **생체 인증(선택)**: 앱을 열 때 BiometricPrompt를 띄운다. 승인 버튼을 누를 때도 다시 확인한다(설정).

## 2. 권한

- **역할**: ADMIN·TUTOR만 쓴다. STUDENT는 등록할 수 없다.
- **사업체 범위**: 모든 업무 도구가 `EasyTutorAccessService.requireAllowedBusiness`를 다시 검사한다.
- **scope**(MCP, 별도 동의)
  - `coord:read`: 조회
  - `coord:draft`: 초안 만들기
  - `mobile:request`: 휴대폰에 촬영·음성·승인·공유를 요청
  - **바로 실행하는 scope는 없다.**
- **기기 토큰이 접근할 수 있는 경로**: `/api/mobile/**`와 `/api/auth/me`만 허용한다. 관리자 웹 API나 장부 API에는 접근할 수 없다(허용 목록 필터).

## 3. 승인 정책

| 동작 | 승인 | 비고 |
|---|---|---|
| 조회(학생·출결·문항·작업) | 불필요 | 응답은 가명(S01…) |
| 출결 기록·정정 | 휴대폰 확인 화면에서 1번 누름 | 동명이인이면 먼저 고름. 같은 날 같은 구분이면 막음 |
| HTML 게시·위키 등록·학생 과제 배정 | 강사 승인 | 승인 전에는 비공개 |
| 카카오톡 안내 | 앱 승인 → 공유 화면 → **사용자가 카카오톡에서 직접 보냄** | 친구 목록 접근·자동 발송 없음 |
| `mobile_request_approval` 결과 | **사람이 휴대폰에서 누른 결과만** 서버에 기록 | AI는 승인 결과를 만들 수 없다. 서버가 기기 토큰과 요청 ID로 확인한다 |

## 4. 위협과 대응

| 위협 | 대응 |
|---|---|
| 휴대폰 분실·도난 | 기기 토큰은 Keystore에 두고, 원격으로 해지한다. 접근 토큰은 1시간이다. 생체 인증(선택). 앱 데이터는 암호화한다 |
| 토큰 탈취 | 해시만 저장하고, 로그에 남기지 않는다. 기기별로 해지할 수 있다. 접근 토큰이 짧다. 비정상 사용(다른 국가, 단시간 대량)은 감사 로그에 표시한다 |
| AI가 휴대폰을 함부로 조작 | `mobile_*`는 **요청만** 한다. 실제 촬영·말하기·공유는 앱 화면에서 사람이 누를 때만 한다. 요청은 5분 뒤 만료된다. 요청 수를 제한한다(작업당 10건) |
| 사진·문서 속 문구가 AI에게 지시를 내림 | 자료는 자료로만 다룬다. 쓰기는 초안만 만든다. HTML은 jsoup로 정화한다. 게시는 사람이 승인한다 |
| 개인정보 외부 전송 | AI에게는 가명과 문항 자료만 준다. 실명은 서버와 앱 확인 화면에만 둔다. 음성 원본은 보내지 않고 받아 적은 글만 보낸다 |
| 중복 실행 | `requestId` UNIQUE, 작업 임대 시간, 출결 중복 검사, 승인 `planHash` 일치 확인 |
| PC의 AI가 파일·명령을 함부로 실행 | 작업별 격리 폴더, 셸 도구 차단, 실행 횟수·예산 상한, 저장소 폴더 사용 금지 |
| 구독 약관 위반 | F2R 앱은 구독 계정에 로그인하지 않는다. 구독은 공식 앱이나 사용자 본인이 로그인한 공식 CLI에서만 쓴다. 다른 학원에 서비스로 제공할 때는 API 키 방식으로 한다(학원별 키 또는 F2R 키 + 사용량 정산) |
| 운영 장애 | 기능 스위치 `app.coordinator.enabled`. 끄면 기존 기능에는 영향이 없다 |

## 6. 통신

- HTTPS만 쓴다(기존 ALB 인증서).
- 앱은 HTTP를 차단한다(`cleartextTrafficPermitted=false`).
- 인증서 고정은 선택이다. 인증서 갱신 때 앱이 막힐 위험이 있어 V1에서는 쓰지 않는다.
- PC Agent와 휴대폰은 포트를 열지 않는다. 서버로 나가는 연결만 쓴다.
