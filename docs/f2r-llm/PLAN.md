## 2. Gemini 코드 진단

그대로 쓰면 안 되는 이유와 고칠 점입니다.

1. **학습 코드가 없습니다.** 압축·복원 층이 학습되지 않은 상태라 복원 오차가 의미 없는 값이고, 이상치 판정도 무작위에 가깝습니다. 정상 데이터로 먼저 학습해야 합니다.
2. **입력 범위가 맞지 않습니다.** 복원 출력이 Tanh(−1~1)인데 입력을 정규화하지 않아, 범위를 벗어난 값은 항상 오차가 크게 나옵니다.
3. **운영 중에 기준값이 오염됩니다.** API가 `update_stats=True`로 요청마다 평균·분산을 바꿔, 이상한 입력이 들어올수록 기준이 따라 움직입니다. 요청 1건이면 분산이 0이라 임의 값(0.1)을 씁니다. 여러 요청이 동시에 같은 값을 고치는 문제도 있습니다.
4. **전송량이 줄지 않습니다.** 원본 1024개 값을 서버로 보낸 뒤 서버에서 압축하고, 압축값을 다시 돌려보냅니다. 통신량을 줄이려면 기기 쪽에서 압축해야 합니다.
5. **수치 표현이 맞지 않습니다.** 1024→128은 87.5% 감소이며 "약 95%"가 아닙니다. 차원 감소율은 메모리·지연 개선율과 다릅니다.
6. **텍스트 출제에는 직접 맞지 않습니다.** 이 엔진은 숫자 벡터의 이상치를 버리는 구조입니다. 새로운 유형의 질문을 이상치로 버리면 안 됩니다. 쓸 곳은 로봇의 센서 입력 품질 확인(잡음 음성, 빈 화면, 흔들린 교재 사진)입니다.
7. **특허 청구항은 계획서에 넣지 않습니다.** 오토인코더 복원 오차와 이동 평균 기반 이상 탐지는 이미 널리 쓰이는 방식이라, 신규성 주장은 심사에서 역효과가 납니다.

## 3. 전체 파이프라인

```
[수집] 업로드 → HTML 정제(기존) → 청킹 → 메타데이터 → 임베딩 + BM25 색인 → D 점수
[생성] 시험 컨텍스트 → 하이브리드 검색 → D 프리필터 상위 K → 프롬프트 조립 → 모델 라우터 → F2R 출제 LLM
[검증] 문항 계약 검사(기존) → 근거 대조 → 다른 모델 재풀이 → 저장(evidence·verify, 기존) → 배포 게이트 → 샘플 오딧
[학습] 검증 통과 문항 → 데이터셋 내보내기 → 평가 세트 분리 → QLoRA 학습(런유어AI) → GGUF 4비트 변환 → 평가 → 통과 시 라우터 전환
[로봇] 마이크·카메라 → 입력 품질 게이트(Gemini 엔진 개량) → 음성 인식·OCR → 기기 경량 모델 / 학원 PC 서버(D 기준 분담)
```

## 4. 모듈별 구현

모두 `problem-generator/wiki-backend-src/backend/` 아래에 새 파일로 추가하고, 기존 코드는 연결만 합니다.

### 4-1. 청킹과 색인 — `chunk_index.py`
- 대상: 기존 `exam_material_sets`의 정제 본문(`body_text`, `html_text`)과 학교 프린트.
- 청크 단위: 기출은 문항 1개, 학교 프린트는 지문 문단 또는 문법 포인트 1개.
- 메타데이터: 학교·학년·연도·학기·시험, 자료 id, 쪽·위치, 단원·문법 태그.
- 색인 두 가지를 함께 만듭니다.
  - BM25: `rank_bm25` 라이브러리, 서버 메모리에서 바로 계산.
  - 임베딩: 한국어·영어를 함께 지원하는 오픈 임베딩 모델을 학원 PC에서 실행하고, 벡터는 SQLite 확장(sqlite-vec) 또는 FAISS 파일에 저장.
- 새 테이블 `context_chunks`(id, material_id, scope, position, text, tags, bm25_tokens, embedding_ref, d_score). 기존 테이블은 건드리지 않습니다.

### 4-2. 다이내믹 덴서티 점수 — `density.py`
v7 기록의 문제(info_rate·noise_volume이 입력값)를 고쳐, 세 값을 저장된 데이터에서 계산합니다.

```python
def density_score(chunk, stats, eps=1e-3):
    # I: 이 청크의 태그(단원·문법)가 과거 기출에서 차지한 비중 (0~1)
    I = stats.exam_share(chunk.tags)
    # Ψ′: 최근 2회 시험에서 그 비중이 늘어난 정도, 줄었으면 0
    psi = max(0.0, stats.recent_share(chunk.tags) - stats.prior_share(chunk.tags))
    # V: 청크 길이 대비 반복 문구·서식 문자·형식적 서두 비율
    V = noise_ratio(chunk.text) * len(chunk.text) / 1000
    return I * (psi + 0.1) / (V + eps)   # 0.1: 변화가 없어도 비중은 반영
```

- `stats`는 기출 문항의 태그 집계로 만듭니다. 기출에 태그가 없으면 먼저 AI로 태그를 붙이고 사람이 확인합니다.
- 점수는 색인할 때 계산해 `d_score`에 저장하고, 검색 결과 재정렬에 씁니다.
- A/B 비교용으로 `D 사용 / BM25만 / 임베딩만 / BM25+임베딩` 네 가지 모드를 설정값으로 바꿀 수 있게 합니다. 효과가 없으면 `BM25+임베딩`으로 고정합니다.

### 4-3. 하이브리드 검색 — `retrieval.py`
- BM25 점수와 임베딩 코사인 점수를 순위 합성(RRF)으로 합친 뒤, D 점수로 재정렬해 상위 K개를 돌려줍니다.
- v7 기록의 버그를 막습니다. `top_k`를 실제로 적용하고, 유사도가 기준 미만이면 빈 결과를 돌려줘 "근거 없음 → 답 보류"로 이어지게 합니다.
- MCP `get_final_context`에 `retrieval_mode`, `top_k` 인자를 추가해, 전체 자료 대신 선별 자료만 받는 옵션을 둡니다. 기본값은 지금과 같게 둡니다.

### 4-4. 모델 라우터 — `model_router.py`
- 작업별(문항 생성, 재풀이, 태그 부여)로 어떤 모델을 쓸지 설정 파일에 둡니다. 선택지는 Claude 등 상용 AI, 학원 PC의 로컬 모델입니다.
- 로컬 모델은 llama.cpp의 `llama-server`가 제공하는 OpenAI 호환 주소로 호출합니다. 같은 코드로 상용 AI와 로컬 모델을 바꿔 끼울 수 있습니다.
- 모델 버전마다 평가 통과 여부를 기록하고, 통과하지 않은 버전은 서비스 작업에 배정하지 않습니다(계획서의 "같은 평가를 통과한 버전만 쓴다").
- 홈페이지 서버와 학원 PC는 Cloudflare Tunnel이나 Tailscale로 연결하고, 학원 PC 쪽 포트는 밖에 열지 않습니다.

### 4-5. 검증 파이프라인 — `verify_pipeline.py`
기존 `save_generated_test`의 evidence·verify 칸을 채우는 자동 단계입니다.
1. 문항 계약 검사: 기존 `question_contract` 그대로 씁니다.
2. 근거 대조: 문항이 인용한 근거 id가 실제로 검색된 청크인지, 지문 문장이 원문에 있는지 문자열로 확인합니다. 아니면 `evidence` 불일치로 표시합니다.
3. 재풀이: 생성한 모델과 다른 모델이 정답을 가리고 풀어, 결과를 `verify.independent_answer`, `verify.status`에 넣습니다.
4. 배포 게이트: `verify.status`가 `일치`가 아닌 문항이 있으면 시험 상태를 `검수 대기`로 두고 고객 화면에 내보내지 않습니다.
5. 샘플 오딧: 자동 통과 문항의 10%를 무작위로 골라 검수 목록에 올리고, 결과를 `teacher.action`에 기록합니다.

### 4-6. 데이터셋 내보내기와 평가 — `dataset_export.py`, `eval_harness.py`
- 내보내기 조건: `verify.status = 일치`이고 교사 확인이 끝난 문항, 또는 교사가 고친 문항(고친 뒤 버전).
- 형식: JSONL 한 줄에 `{"instruction": 출제 원칙, "input": 기출 프로파일 + 근거 청크, "output": 문항·정답·해설·근거 id}`.
- 평가 세트 분리: 시험 날짜 기준으로 나눕니다. 평가할 시험보다 늦은 자료는 학습에 넣지 않습니다.
- 평가 지표(계획서와 같음): 정답률, 근거 일치율, 형식 준수율, 독립 풀이 불일치율, 자동 통과 문항의 실제 오답률, 문항당 토큰·지연.
- 학생 이름 등 식별 정보는 내보내기 단계에서 지우고, 채무상담 데이터는 내보내기 대상에서 뺍니다.

### 4-7. 학습 — `training/` 폴더(저장소 안, 서버 배포 대상 아님)
- 환경: 런유어AI 48~80GB 단일 GPU(L40S·H100급), 확보한 포인트 272,727원 사용.
- 방법: QLoRA(PEFT 또는 Unsloth) 파인튜닝. 1차는 데이터 1,500쌍 내외로 시작합니다.
- 베이스 모델 후보: 7~8B급 오픈웨이트 모델 중 한국어·영어 성능과 **상업 이용 라이선스**를 확인해 고릅니다. 라이선스가 비상업용인 모델은 서비스에 쓰지 않습니다.
- 산출: LoRA 가중치 → 병합 → GGUF 변환 → 4비트 양자화(약 5GB) → 학원 PC `llama-server`에 올림.
- 머신 반납 시 환경이 초기화되므로, 학습 결과와 체크포인트는 매 실험마다 내려받아 보관합니다.

### 4-8. 교육용 로봇 — `edge/` (2027년 하반기부터)
- R1 소프트웨어 튜터: PC·태블릿에서 음성 인식(whisper.cpp), 교재 사진 OCR, 기기용 3~4B 모델, 무거운 생성은 학원 PC 서버로 요청.
- 입력 품질 게이트: Gemini 엔진을 아래처럼 고쳐 씁니다.
  - 음성·이미지 임베딩(고정 크기)을 입력으로 하고, 정상 사용 데이터로 먼저 학습합니다.
  - 기준 평균·분산은 학습 후 고정하고, 운영 중에는 갱신하지 않습니다(기기별로 따로 보관).
  - 이상치로 판정되면 버리지 않고 "다시 말해 주세요", "교재를 다시 비춰 주세요"처럼 재요청합니다.
  - 압축은 기기에서 하고, 서버에는 압축값만 보냅니다. 통신량은 실제 바이트로 측정합니다.
- 연산 분담: 짧은 응답·안전 관련 동작은 기기에서, 문항 생성·분석은 서버에서 처리합니다. 학생 음성·영상은 학원 밖으로 보내지 않습니다.
