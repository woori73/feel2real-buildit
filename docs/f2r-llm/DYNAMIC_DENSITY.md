# 다이내믹 덴서티(동태밀도, D) — 정의·적용·검증

작성일: 2026-11-08 · 관련: [PLAN.md](PLAN.md) 4-2, 4-3

## 1. 정의

원형(대표님 원문):

```
D(t) = I(t) · dΨ(t)/dt / (V(t) + ε)
```

| 기호 | 원문 정의 | F2R 출제에서 계산하는 값 |
|---|---|---|
| I(t) | 입력된 원시 정보량 | 그 항목(단원·문법 태그)이 해당 학교 과거 기출에서 차지한 비중(0~1) |
| dΨ/dt | 시간에 따른 정보의 변화율 | 최근 2회 시험의 비중 − 그 이전 비중. 줄었으면 0 |
| V(t) | 정보가 차지하는 가상 점유 공간(노이즈 크기) | 범위 분량. 청크 단위에서는 길이 × 반복 문구·서식 문자·형식적 서두 비율 |
| ε | 연산 붕괴를 막는 최소 안정 상수 | 1e-3 |

세 값은 **저장된 데이터에서 계산한다.** 사람이 입력값으로 넣지 않는다(v7 기록의 info_rate·noise_volume 입력 방식은 쓰지 않는다).

## 2. 적용

### 2-1. 출제 원칙 6번 (운영 중, 위키 MCP 프롬프트)
`problem-generator/wiki-src/src/lib/mcpPrompt.ts`의 예상문제 원칙 6번:

> 범위 안 항목(본문·문법)마다 동태밀도 D = 기출 출제 비중 × 최근 증가량 ÷ (범위 분량 + ε)를 계산해, D가 높은 항목에 문항을 더 배정하고 계산표를 함께 보고한다.

- 지금은 생성 모델이 프롬프트 안에서 직접 계산한다. 결과 계산표는 문항 보고에 함께 남긴다.
- 클로드와 자체 LLM v0를 비교할 때 두 모델 모두 같은 원칙 문구를 받는다.

### 2-2. 검색 재정렬 (계획, `density.py` → `retrieval.py`)

```python
def density_score(chunk, stats, eps=1e-3):
    I = stats.exam_share(chunk.tags)                                        # 기출 비중
    psi = max(0.0, stats.recent_share(chunk.tags) - stats.prior_share(chunk.tags))  # 최근 증가량
    V = noise_ratio(chunk.text) * len(chunk.text) / 1000                    # 분량·노이즈
    return I * (psi + 0.1) / (V + eps)   # 0.1: 변화가 없어도 비중은 반영
```

- `stats`는 기출 문항의 태그 집계로 만든다. 기출에 태그가 없으면 AI로 태그를 붙이고 사람이 확인한다.
- 색인할 때 계산해 `context_chunks.d_score`에 저장하고, BM25+임베딩 순위 합성(RRF) 뒤 재정렬에 쓴다.
- D는 **순위만 바꾼다.** 근거가 없는 항목을 D로 끌어올려 출제하지 않는다(유사도 기준 미만이면 "근거 없음 → 답 보류").

## 3. 검증

D가 실제로 도움이 되는지 확인되기 전까지는 "효과 있다"고 쓰지 않는다.

| 모드 | 설명 |
|---|---|
| `D` | BM25+임베딩 → D 재정렬 |
| `bm25` | BM25만 |
| `embedding` | 임베딩만 |
| `hybrid` | BM25+임베딩(RRF), D 없음 |

- 같은 시험 컨텍스트·같은 출제 원칙·같은 모델로 네 모드를 돌려 [EVAL_RESULTS.md](EVAL_RESULTS.md) 지표로 비교한다.
- 추가로 보는 값: 실제 시험 유사 문항 비율(시험 후 실제 시험지와 대조), 근거 청크 수와 토큰 수.
- 평가 세트는 시험 날짜 기준으로 나눈다. 평가할 시험보다 늦은 자료는 stats 계산에도 넣지 않는다.
- `D`가 `hybrid`보다 낫지 않으면 `hybrid`로 고정하고 이 문서에 결과를 남긴다.

## 4. 다른 제품 적용: 시험 보안 검사대 렌즈 찾기 (2026-11-20)

같은 식을 광학 검사에 옮겼다. 출제에서 "D가 높은 항목에 문항을 더 배정"하듯, 렌즈 찾기는 **D가 높은 후보 자리에 정밀 분석(카메라 원본 해상도)을 몰아준다.** 코드: `src/main/resources/static/js/exam_security_lens.js`(`lensDensity`·`allocateFine`).

| 기호 | 출제(2장) | 렌즈 찾기 |
|---|---|---|
| I(t) | 기출 출제 비중 | 플래시 켰을 때 − 껐을 때 평균 밝기 차이(0~1) |
| dΨ/dt | 최근 증가량 | 끔·켬 반복 중 같은 자리에서 다시 나타난 비율(0~1) |
| V(t) | 범위 분량·노이즈 | 후보 넓이 ÷ 화면 넓이(넓게 번쩍이는 면일수록 큼) |
| ε | 1e-3 | 1e-3 |

흐름:
1. **1단계(전체를 거칠게):** 화면을 640폭으로 줄여 끔·켬 3번 비교. 멀리서 흐려진 작은 렌즈를 놓치지 않게 기준을 낮춘다(가까이 켠 밝기 100·차이 40, 멀리 80·25).
2. **D 계산·배정:** 후보마다 D를 계산해 높은 순으로 최대 5곳(`FINE_BUDGET`)만 고른다.
3. **2단계(후보만 촘촘하게):** 고른 자리만 카메라 원본 해상도(요청 1920×1080)로 잘라 끔·켬 2번 다시 비교하고, 최종 기준(가까이 200·60, 멀리 170·40)을 2번 모두 넘은 것만 '확인 필요'로 올린다. 다시 안 보인 후보와 예산 밖 후보는 노란 점선 "약한 후보"로 알리기만 한다.

알려진 한계와 검증:
- "거칠게 훑고 의심 자리만 자세히 보기"는 영상 처리에서 널리 쓰이는 방식이다. F2R이 새로 만든 원리라고 쓰지 않는다. F2R 쪽 의미는 **출제와 검사에 같은 D 원칙을 일관되게 적용**했다는 데 있다.
- 비슷한 생각의 연구 사례: DD-GNG(IROS 2019, 의심 물체 부분의 위상 구조 밀도를 높여 사다리를 실시간 검출). 비교 참고로만 쓴다.
- 지금 확인한 것은 합성 이미지 단위 테스트뿐이다(1단계 최종 기준으로는 놓치는 2×2픽셀 렌즈를 2단계에서 원본 좌표로 찾음). 실제 효과는 [exam-security/TEST_PLAN.md](../exam-security/TEST_PLAN.md) 4-1의 `?dd=off`(예전 방식) 대비 측정으로만 쓴다.
- ε가 작은 후보 넓이보다 커서, 아주 작은 점끼리는 V보다 I·dΨ/dt가 순위를 정한다.
- 렌즈처럼 생긴 작은 반짝임이 5곳보다 많으면 진짜 렌즈가 예산 밖으로 밀려 약한 후보로만 표시될 수 있다.

## 5. 플랫폼 적용 지도 — LLM·서버·전송 경량화 (2026-11-21)

원장님 지시: "LLM과 서버 물류 경량화 등에도 적용." 원칙은 하나다. **같은 자원(토큰·연산·전송·저장)을 D가 높은 곳에 먼저 쓴다.** 효과는 3장 방식대로 D 사용/미사용을 비교해 잰 값만 쓴다.

| # | 적용처 | I(정보량) | dΨ/dt(변화) | V(노이즈·부피) | 자원 | 상태 |
|---|---|---|---|---|---|---|
| 5-1 | **LLM 근거 배정(컨텍스트 경량화)** | 청크 태그의 기출 비중 | 최근 2회 증가량 | 분량 × 노이즈 비율 | 프롬프트 토큰 | `density.allocate_context` 구현·단위 테스트(T02). 검색(T01·T03) 연결 전 |
| 5-2 | 렌즈 찾기 2단계 정밀 확인 | 밝기 차이 | 반복 출현율 | 넓이 비율 | 원본 해상도 분석 | 운영 배포(4장) |
| 5-3 | **연산 분담(기기 / 학원 PC / 클라우드)** | 작업의 결과 중요도(예: 시험 출제 > 연습 문제) | 마감 임박도(시험일까지 남은 날의 역수) | 예상 처리량(토큰·초) | GPU·상용 AI 요금 | 설계(T14). PLAN 4-8 "D 기준 분담"을 구체화 |
| 5-4 | **전송·저장 경량화(자료 물류)** | 자료 조회·출제 인용 횟수 | 최근 증가량(시험 기간) | 파일 크기(MB) | 네트워크·저장 비용 | 설계(T14) |

### 5-1. LLM 근거 배정 (구현)

- 하이브리드 검색(T03)이 돌려준 청크를 `allocate_context(chunks, stats, token_budget, min_similarity)`에 넣으면, D 높은 순으로 토큰 예산 안에 담는다. 예산을 넘는 청크는 건너뛰고 더 작은 고밀도 청크를 본다.
- 유사도가 기준 미만이면 D가 높아도 뺀다(2-2의 "근거 없음 → 답 보류" 원칙). 태그가 없는 청크는 D=0이다.
- 프롬프트 캐싱(CLAUDE.md 필수 규칙)과 함께 쓸 때: 같은 시험 컨텍스트에서 고른 청크 묶음은 앞쪽 고정 블록에 넣어 캐시를 재사용한다. 묶음이 바뀌면 캐시가 깨지므로, 재정렬은 색인 시점(`d_score`)에 한 번 하고 요청마다 바꾸지 않는다.
- 토큰 수는 `estimate_tokens`(2.5자당 1토큰) 근사다. 실제 절감률은 API 응답의 사용 토큰으로 잰다.
- 측정: 같은 시험·같은 모델로 `allocate_context` 사용/미사용(상위 K 고정)을 비교해 문항당 입력 토큰, 정답률, 근거 일치율(EVAL_RESULTS.md 지표)을 적는다.

### 5-3. 연산 분담 (설계)

- 작업 하나(출제·재풀이·태그·채점·영상 처리)마다 D_job = 중요도 × (임박도 + 0.1) ÷ (예상 처리량 + ε)를 계산한다.
- 배정 규칙(초안): D_job이 높은 작업부터 클라우드 상용 AI·학원 PC GPU에 보내고, 낮은 작업은 기기 경량 모델이나 야간 대기열로 미룬다. 학생 음성·영상은 D와 상관없이 학원 밖으로 보내지 않는다(PLAN 4-8).
- 측정: 1주 동안 실제 작업 기록(종류·시작·끝·토큰·요금)을 모아, 지금 방식(먼저 온 순서)과 D 순서를 같은 기록으로 다시 돌려 마감 지연 건수와 상용 AI 요금을 비교한다. 기록 없이 효과를 주장하지 않는다.

### 5-4. 전송·저장 경량화 — 자료 물류 (설계)

- 자료(기출 PDF·사진·영상)마다 D_asset = 조회·인용 비중 × (최근 증가량 + 0.1) ÷ (크기 MB + ε).
- 쓰임(초안):
  - D가 높은 자료는 시험 기간 전에 학원 PC·서버 가까운 저장소에 미리 받아 둔다(요청마다 원본을 다시 내려받지 않음).
  - D가 낮고 큰 자료(원본 영상 등)는 저렴한 저장 등급으로 옮기는 후보로 표시만 한다. 옮기기는 사람이 확인한 뒤에만 한다.
  - 휴대폰 → 서버 전송은 원본 대신 필요한 부분만 보낸다(렌즈 찾기는 아예 보내지 않음, 채점 사진은 판독 가능한 해상도까지만).
- AWS 저장 등급 변경·새 자원 추가는 비용·운영 영향이 있어 **원장님 승인 뒤에만** 한다. 측정: 한 달 S3 요청·전송량 기록으로 D 정책 적용 전후를 계산한다.

### 5-5. 공통 한계

- 세 값의 정의는 적용처마다 다르다. "같은 공식"이라는 것은 구조(정보량 × 변화 ÷ 부피)가 같다는 뜻이지, 값이 서로 비교 가능하다는 뜻이 아니다.
- 우선순위 배정·캐시·코스-투-파인 분석은 널리 쓰이는 방식이다. 신규 원리로 주장하지 않는다(PLAN 2장 7번).
