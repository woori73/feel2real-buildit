# Studio 폐지 자료 정리 (2단계: 보관 → 영구 삭제)

감독 지시(2026-11-12): "정리를 안 하면 서버에 자료가 계속 남아서 나중에 과부하가 되니 폐지 자료를 정리하도록".
안전을 위해 두 단계로 나눈다. 스키마는 V1108, 정책 원문은 [DOMAIN.md](../DOMAIN.md) Studio 절, API는 [API.md](../API.md) `/api/studio/cleanup/*`에 있다.

## 절차
1. **후보 보고**: AI 작업 세션이 `GET /api/studio-agent/cleanup/candidates`로 후보 목록을 받아 감독께 보고한다. 보고에는 작업 ID, 버전, 용량, 이유, 총 용량을 넣는다. 화면에서는 제작소 → "폐지 자료 정리·보관함" → ① 폐지 후보에서 볼 수 있다.
2. **1단계 보관**: 감독이 화면에서 승인할 버전을 고르고, 확인 메모를 적은 뒤 "선택한 후보 보관"을 누른다.
   - 보관한 버전은 목록·검색·버전 목록에서 빠진다.
   - "② 보관함"에서 언제든 되살릴 수 있다.
3. **2단계 영구 삭제**: 보관한 지 14일이 지나면 보관함에 "영구 삭제 가능"이 표시된다. 감독이 고르고 메모를 적은 뒤 "영구 삭제"를 누른다.
   - 14일이 안 된 버전과, 그사이 참조가 생긴 버전은 자동으로 제외된다.
   - 영구 삭제는 되돌릴 수 없다.
4. **삭제 기록**: 실행할 때마다 `studio_cleanup_log`와 `studio_events`(CLEANUP_*)에 남는다. 기록 항목은 무엇을, 언제, 누가 승인했는지, 지운 용량이다. AI 세션은 `GET /api/studio-agent/cleanup/log`로 기록을 읽어 Studio 문서(`EP01_STUDIO_CLEANUP_LOG`)로도 정리한다.

## 자동으로 막는 것 (보관·삭제 공통)
- 각 작업 ID의 최신본(head)과 승인본
- 원본(`source-*` 또는 origin ORIGINAL)
- 진행 중인 JOB 요청서(WAITING·WORKING·REVIEW)
- 현재 기준 자료: 작업 ID에 PRINCIPLES·CONTI·BLOCKING_MAP·FACE_SHEET·_REF·HANDOFF·PRODUCTION_LOG가 들어간 것
- 수정 작업(studio_tasks)이 참조하는 버전과 그 검수 보고서
- 다른 자료 본문에 버전 ID가 적혀 있는 버전

## 파일 처리
다른 버전이 같은 파일을 쓰거나 다른 자료 본문에 fileId가 적혀 있으면, 버전 행만 지우고 파일은 남긴다. 저장소 파일은 DB 커밋 뒤에 지운다. 저장소 삭제가 실패하면 경고 로그를 남긴다.

## 알아 둘 점
S11 r1~r10 시험 자료는 대부분 작업 ID 하나에 버전이 하나뿐이다. 그래서 그 버전이 곧 최신본이고, 규칙상 "최신본 보호"에 걸려 차단 목록에 나온다. 작업 ID 전체를 폐지하려면 최신본 보호의 예외 규칙을 감독이 따로 정해야 한다.
