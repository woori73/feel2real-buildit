## 3. 인증·암호화·개인정보 보안 보고서

양호한 점
- 인증정보를 받는 필드·저장소가 없다(비밀번호/OTP/인증서/쿠키 입력 API 없음). 로그인은 headed 브라우저에서 사람이 하고, 로그인 후 **별도 TTY 동의**를 받아야 수집이 시작된다. 작업마다 새 context, `finally`에서 close.
- vault: AES-256-GCM, 랜덤 12바이트 nonce, AAD=`v1:{businessId}:{id}:{object}` → 다른 사업체 파일명으로 복사/변조 시 복호화 실패. `CREATE_NEW`+`NOFOLLOW_LINKS`+600/700 권한, 작업트리 안 경로 거부, 평문 임시파일 없음. 서버 로그 출력 코드 없음.
- 수집기: 다운로드는 10MB 상한·메모리에서 암호화·UUID 파일명(서버 제안 파일명을 경로로 쓰지 않음), 외부 origin 요청·WebSocket·service worker 차단, 에러 문자열은 고정 코드만 서버로 전송.
- 업로드 브리지: loopback 한정, `redirect: 'error'`로 쿠키 타 호스트 전달 차단, 거래 행/토큰 미출력.
- SSRF: 서버가 사용자 지정 URL을 호출하는 코드 없음. 파일 업로드는 확장자 허용목록+크기+POI 수식 거부+PDF 암호/페이지 제한.
- CSRF: 앱 전역이 `csrf.disable` + 쿠키 `SameSite=Lax`(기존 정책). 교차 사이트 POST엔 쿠키가 실리지 않아 현 수준은 앱 전체와 동일. 단, 돈이 움직이는 `approve-and-commit`은 §6 P1-1의 별도 보강 대상이다.

미비·위험 (운영 전 필수는 §6)
- **키 관리**: 단일 정적 키(환경변수), 키 ID/버전 없음 → 교체·폐기 불가. Node 수집기 키와 서버 vault 키는 별개지만 동일 방식.
- **보관·파기**: 보존기간·삭제 정책 없음. 원본·감사는 추기 전용이라 개인정보/신용정보 파기 요청에 대응할 수 없다. 감사 파일은 이벤트당 1파일이라 **삭제 탐지 불가**(PR도 인정).
- **조회 감사 없음**: `GET /previews/{id}`는 거래처·적요가 담긴 drafts를 반환하지만 열람 이벤트를 기록하지 않는다.
- **최소 권한**: `requireAllowedBusiness`는 ADMIN이면 **모든 활성 사업체** 허용. "관리자도 불필요한 금융정보 접근 금지" 요구를 충족하지 않는다(사업체 단위 담당자 지정 없음).
- DB에는 평문 raw 행이 들어간다(기존 EASY 구조). "원본 암호화"는 **vault 파일에만** 해당하며 stage 이후 거래 데이터는 기존 DB 보호 수준이다.
- `externalAccount` 열의 원문(실계좌번호일 수 있음)이 DB·API 응답 drafts에 그대로 나간다. 마스킹 없음.

**운영 원칙 충돌 보고**: `MASTER_OPERATING_PRINCIPLES`/EASY 원칙은 `COLLECT → LEDGER SAVE → CLASSIFY`(수집 즉시 저장, 새 게이트 삽입 금지)이고, 이번 지시는 "승인 전 장부 불변"이다. PR은 이 충돌을 스스로 보고하고 이번 사용자 지시를 우선했다. 판단은 맞으나 **운영 정책으로 확정하려면 사용자의 명시 결정이 필요**하다(§7-A).

### P1 — 운영 활성화·#854 연동 전 필수
1. **"사람 승인"이 서버에서 검증되지 않는다.** `userApprovedUpload`, `reviewed`, `userApprovedLedgerCommit`은 클라이언트가 보내는 불리언이다. #854는 승인 후 "기존 업무 REST API"를 사용자 토큰으로 호출하는 구조라, allowlist 문서 약속(코드 아님)이 깨지면 AI가 stage/commit까지 호출할 수 있다. → ① #854 도구 allowlist에서 `/financial-collector/**` 쓰기 경로 **명시 deny**(테스트 포함), ② `approve-and-commit`에 **일회성 확인 토큰**(검토 화면이 발급, 짧은 만료, `collectionId+reviewHash` 바인딩) 또는 재인증(step-up) 도입.
2. **최소 권한 미충족**: ADMIN=전 사업체. 사업체별 담당자(데이터 접근 grant) 도입 + `GET` 열람 감사 기록.
3. **키 관리**: KMS/키 버전(envelope에 key id), 교체·폐기 절차, 키와 데이터 물리 분리.
4. **보존·파기·삭제**: 보존기간, 파기 요청 처리(암호화 파쇄 crypto-shredding 등)와 감사 보전(WORM/해시체인) 양립 정책.
5. **파서 격리**: POI/PDFBox를 앱 JVM 안에서 실행 중. 자원 제한된 별도 프로세스(타임아웃·메모리·CPU)로 분리. 컨테이너 multipart 한도(105MB)가 앱 상한(10MB)보다 커서 큰 요청을 먼저 받아낸다 → 컨트롤러 전 단계 제한.
6. **#854/#855 병합 전 마이그레이션 번호 충돌 해소**: 두 PR 모두 `V1094__…sql`을 추가한다(main 마지막은 V1093). 둘 다 병합되면 Flyway 중복 버전 → prd 502(CLAUDE.md §4 원인과 동일). 먼저 병합되는 쪽이 V1094, 다른 쪽은 재번호.

## 9. PR #855 MCP Gateway 연동 검토

- #855의 `read-policy.json`은 **정적 허용 경로 목록**(GET 483건, easy 66건)이다. `/financial-collector/**`는 현재 **미포함 — 정상**. 병합 후에도 자동 포함되지 않도록 생성 스크립트(`build-inventory.py`)에 deny 규칙을 두고 테스트로 고정한다.
- `GET /previews/{id}`는 거래처·적요 drafts를 반환하므로 **MCP에 그대로 노출 금지**.
- 요청한 초기 읽기 4기능 매핑:

| 기능 | 기존 정책 경로 | 판단 |
|---|---|---|
| 수집 작업 상태 | `/api/admin/easy/collections/runs`, `/collector/tasks` 이미 포함 | 응답 필드에 원본 행·토큰이 없는지 **확인하지 못함** → 필드 allowlist 확인 필요 |
| 수집 자료 목록 | 없음 | **메타데이터만**(id, dataset, 기간, 상태, 건수, sha 앞 8자) 반환하는 신규 목록 엔드포인트 필요 |
| 처리 오류 | `report.issues`(코드 문자열) | issues 코드만 반환하는 요약 엔드포인트로 분리 |
| 미반영 거래 요약 | 없음 | 건수·금액 합계만. 거래처/적요 제외 |

- 인증정보·세션 토큰·원본 금융정보: #853에는 서버에 저장되는 기관 자격증명이 없어 노출 대상 자체가 없다. 노출 위험은 vault 파일(MCP 경로 없음)과 drafts 응답뿐 → 위 규칙으로 차단.
- 별도 확인 권고: #855 정책에는 `/api/admin/easy/transactions`, `/transactions/export`(거래처·적요 포함 원장 데이터)가 이미 포함돼 있다. "원본 금융정보 비노출" 원칙 기준으로 #855 검수에서 별도로 판단할 것.
- `SecurityConfig` 필터 체인을 #854·#855가 모두 수정한다 → 병합 순서 확정 후 두 번째 PR에서 충돌 재확인.
