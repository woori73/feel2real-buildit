# 02 — 여신금융협회 카드매출 (cardsales / "매통조") 조사

> 조사일: 2026-09-20 (PHASE 0). 표기: ✅ VERIFIED(원문 확인) / 🟡 PARTIAL(2차 출처) / ❓ UNKNOWN.
> **최상위 발견: 카드매출 전용 공식 OpenAPI 포털이 실재한다** — `openapi.crefia.or.kr` (가맹점 매출거래정보 통합조회시스템="매통조"와 동일 데이터 소스). 자동수집의 1차 경로가 존재하며, 스크래핑은 약관상 명시 금지.

## 1. 공식 OpenAPI (매통조 OpenAPI)

### 1.1 API 4종 — ✅ ([API 표준](https://openapi.crefia.or.kr/cfaApiGide/apiStandard))
| API | 내용 |
|---|---|
| 가맹점정보 API | 가맹점명·업종 등 가맹점 메타 |
| **승인정보 API** | 승인내역 조회 + 일별/월별 집계 (매출금액·거래일자·**승인번호**·미매입정보) |
| **매입정보 API** | 매입내역 조회 + 일별/월별 집계 (전표 카드사도착 기준: 매입금액·카드종류·**수수료**·거래일자·매입일자·**매입취소**·지급금액·**지급예정일**·부가세대리납부금액) |
| **입금정보 API** | 입금내역 조회 + 월별 집계 (카드사·결제계좌·입금일자·매출금액·**실입금액**·매출건수·**보류금액**·가맹점번호·부가세대리납부금액) |

→ 작업지시 조사 항목(승인/승인취소/매입/매입취소/카드사/가맹점번호/승인번호/승인일/승인금액/수수료/지급예정액·일/실제입금)이 **필드 수준으로 모두 커버**됨(승인/매입/입금 3단계 = SALE/SETTLEMENT/PAYOUT 모델의 원천 데이터).

### 1.2 기술 사양 — ✅
- OAuth2 `client_credentials`, 액세스 토큰 86400초, `Authorization: Basic {client_id:client_secret}`, JSON, 게이트웨이 `openapi.crefia.or.kr:24002` (예: `/oauth/token`, `/oauth2/mer/page?merNo=&pageIndex=&pageSize=` — [ 파이썬 예제](https://notion4570.tistory.com/875))
- 에러코드 체계 E01~E99. "일일 호출 횟수 제한" 존재 명시(수치 ❓).
- 개별 API의 요청/응답 필드 스키마 상세·최대 백필 기간: **이용기관 가입(로그인) 후 열람 가능** ❓ → 후속 과제.

### 1.3 이용 절차·동의 모델 — ✅ ([API란](https://openapi.crefia.or.kr/cfaApi/apiIntro), [이용약관](https://openapi.crefia.or.kr/useApp/signUpMain))
1. 협회 회원가입 → API 사용 신청 → 검토 → **클라이언트 ID/Secret 이메일 발급**
2. **가맹점(사업자)의 "정보 전송 이용 동의"가 조회 전 필수** (제6조, 유효기간 만료 시 재동의). 동의/취소 API를 직접 사용하는 "자체인증기관" 모드 존재
3. 제3자 제공 금지(제9조 2호), 거래기록 5년 보존(제24조)
4. ⚠️ **제22조 3호: API 이용기관조차 웹 조회화면 스크래핑 명시 금지**
- 운영 이력: 2022-04-20 시범오픈, "과금체계 마련 시까지 무료" ([뉴시스](https://www.newsis.com/view/NISX20220419_0001838950) 등 4개 매체) — **현재 과금 요율 공개 확인 불가** ❓
- 이용기관 자격 제한(업종 등) ❓

## 2. cardsales.or.kr 웹 조회 시스템

### 2.1 제공 데이터·그레인 — ✅ ([여신협회 공식 소개](https://gongsi.crefia.or.kr/portal/financialConInfo/branchCards))
- 승인내역: 거래시간/승인금액/승인번호/미매입정보, 일·기간·월 집계

- 반영 시점: 협회가 **카드사로부터 승인일·매입일 기준 익일 수집**(일 단위). 홈택스는 월 단위 → 집계 주기 차이 🟡([세무사 블로그](https://m.blog.naver.com/tax_blogg/223579596885))
- 조회 가능 기간(웹): 전전년도 1월부터, 1회 조회 최대 31일 🟡([슈가 docs](https://docs.channel.io/sugar/ko/articles/여신금융협회-카드매출자료-조회-d3dc7479)). 정산 데이터 매월 6일경/실적 15일경 갱신 🟡

### 2.2 로그인·파일 — 
- **엑셀 다운로드**: 승인내역 화면 [엑셀] 버튼 ✅ ([싸부넷 FAQ](https://ssabu.net/bbs_detail.php?bbs_num=262&id=&tb=board_faq)). 더존 WEHAGO 등 회계SW가 "신용카드매출엑셀업로드" 전표 자동화 운영 ✅
- 로그인: 사업자등록 대표자 회원가입 후 **ID/PW** 구조, 공동인증서/OTP 요구 언급 없음 🟡. 비로그인 봇 접근 시 "접속 제한" ✅관찰(자동화 탐지 존재). 최근 정책 변경 여부 ❓
- 제휴 카드사 10개(신한·삼성·KB국민·현대·롯데·하나·BC·농협·씨티·우리) 통합 조회 ✅

## 3. CODEF/중계 API 지원 여부

- **CODEF에 가맹점 카드매출(매통조) 상품 없음** ✅ — developer.codef.io CARD 도메인은 카드회원(개인/법인) 승인·청구내역만. (단 06번 문서 참고: 2023 PDF에 여신협회 상품 존재 기록 → 현재 YS 카테고리 비어있음, 벤더 확인 필요)
- 중계 상용화 사례: **하이픈코퍼레이션** "여신금융협회 기준" 승인/매입/입금 조회 API 16종(ERP·세무용) 🟡 [hyphen.im](https://hyphen.im/product/view?seq=12), **Octover** "가맹점 매출 정산 패키지"(소스: 여신협회·배달업체·홈택스) 🟡 — 재판매 구조(매통조 API 계약 vs 계정 위임) ❓ 영업 확인 필요
- **EASY 권고**: 하이픈류 재판매보다 **협회 OpenAPI 직접 이용기관 신청**이 종속 감소·근거 명확.

## 5. EASY 설계 결론

1. **CardsalesAdapter = 매통조 OpenAPI 기반** (승인→매입→입금 3-API 구조 그대로 SALE/SETTLEMENT/PAYOUT 관계 모델로 매핑, →14번 문서). dedupe 1차 키: 승인번호(승인), 매입일자+금액(매입), 결제계좌+입금일자+실입금액(입금).
2. 전제 조건: ① 협회 이용기관 승인(자사 사업자 자격 확인 필요) ② 고객(가맹점)별 **전송동의 수집·관리 화면** ③ 재동의 만주기 추적.
3. 폴백: 이용기관 승인 전/실패 시 **엑셀 다운로드 → 기존 import 파일 업로드 반자동 경로** 재사용(자격증명 0).
4. 미해결(가입 후 확인): 필드 스키마 원문, 백필 한도, 일일 쿼터, 과금 여부, 이용기관 자격.
