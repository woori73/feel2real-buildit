# 개발 우선순위·예상 기간·비용 보고서

## 1. 전제

- 비용은 2026년 한국 시장의 **기획·디자인·개발·QA·보안·세무검증을 포함한 총인건비성 예산의 거친 범위**다.
- 1 FTE-month를 약 1,200만~2,000만원으로 가정했다. 실제 내부 인건비·외주 단가·병행작업에 따라 달라진다.
- 외부 금융·세무 API는 대부분 계약 견적이 필요해 개발비와 분리했다.
- 기존 EASY 자산을 재사용하며 DB 변경·코드 구현은 후속 승인 이후에만 한다.

### 출시안

- **Lean Pilot (내부/제한 고객):** 단계 0~3, 5~7개월, 약 6~11억원.
- **Commercial Ledger:** 단계 0~5, 병렬 수행 시 9~14개월, 약 11~22억원 + 외부 제휴비.
- **Full tax/payroll suite:** 신고·급여까지 15~24개월, 누적 약 20~40억원 + 지속 유지·검증비.

금액보다 중요한 변수는 외부수집 계약과 신고 책임범위다. 이 두 결정이 늦으면 개발자를 늘려도 일정이 줄지 않는다.

## 3. 우선순위

### P0 — 착수 전 필수

1. `user-business-role` 권한과 사업체 격리 위협모델
2. 세무대리/상담/신고 제출의 법적 경계
3. 외부수집 build-vs-buy 및 자격증명 보관 원칙
4. 계정과목·분개·마감 정책의 회계 검증
5. 개인정보·주민번호·금융정보 처리와 보존정책

### P1 — 1차 매출 가능한 제품

1. 사업자 온보딩과 월 장부
2. CSV/파일수집과 자동 분류 추천
3. 사용자 승인 후 분개
4. 검토 큐, 증빙 상태, 수정로그
5. 손익·현금흐름·세무사 전달 export

### P2 — 경쟁력

1. 정식 카드/계좌 수집 1~2개
2. 증빙 업로드/OCR
3. 반복거래 개인화
4. 결산·신고 사전검토
5. 세무사 협업 포털

### P3 — 고위험 확장

1. 부가세 신고서/전자파일
2. 원천세·지급명세서
3. 종합소득세
4. 급여·연말정산·4대보험
5. 실제 제출/대리 연계

## 5. REA 활용성 검토

공식 자료 기준 현재 `rea-agents`는 웹페이지 CDP 관찰, DOM/접근성/스크립트/리소스·네트워크 메타데이터, 정적 번들 분석, 제한된 Playwright 시나리오와 Evidence 비교를 제공한다. 웹 관찰은 범위를 제한하고 값 대신 shape를 수집하며, 일반 브라우저 자동화 도구가 아니라 증거 수집 도구로 설계돼 있다. 근거: [REA README](https://github.com/morluto/rea), [웹 관찰 문서](https://github.com/morluto/rea/blob/main/docs/browser-observation.md).

환경 확인 결과:

- Node.js `v26.5.0`: 요구조건(22.19+, 24.11+, 또는 26+) 충족
- npm `11.17.0`: 사용 가능
- `rea` 명령: 설치되지 않음
- 조사일 npm 공개 최신 표시는 `rea-agents 6.4.0`이었으나 빠르게 변하는 패키지이므로 도입 시 재확인 필요

이번에는 지시대로 설치·setup·MCP 등록을 하지 않았다. 따라서 **호환성은 충족, 실제 REA 실행은 미검증**이다. 후속 승인 시 별도 브라우저 프로필·loopback CDP·허용 origin을 사용하고, 이지샵 계정정보·쿠키·storage value를 Evidence에 포함하지 않는 최소 캡처 정책이 필요하다.

## 6. 성공 기준과 중단 기준

### Pilot 성공 기준

- 사업체 간 접근 누출 0건
- 승인 없는 transaction/journal write 0건
- Top-3 분류 추천 정확도 90% 이상(업종별 별도 측정)
- 수집 재실행 중복 전기 0건
- 장부↔분개 합계 일치 100%
- 모든 수정의 actor/before/after 추적 100%

### 중단/재설계 기준

- 합법적·안정적 외부수집 계약을 확보하지 못함
- 세무대리 범위를 피할 수 없는 제품 요구가 생김
- tenant 격리를 기존 관리자 구조에 안전하게 적용할 수 없음
- 신고 규격 유지·검수 인력을 상시 확보할 수 없음

## 7. 다음 승인 요청안

다음 단계에서는 구현이 아니라 3주짜리 **P0 설계 스프린트**만 승인받는 것이 합리적이다.

1. tenant/권한 상세설계와 데이터 마이그레이션 초안
2. 장부 MVP 화면설계
3. 외부수집 공급자 RFI 문서
4. 회계·세무 검수 체크리스트
5. AI 제안 schema와 골든셋 계획

이 산출물을 승인받은 뒤에만 코드·DB 변경, REA 설치, 외부 공급자 접촉 여부를 결정한다.
