# REA 분석 결과와 안전한 설정 절차

기준일: 2026-10-12  
공식 저장소: https://github.com/morluto/rea  
npm 패키지: `rea-agents`

## 1. 조사 결론

REA는 웹페이지를 CDP로 관찰해 DOM/접근성 구조, 공개 JavaScript와 번들, 리소스·네트워크 메타데이터, 사용자 동작 흐름을 Evidence로 남기는 도구다. 일반적인 브라우저 자동화 자체가 목적이 아니라 재현 가능한 근거 수집에 초점이 있다. 실제 클릭과 기능 검증은 Playwright 시나리오를 제한적으로 함께 사용한다.

이번 조사에서는 REA를 설치하거나 MCP에 등록하지 않았다. 환경 호환성만 확인했다.

| 항목 | 확인값 | 판정 |
|---|---|---|
| Node.js | `v26.5.0` | 호환 |
| npm | `11.17.0` | 사용 가능 |
| `rea` 명령 | 없음 | 미설치 |
| npm 공개 버전 | 조사 시점 `rea-agents 6.4.0` | 설치 직전 재확인 필요 |

## 2. 설치 전 조건

- Node.js 22.19+, 24.11+ 또는 26+ 계열
- Chrome/Chromium과 Playwright를 실행할 수 있는 로컬 환경
- 조사 전용 Chrome 프로필
- 허용할 origin과 조사 범위를 문서로 고정
- 실제 계정정보·금융정보를 Evidence에 저장하지 않는 마스킹 정책

클라우드 Work가 사용자 PC의 브라우저나 `localhost` CDP에 자동 접근한다고 가정하지 않는다. REA와 관찰 대상 Chrome은 연결 가능한 동일 실행 환경에 있어야 한다.

## 3. 공식 README 기준 설치 절차

설치 승인을 받은 후 공식 README의 현재 명령을 다시 확인한다. 조사 시점의 기본 진입 명령은 다음과 같다.

```bash
node --version
npm --version
npm view rea-agents version
npx rea-agents setup
```

`setup`은 로컬 설정과 MCP 연결에 영향을 줄 수 있으므로 별도 승인 없이 실행하지 않는다. 저장소의 production dependency로 추가하지 말고 분석 도구로 분리한다.

설치 후에는 다음을 기록한다.

- 설치한 `rea-agents` 정확한 버전
- Node/npm 버전
- 설정된 브라우저와 CDP endpoint
- 허용 origin
- 생성된 설정 파일의 위치와 민감정보 포함 여부

## 4. 권장 관찰 절차

1. 조사 전용 Chrome 프로필을 만든다.
2. loopback 주소에만 CDP를 연다.
3. 공개 페이지부터 관찰하고 DOM/접근성/공개 script/resource 구조를 기록한다.
4. 인증이 필요한 화면은 정상 계정으로만 로그인하고 우회하지 않는다.
5. Playwright는 화면 이동·버튼·검증 가능한 결과 확인에만 사용한다.
6. Evidence에는 값 대신 필드명·shape·상태 전이·URL pattern을 우선 기록한다.
7. 조사 종료 후 로그인 세션과 브라우저 프로필을 전달 산출물에서 제외한다.

## 5. 이지샵 분석에 적용한 분류

모든 사실은 아래 세 등급 중 하나로 기록한다.

- **실제 확인**: 정상 로그인 또는 공개 화면에서 직접 확인
- **공식 설명 확인**: 이지샵 공식 홈페이지·도움말·안내 문서로 확인
- **기술적 추정**: 공개 UI/JS/network shape로 추론했지만 서버 동작이나 내부 구현은 미확인

접근하지 못한 기능은 `미확인`으로 남긴다. 요금 결제, 금융기관 연결, 신고 제출, 실제 사업자·금융정보 입력은 하지 않는다.

## 6. 수집 금지 정보

- 로그인 ID와 비밀번호
- Cookie, Authorization header, access/refresh token
- localStorage/sessionStorage의 값
- 인증서, 공동인증서 파일, API key
- 실제 사업자등록번호, 주민번호, 계좌·카드 전체번호
- 실제 거래·급여·세금신고 원문
- 타사 비공개 source map, 비공개 API 응답 원문, 우회로 얻은 데이터

오류 재현에 식별자가 필요하면 합성값 또는 해시로 대체한다.

## 7. 이 조사에서 확인한 주요 시사점

- 초보 사용자의 핵심 흐름은 기술 용어보다 `자료 수집 → 자동 정리 → 확인할 것만 검토 → 신고 준비`로 보여야 한다.
- 자동수집은 화면 문제가 아니라 공급자 계약, 사용자 동의, token lifecycle, 재시도·중복·대사가 핵심이다.
- 장부와 분개는 원본 추적 및 사용자 승인 구조를 유지해야 한다.
- EasyShop과 유사한 기능은 재현하되 문구·화면·비공개 구현을 복제하지 않고 독립 요구사항으로 재구성한다.

세부 기능 분석은 같은 폴더의 `01_easyshop_feature_flow_analysis.md`와 `03_easyshop_vs_easy_comparison.md`를 참고한다.
