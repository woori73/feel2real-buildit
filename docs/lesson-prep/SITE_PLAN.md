# F2R 학습 사이트 — 두 페이지 구조 (대표 지시 2026-11-22)

> 대표가 정한 큰 틀. 이후 작업은 이 문서를 기준으로 한다. 조사 자료(영어·수학 서비스 화면, 국어 등 비영어 조사서)의 **구조와 흐름**을 반영하고, 이름·문구·그림·문항은 F2R 것을 쓴다.

## 1. 큰 틀

| 페이지 | 누가 | 하는 일 |
|---|---|---|
| **① 학생 풀이 페이지** | 학생 | 과목·시험을 골라 화면에서 문제를 푼다. 게시된 자료만 보인다 |
| **② Claude와 함께 문제 제작 페이지** | 원장·강사 + Claude 세션 | 공장식으로 자료를 만든다. 게시하면 ①에 올라간다 |

화면은 깔끔하게: 위 메뉴 + 왼쪽 메뉴, 표·카드, 여백 넉넉히(`fragments/_prep_shell.html`, `worksheets.css`의 모양을 기준으로 한다).

## 2. 과목·시험 구분과 풀이 형태

| 구분 | 학생 풀이 형태 | 지금 있는 것 |
|---|---|---|
| 내신(영어) | 지금의 **디지털 모의고사** 형태 그대로 | `/naesintest` (tp_exams kind=NAESIN, 3개 학교·학년 34회차) |
| 수능 | 해설·모의고사 | `/csat/2027-english`, `/wiki`, 예비고1 `/naesintest/pre-high` |
| iBT · SAT | 지금 사이트 형태를 **조금 더 개선** | `/testprep/practice`(9세트), `/testprep/sat`(4세트) |
| TOEIC | iBT와 비슷하게 풀되 **잘 틀리는 부분을 섹션별로** 구성. 지금은 **Part 5·6 어휘·어법 강조** | `/testprep/toeic`(3세트: 1회분 + 독해 2세트) |
| 국어 · 수학 · 사회 · 과학 등 타과목 | **디지털 모의고사** 형태 | 없음 — 조사서의 시범 문항 9개는 검수 전 시안 |

타과목은 영어처럼 세부 구성(단원 트리·유형 체계)까지 하지 않는다. **기출과 시험범위 자료가 주어지면 그에 맞춰 유사 문항을 만드는** 방식이다. 필요한 자료는 더 구해 와서 만든다.

## 3. 제작 공정 (공장식, 모든 자료 공통)

```
① 기출 분석 → ② 시험범위 자료 (공인시험은 기출 업데이트) → ③ 변형·유사 문제 제작
→ ④ 검수: 만든 세션이 아닌 세션 최소 3곳 → ⑤ 검수 의견 반영해 수정 → ⑥ 게시 = 학생 풀이 페이지에 올림
```

- 지금 있는 것: 제작 작업 대기열(`CoordPcTaskService`, `coord_jobs` kind=PC_TASK, MCP `f2r_pc_task_*`) — 요청·맡기·검수·완료까지 있고 화면은 없었다 → 제작 현황판 `/dashboard/factory`를 얹었다. 검수 필요 수 2곳 → **3곳**(반영함). 상세: [FACTORY.md](FACTORY.md).
- 문항 표시 3종(국어 조사서): 기출 평가 요소 기반 / 시험 범위 연계 / 개념 연습. 모두 F2R의 새 문항이고, 근거 자료는 내부에 남긴다.
- 시험 범위는 여러 쪽수 구간으로 적는다(예: 12~45쪽, 72~83쪽, 92~115쪽). 시작·끝 쪽만 적으면 빠진 쪽에서 문제가 나온다.
- 다른 회사의 지문·문항·그림은 싣지 않는다. 기출은 **평가 요소·사고 과정·오개념**만 읽고, 지문·보기·선지·해설은 새로 쓴다.
- Claude API는 전 환경 기본 OFF(CLAUDE.md)이므로, 「Claude와 함께」는 지금 구조대로 **Claude 세션이 MCP로 작업 대기열을 처리**하는 방식으로 잇는다. 화면은 요청·진행·검수·게시를 보여 주고 지시 문장을 건넨다.

## 5. 대표가 정할 것

1. 타과목 시범 문항 9개(국어 5·수학 1·사회 1·과학 1·한국사 1)를 학생 페이지에 올릴지 — 지금은 「검수 전 시안」이라 올리지 않는다.
2. 학생 풀이 페이지를 로그인 없이 열지, 기록 저장은 로그인 후로 할지(조사서 제안: 무료 풀이는 비회원도, 기록은 계정에).
3. 게시 권한: 검수 3곳 통과 뒤 원장 승인 한 번을 거칠지(기본값: 거친다).
