# 04. BuildIt 홈 첫 화면 개편 설계서 (spec)

> **이 문서는 설계만 담는다. 코드 수정·PR·배포·AWS/DB 변경을 지시하지 않는다.**

## 0. 설계 목표와 측정 기준

| 지표 | 현재(실측) | 목표 |
|---|---|---|
| 첫 화면(PC 900px) 내 서비스 진입 링크 수 | **0** (헤더 4개는 라벨 오류, 서비스 카드와 무관) | **8** (카드 CTA) + 헤더 4 |
| 첫 화면(모바일 844px) 내 서비스 진입 링크 수 | **0** (햄버거 2클릭 필요) | **4장 + 전체보기 1** = 5 |
| `#services` 도달 스크롤 | PC 3453px(3.8화면) / MB 4523px(5.4화면) | **PC 368px(0.41화면) / MB 300px(0.36화면)** |
| 주요 기능 도달 클릭 수 | 2~3 (햄버거→행, 또는 스크롤→카드→CTA) | **1** |
| 헤더 라벨↔목적지 불일치 | 4개 중 2개 | **0** |
| 문서 길이 | PC 8732 / MB 11005 | **PC ≤ 8000 / MB ≤ 9500** (압축은 2단계, 본 개편 범위 외) |

**원칙 (메가스터디 P1~P7 적용, 01 §8)**: 첫 화면 = 진입구, 첫 화면 아래 = 설명. 단 메가스터디처럼 1480 고정 캔버스·별도 모바일 호스트는 **따르지 않는다**(반응형 단일 코드 유지).

### A. 상단 헤더

| 항목 | 스펙 |
|---|---|
| 높이 | 68px 유지 (`landing_v3.css:61`), `position` sticky, 스크롤 시 `.scrolled` 배경 유지 |
| 로고 | `a.nav-brand` → `/` (현행 유지) |
| 카테고리 | **4개 고정 + 드롭다운 없음** (메가스터디 GNB 패턴). 라벨/URL은 §2 표 |
| 인증 | `div.auth-actions[data-auth-actions]` = `button.btn-login`(모달 오픈) + `a.btn-signup href="/register"`. **현행 마크업 그대로 재사용** — 비로그인 시 서버 HTML에 `hidden`으로 있고 JS가 해제(02 §9, `anon_home.html` 실측). **로그인 시 `account-menu`(👤)로 자동 교체** |

## 2. 버튼 동작 규약

| 버튼 | 타입 | 동작 | 검증 기준 |
|---|---|---|---|
| 헤더 카테고리 4 | `a[href]` | **동일 탭 즉시 이동** (드롭다운/호버 아님) | 메가스터디 GNB 패턴(01 §2). `javascript:;` 금지 |
| 카드 CTA 8 | `a[href]` | 동일 탭 이동. **중클릭/⌘클릭로 새 탭 가능해야 함** (`<a>`여야 하고 `<button onclick>` 금지) | 02 §11 P2 (`#hero` 폼 submit 회피) |
| "전체 서비스 보기" | `a[href="#services"]` | 인페이지 앵커 스크롤 (`html{scroll-behavior:smooth}` 이미 존재, `landing_v3.css:778`) | |
| 로그인 | `button[data-auth-login]` | **현행 유지**: `login-modal` 오픈 (페이지 이동 아님) | `/signin`은 **404**이므로 절대 링크 생성 금지 (02 §9 실측) |
| 회원가입 | `a[href="/register"]` | 이동. 개편 시 `?returnUrl=%2F` 부가 권장(현행 드롭다운은 `/register?returnUrl=%2F`) | |
| 문의하기 | `button onclick="openContactModal()"` | 모달 유지. **모바일 드로어에도 동일 버튼 1행** | |
| C-1 "만들기" | `button[type=submit]` inside `form.v3-ask[data-buildit-form]` | **로직 변경 금지** — 기존 submit 핸들러 그대로 | 기능 보존 조건 §4 |
| 모바일 드로어 행 | `a[href]` × 8 + 로그인/회원가입 + 문의 버튼 | 1클릭 이동 | 현행 5행 → 8행 + 인증 2행 |

**부드러운 실패**: 게이트된 서비스(`/builder`, `/problem-generator`, `/ledger`, `/easy`) 링크는 302가 아니라 **200 공개 소개 페이지**에 도달한다(02 §9). 따라서 카드 href에 `?returnUrl` 류를 붙일 필요가 없다.

## 3. 반응형 브레이크포인트 (기존 토큰 재사용, 신규 발명 금지)

### 권장: **안 C 혼합형**

근거 3가지 (모두 실측 기반):
1. **"첫 화면 = 서비스 8개" 요구를 설명·배지와 함께 충족** (안 A의 무설명 아이콘 대비). 02 §11 P0 1번을 직접 해결.
2. **AI 홈페이지 제작을 제거하지 않고 1순위에 유지** — 지시문 §4 단서 조항을 안 B(그리드만)보다 명확히 충족. C-1 좌 분할이 `#hero` 폼의 새 집.
3. **소식 패널**로 "새 서비스·업데이트" 요구(§4-C)를 만족하면서, 메가스터디의 배너 3중 스와이퍼·칩 22개는 도입하지 않아 **BuildIt의 독자적 서비스 포털 성격**을 지킨다(01 §9).

안 B는 "카드만"이라 문의 전환·소식 전달이 약하고, 안 A는 캐러셀/아이콘 세트라는 신규 UI 인프라를 요구해 §7 금지사항(기능 변경) 우회 리스크가 있다.

## 6. 이 설계가 **하지 않는** 것 (범위 통제)

- 문서 길이 압축 (PC 8732 / MB 11005) — 2단계 과제. 이번 개편으로 첫 화면 도달은 개선되나 총 길이는 줄지 않는다.
- `/home`(F2R)과 `/`의 통합 — 두 홈 문제는 02 §5에 기록하되 **라우팅/IA 개편이 필요하므로 본 설계 범위 밖**. 이번에는 헤더에서 "F2R" 링크를 빼는 것까지만.
- `/easy`, `/newstart`, `/choonggi`, `/lms/*`, `/wemade` 노출 — 03 §1-B에서 제외 확정.
- `/report`, `/shorts` 카드화 — **미존재** (03 §1-C).
- 검색 UI — 메가스터디는 통합검색(`search_ai`)이 있으나 BuildIt에 대응 라우트가 **없음(미검증)**. 신규 URL 발명 금지에 따라 제외.
- 디자인 토큰 변경(색·타이포·간격) — 기존 `--v3-*` 재사용.
