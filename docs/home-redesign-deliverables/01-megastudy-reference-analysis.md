| PC 뷰포트 | 1440 × 900 |
| PC 대상 URL | `https://www.megastudy.net/megastudy.asp` |

| 좌표 측정법 | `getBoundingClientRect()` + `scrollY` (문서 좌표, px 반올림) |
| 스크롤 동작 | `document.documentElement.scrollTop` 설정 후 별도 evaluate로 재확인 |
| 주석 이미지 | `annot-megastudy-pc-1440-fold.png`, `annot-megastudy-mb-390-fold.png` |

**핵심 구조 사실**: 메가스터디는 반응형이 아니다.

- PC: `<meta viewport width=1480>` 고정 캔버스. 실측 스크롤 폭 1480px, 1440 뷰포트에서는 좌우가 잘림.
- 모바일: **별도 호스트** `m.megastudy.net` / 별도 템플릿. 뷰포트 `device-width`, 실측 content width **375px** (390 뷰포트 대비 15px 우측 여백).
- 즉 "한 페이지가 리플로우"하는 게 아니라 **PC용/모바일용 IA를 각각 설계**한다. BuildIt 개편안의 브레이크포인트 전략에 영향을 주는 사실(§5 참조).

## 8. BuildIt이 "정보 구조·동선"만 가져올 것 (복제 아님)

| 가져올 원칙 | 근거 | BuildIt 적용 방향 |

| P1. 첫 화면에 **주메뉴 = 서비스 목록**을 실제 href로 | GNB 7개 전부 1클릭 이동, `javascript:;` 없음 | 헤더에 서비스명 + 실링크 |

## 9. 가져오지 않을 것 (독자성 확보)

- **1480px 고정 캔버스 + 별도 모바일 호스트** 방식 → BuildIt은 반응형 단일 코드로 유지 (유지비용, SEO, 코드 1개).
- 배너 3중 스와이퍼 + 이벤트 칩 22개 → **판매/이벤트 중심 IA**. BuildIt은 서비스 포털이 목적이라 카드 수를 6–8개로 제한.
- 색상·타이포·插画·`javascript:;` 탭 패턴 → 디자인 요소는 BuildIt 기존 토큰(`ag-dark`, `v3-*`) 사용.
- 문서 높이 3346px 이상으로 늘리는 것 → BuildIt은 오히려 **첫 화면 압축**이 목표.
