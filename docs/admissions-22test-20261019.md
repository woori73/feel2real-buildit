# 2027 입시상담 AI — 개발 DB 적재 + Muse Spark 실제 LLM 22건 평가 보고 (2026-10-19)

> 범위: 개발 DB 구성, draft-seed-2027.json 적재, 실제 Muse Spark LLM 22건 테스트, 실패 원인 분석·수정.
> 금지 사항 준수: 운영 DB 변경 없음 / 운영 배포 없음 / AWS 인프라 변경 없음 / 시크릿 값 노출 없음 / 미검증 입시자료 공개 없음.
> 이 저장소는 공개 저장소이므로 **미검증 입시자료와 답변 전문은 커밋하지 않았다.** 시드는 저장소 시크릿으로만 전달했고,
> 답변 전문은 AES-256 암호화 아티팩트로만 보관한다(복호화 키는 로컬에만 보관).

## 1. 개발 DB 구성 결과 (격리 스키마 `f2r_22test`, MySQL 8.4, localhost:3308)

| 항목 | 결과 |
|---|---|
| Flyway V1078 `add admissions tables` | 적용 성공 (전체 192개 마이그레이션, 최종 v1092) |
| `draft-seed-2027.json` 적재 | 대학 10 / 공식자료 20건 적재 (`/api/admin/admissions/load/seed`, loadSeed 형식) |
| 상태 유지 | 적재 직후 admissions_* 전체 **DRAFT** 확인 (materials 20 DRAFT, 나머지 테이블 0건) |
| 공개 차단 1 | `POST /api/admissions/chat`가 공개 API 기본 OFF에서 **503** + "아직 이용할 수 없습니다" 반환 |
| 공개 차단 2 | 격리 CI DB DRAFT 게이트: 전부 DRAFT 상태에서 질문 2건 → 근거(sources) 0건, LLM 미호출 |
| 코드 계약 | `AdmissionsFactSearchService`는 ACTIVE 행만 검색 (DRAFT/REVIEW는 검색되지 않음) |

- 공유 개발 DB(`f2r_db`)는 flyway 히스토리가 main과 발산해 있어(V983으로 적용된 위키 마이그레이션과 main의 V985 재번호 충돌)
  본 작업에서는 사용하지 않고 격리 스키마 `f2r_22test`를 사용했다. 작업 전 스냅샷 백업을 보관했다.
- CI 쪽 개발 DB는 격리 MySQL 8.0 서비스 컨테이너(`f2r_test`)를 사용하며 job 종료 시 소멸한다.

## 2. 실제 LLM 22건 테스트 환경

- 코드: main 기반 `AdmissionsChatService.ask()` + `MetaMuseSparkLlmTransport` (muse-spark-1.3-contributor)
- 시드: draft-seed-2027.json(뮤즈 수집본) + 기존 검증 시드 univ_sample(학과·전형·일정 상세행) + 상담 지식베이스 → 전부 DRAFT 적재 후 CI 격리 DB에서만 ACTIVE 전환(테스트 절차용, 소멸 DB)
- API 키: 기존 저장소 시크릿 `META_JIPJIGI_API_KEY`를 CI 앱 프로세스에만 주입. 값 출력·로컬 복사 없음.
- 평가: 기존 `e2e/admissions-live/run.js` 자동 규칙(근거 없는 답변·근거 밖 수치·합격 단정·학년도 혼동·거절 기대) + 사람 검토(사실 대조)
