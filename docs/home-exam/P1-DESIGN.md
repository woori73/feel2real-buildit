# 신청·자료·입금 관리 설계 (검토용, 운영 미적용)

P0 PR #919를 기반으로 한다. 기존 AcademyInquiry는 학원별 상담 도메인이고 신청 상품·계약·배송 상태가 없으므로 기존 인증/관리자 허브/저장소 인터페이스의 접근 통제 방식을 재사용하되 새 상품 접수 데이터는 분리한다.

## 활성화 경계

`app.exam-intake.enabled=false`가 기본이다. 신규 API/화면은 명시적으로 활성화하기 전 등록되지 않는다. 제안 SQL은 `docs/home-exam/proposed-schema.sql`에만 두고 Flyway 운영 위치에 설치하지 않는다. 로컬 테스트 전용 H2/격리 MySQL에만 적용한다. 운영 전에는 승인 후 최신 main 및 실제 flyway_schema_history를 확인해 다음 버전을 지정해야 한다(현재 저장소 최고 V1096; 문서의 오래된 V947 예시를 사용하지 않음).

운영 승인에는 DB schema, 비공개 파일 경로/볼륨·백업·삭제 정책, 악성파일 검사기, 개인정보 처리 동의/환불 안내, 계좌 등록·승인을 포함한다. 현재 운영 DB나 기존 미디어에 접근/변경하지 않는다.

## 데이터와 권한

- 기존 로그인 사용자가 문의/신청을 만들고 자신의 접수 메타데이터·진행 상태를 확인한다. 로그인하지 않은 방문자는 기존 카카오톡·이메일 경로를 계속 사용한다.
- 신규 접수에 상품 version/14일/주2회/4회/회당40/총160/20,000원 스냅샷을 저장한다. 현재 설정을 바꿔도 과거 접수는 변하지 않는다.
- 신청자는 제작 시작 전 내용 수정 및 자료 삭제를 **요청**한다. 제작 후에는 수정 요청과 취소 요청만 받는다. 관리자가 처리 이력을 남긴다. 승인 전 요청만으로 원본/개인정보를 지우지 않는다.
- 비공개 파일 본문 열람/다운로드는 **ADMIN만** 허용한다. 소유자도 목록·검사 상태만 확인한다. 다른 사용자의 ID 추측은 404, ADMIN 아닌 파일 다운로드는 403.
- 동시 제출은 소유자+멱등키+요청 해시로 중복 방지한다. 동일 키에 다른 내용을 재사용하면 409. 상태 변경은 버전 확인과 DB 잠금으로 동시 입금 확인/배송 중복을 막는다.

## 업로드

PDF/JPEG/PNG만, 파일당 10MiB·신청당 10개/총100MiB. 확장자+선언 MIME+실제 파싱으로 검증하며 이미지 픽셀 수와 PDF 페이지/객체 수를 제한한다. HTML/스크립트/첨부파일이 있는 PDF는 거절한다. 별도 비공개 디렉터리(0700), 난수 파일명, 파일0600, 공개 static 경로 및 기존 agent-media와 분리한다.
검사기 미설정/실패 시 격리하고 ADMIN에게도 본문을 제공하지 않는다. 실제 악성코드 검사 완료 후에만 열람한다. 스캐너 로컬 단위 테스트의 대역은 운영 검사 성공으로 표시하지 않는다. 업로드 실패 시 임시 파일 정리, 재시도와 SHA-256 중복 검사를 제공한다.

## 입금·제작·환불

계좌는 ADMIN 설정에서 등록하며 저장만으로 공개되지 않는다. 별도 승인 후 활성화한다. 승인된 계좌가 없으면 입금 확인 요청도 차단한다. 신청자가 누르는 “입금했습니다”는 확인 요청에 불과하고 ADMIN만 입금 완료로 바꾼다. 입금자명·접수 번호와 계약금액을 연결하며 임의로 납부액을 바꿀 수 없다.
계약당 총4회 전달을 별도 ordinal 기록으로 보존한다. 4/4는 전부 전달된 상태이며 검수/완료는 관리자 처리로 구분한다. 수정 요청은 추가 결제 확정 없이 접수한다.
환불은 요청→검토→승인→실제 환불 완료 **기록**의 별도 흐름이다. 금액 자동 산정/공제 및 송금 API는 없다. 제작 전/중/부분 전달/완료/사업자 귀책/7일 이후를 검토 정보로 구분한다. 7일 내15,000원은 사용자 제안이며 법적 확정 정책이 아니다. 금액·승인·환불 완료를 기록하는 운영 동작도 별도 운영 승인 후에만 사용한다.

## 알림과 보존

접수와 같은 트랜잭션에 outbox 이벤트를 저장한다. inquiry.created/application.created/document.uploaded/payment.confirmation_requested/payment.confirmed/revision.requested/refund.requested/application.overdue를 구분한다. 외부 전송 실패가 접수를 롤백하지 않는다. 이벤트 ID로 중복 식별, 전송 시도/재시도/상태/관리자 ACK를 기록한다. 알림에는 접수 ID·유형·인증된 관리자 화면 링크만 포함하며 이름·학교·연락처·본문·파일·토큰은 보내지 않는다.
Muse는 사용자 확인상 에이전트 알림 API가 없으므로 비활성. Muse Spark 유료 모델 호출은 하지 않는다. Dots는 서비스 식별/공식 API 미확인. 기존 SMTP를 별도 opt-in fallback으로 설계하며 테스트는 발송 대역만 사용한다.
개인정보·파일은 목적 달성 후 법령/승인된 보존 정책에 따라 삭제/비식별화해야 한다. 보존 기간이 미확정이므로 자동 삭제 작업은 활성화하지 않는다. 알림 outbox에는 ID/행위/시각/상태만 남긴다. 비공개 신청/변경 요청 및 변경 전후 감사 자료에는 개인정보가 포함될 수 있으므로, 보존 정책은 원본뿐 아니라 해당 이력과 계좌 감사 스냅샷에도 적용해야 한다. 법적 보존 의무/보존기간/백업 삭제까지 확정해야 운영 활성화할 수 있다.
