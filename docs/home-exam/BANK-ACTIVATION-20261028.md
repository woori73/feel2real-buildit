# 계좌·신청 운영 준비 (2026-10-28 KST)

사용자 지정 계좌는 관리자 등록용 비공개 JSON으로 준비했다. 실제 계좌번호는 저장소/공개 JS/CI fixture에 포함하지 않는다. `bank-registration.private.json`은 작업 산출물에만 있으며 관리자 계좌 설정의 파일 선택으로 입력할 수 있다. 파일 선택은 서버에 업로드하거나 저장/승인하지 않는다.

## 고객과 관리자 흐름

1. 신청 완료 후 승인 계좌의 은행·계좌번호·예금주·계약 입금액·신청번호를 표시한다. 미승인 계좌는 표시하지 않는다. 문의에는 입금을 안내하지 않는다.
2. 계좌번호 복사 실패/미지원은 수동 복사 안내로 처리한다.
3. 입금자명을 입력하고 입금 신고하면 `CONFIRMATION_REQUESTED`만 기록한다. 관리자만 실제 입금 확인 후 `CONFIRMED`로 바꿀 수 있다.
4. 카카오톡 확인 내용은 신청번호·입금자명·입금액을 포함한다. 고객이 복사하여 기존 카카오톡 채널에서 직접 보낸다. 자동 전송/외부 API 호출 없음.
5. 입금 신고 후에는 요청 당시 계좌 스냅샷을 표시하고 추가 입금을 안내하지 않는다. 관리자 입금·자료 확인 후 최대한 빨리 제작하고 1차 수정·검수를 거쳐 제공한다. 일정은 개별 안내한다.
6. 정상 전달·접근 가능 확인을 거친 회차만 제공 완료로 기록한다. 새 동의 버전 v2는 회차별 기본 환불 예정액을 안내한다. 예정액은 법정 확정액이 아니며 실제 승인/환불 송금과 분리한다. 과거 계약에는 소급하지 않는다.

## 사업자 정보

사용자가 제공한 출판사 상호/대표자/사업자등록번호/통신판매업 신고번호/주소를 Footer 후보로 구현했다. 기존 학원 정보와 구분한다. `app.home.exam-seller-confirmed=false`가 기본이며, 현재 판매 주체/등록 주소 확인 전에는 신규 정보를 게시하지 않는다. 로컬 검토는 명시적 true로 렌더링한다. 신고증 원본은 이 세션에 없고 현재 주소 확인 답변은 대기 중이다. 원본 이미지는 공개하지 않는다.

## 운영 활성화 전 실행 계획 — 이번에는 실행하지 않음

- 운영 승인 전 `app.exam-intake.enabled=false` 유지. 계좌정보 승인은 기능 활성화 승인과 다르다.
- 별도 승인 후 운영 담당자가 현재 배포 SHA/JAR 해시, DB 스키마와 Flyway 이력을 읽기 전용 확인하고 기존 #915 백업/복구 절차를 재사용한다. 이미 적용된 마이그레이션을 덮어쓰지 않는다.
- 승인된 암호화 저장소에 DB 일관 백업을 만들고 격리 복원으로 스키마/건수를 확인한다. 실행 시 자격정보는 기존 비밀 관리 경로를 사용하며 로그/명령줄에 값을 넣지 않는다. 현재 이 연결에는 AWS 실행 identity가 없어 실제 운영 복원 권한은 미검증이다.
- `docs/home-exam/proposed-schema.sql`의 신규7개 테이블을 차기 승인된 마이그레이션으로 변환한다. 기존 테이블/고객 행 수정 없음. 현재 PR에는 운영 Flyway 파일을 넣지 않았다.
- 전용 비공개 볼륨, 서비스 계정만 접근(디렉터리0700/파일0600), 백업·보존·삭제 정책을 설정한다. 기존 미디어 경로와 분리한다.
- 실제 악성파일 검사기(clamscan 절대경로, 최신 시그니처)를 준비하고 정상/유해 검증 파일, 타임아웃/실패 격리를 확인한다. 현재 로컬은 검사기 미설정에 따른 격리만 검증했다.
- 계좌 JSON을 관리자 화면에서 불러와 값 확인 → 저장(미승인) → 별도 승인 → 관리자 GET과 소유자 GET의 일치 확인. 이 운영 DB 변경도 별도 승인 후에 한다.
- 개인정보/미성년자/처리 이력/백업의 보존·삭제 및 법정 환불 정책 검토, 판매 주체/주소 확인, SMTP 수신 경로 검증 후 운영 활성화한다. Muse 알림 API는 사용자 확인상 없으며 Dots는 공식 연동 자료 미확보.
- 장애 시 우선 기능 플래그를 끄고 신규 접수를 차단한다. 승인된 정상 JAR로 복구하되 신규 접수/금융 감사 자료를 삭제하거나 이전 DB로 무조건 덮어쓰지 않는다. DB 복구는 변경 이후 접수를 별도 보존하고 복구 범위 승인·격리 복원 검증 후 수행한다.

## 검증 및 한계

로컬 Java/실제 앱 E2E, 최신 PR CI의 실제 결과를 PR에 기록한다. 로컬 실제 지정 계좌 캡처는 비공개 작업 산출물에만 보관하고 CI는 합성 계좌만 쓴다. 운영 등록 상태, 운영 브라우저·캐시·성능, 실제 은행 입금 조회/송금, 실제 카카오 메시지/이메일 발송은 미검증이다. 준비 기능과 실제 운영 활성화를 혼동하지 않는다.
