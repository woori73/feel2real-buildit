## 적용 내용

- 독립 시안의 78% 레이아웃·청백색 원형 HUD·6개 신청 메뉴를 실제 Thymeleaf 홈페이지에 통합.

- 메인 영상과 선택 포스터는 기존 코드가 선택한 동일 캐릭터 URL만 표시. `object-fit:contain`으로 원본 프레임 보존.
- 승인된 GLB가 없으므로 운영에는 3D 뷰어·진단 GLB·테스트 모드·유료 생성 경로를 포함하지 않음. `?preview3d=1`도 테스트 모델을 표시하지 않음.
- 22%는 기존 JARVIS 시안 대비 무대/메뉴 레이아웃 축소율이다. 이전 운영의 좌우 2열 배치에 대한 높이 22% 감소를 의미하지 않는다. 통합본은 시안대로 대화창을 무대 아래에 둔다.

## 배포 및 복구 기준

최신 성공 배포는 [run 40490751572](https://github.com/woori73/feel2real-buildit/actions/runs/40490751572), SHA `df425588c97d7f1fb668e23452e638bc9cb14fd4`. 로그에서 2026-10-27 10:48 UTC SSM Success, Spring 첫 PID 세대 health 성공, 최종 DEPLOY SUCCESS를 확인했다. 이는 배포 이력이며 현재 서버 JAR SHA-256을 직접 읽은 증거는 아니다. 오래된 `docs/DEPLOYED_BASELINE.md`의 10월 17일 기록을 현재 운영 버전으로 사용하지 않는다.

후속 실행 전 필수 확인:

1. 운영 DOM/Network에서 양 캐릭터 포스터·idle/speak/think MP4 응답, 실제 재생, 원본 SHA-256을 읽기 전용으로 기록한다.
2. 운영 JAR 해시, 미디어 파일 해시, main 최신 SHA, 현재 schema migration 상태를 기록한다. 이 PR은 Java/DB/Flyway 변경이 없지만 실제 배포 기준과 같음을 확인한다.
3. 기존 정상 JAR을 해시 검증된 고유 백업으로 확보하고 복구 실행 권한을 확인한다. `app.jar.previous`만 있다고 가정하지 않는다.
4. CI와 운영 검증이 모두 통과한 PR만 병합하고 그 SHA를 고정해 기존 `deploy-ec2.yml`을 실행한다. target=new, assistant_switch/hwpx_worker/mcp_switch/agent_media_public=unchanged. 기존 워크플로는 수동 실행만 지원한다.
5. 건강 검사 실패 시 기존 deploy guard가 이전 JAR/env를 복구한다. 건강 검사는 통과했어도 화면/미디어/로그인 회귀 발생 시 검증한 직전 JAR로 즉시 복구하고 동일 URL을 재점검한다. **현재 즉시 복구 실행 연결은 미확보**.

## 발견 및 권고

- 시안 브랜치를 그대로 병합하면 제품 홈페이지는 바뀌지 않으므로 필요한 화면 파일만 새 브랜치에 통합했다.
- 기존 반응형 검사는 메뉴가 영상 내부에 있다는 구형 배치 가정을 포함했다. 메뉴 기능·문구 검사는 보존하고 새 command 영역 경계 및 실제 클릭으로 검사한다.
- 새 로컬 검사에서 두 영상 버퍼가 짧게 함께 `is-on`인 구간 때문에 검사기 선택 오류가 발생했다. 재생 중인 버퍼를 원자적으로 선택하도록 검사기를 보완했다. 제품 영상 로직은 변경하지 않았다.
- 운영 원본 확인과 배포/롤백 인증이 확보되기 전까지 상태를 미검증으로 유지한다. 진단 모델이나 과거 캐릭터 시트로 대체하지 않는다.
