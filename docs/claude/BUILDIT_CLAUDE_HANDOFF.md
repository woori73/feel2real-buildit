# BuildIt 개발 인수인계 (Claude용)

이 문서는 BuildIt 프로젝트, 특히 **내신 Wiki**에 대해 Claude가 매번 새로 설명을 들을 필요 없이 유지해야 할 배경·구조·원칙을 담은 장기 인수인계서입니다.
이번에 당장 해야 할 작업은 이 문서가 아니라 별도의 `NAESIN_WIKI_V1_1_TASK.md`에 있습니다. 이 문서는 먼저 읽고 이해만 하면 됩니다.

---

## 1. Claude의 역할

Claude는 BuildIt 프로젝트에서 두 가지 역할을 담당합니다.

### 현재 역할 — Wiki 개발자
현재 구현되어 있는 내신 Wiki를 분석하고, 기존 기능을 재사용하여 UX를 정리·개선합니다.
새 시스템을 처음부터 만들지 않습니다.

### 향후 역할 — FINAL Editor
시험기간에는 내신 Wiki에 축적된 자료를 읽고 분석하여 FINAL 및 직보 자료를 편집·제작하는 역할도 담당합니다.
따라서 현재 개발 단계에서도, 나중에 AI가 자료를 효율적으로 찾을 수 있는 구조를 유지해야 합니다.

## 3. 내신 Wiki의 목적

내신 Wiki 안에 ChatGPT/Claude 수준의 범용 AI를 구현하는 것이 목적이 아닙니다. 역할을 분리합니다.

```
ChatGPT / Claude
→ 원본 자료 가공
→ 편집용 자료 + JSON

        ↓

내신 Wiki
→ 자료 저장
→ 문제 제작/변형
→ 학생 오답 축적
→ 수업 인사이트 축적

        ↓

Work / Claude
→ 축적 자료 분석
→ FINAL / 직보 편집
```

Wiki는 자료와 경험을 축적하는 Brain이고, 고도의 최종 판단과 편집은 Work/Claude가 담당합니다.

## 4. 모든 데이터의 중심은 시험 Context

다음 Context를 먼저 선택합니다.

```
학교
→ 학년
→ 연도
→ 학기
→ 시험
```

예:

```
신구중학교
2학년
2026년
2학기
중간고사
```

해당 시험에 관련된 자료를 여러 DB 화면을 돌아다니지 않고 한 Context에서 찾을 수 있어야 합니다.

## 5. 내신 Wiki의 4 CORE

분류는 당분간 더 늘리지 않습니다.

### 01. 제작 문제

축적 대상:
- Digital Twin으로 제작한 문제
- 기존 문제 변형
- 지문 기반 제작 문제
- 수업에서 사용한 문제
- 저장·선별한 문제

기존 기능인 Digital Twin, 문제 생성, 기존 문제 변형, 문제 저장, 문제 선택, Word 2007 내보내기를 최대한 재사용합니다.
Digital Twin은 별도의 5번째 CORE가 아니라, 문제를 제작·변형하는 지능입니다.

### 02. 학교 프린트

구조는 단순하게 `원본 + JSON`입니다.

학교 프린트 사진/PDF 등을 ChatGPT/Claude에 넣어:

```
원본
   ↓
ChatGPT / Claude
   ├─ 수업용 편집자료 → Word/HWP에서 사용
   └─ 구조화 JSON → Wiki 저장
```

합니다. Wiki 내부에서 고비용 OCR/문서복원 AI를 다시 구현할 필요가 없습니다.

### 03. 학생 오답

학교 프린트와 동일한 원칙을 사용합니다. 구조는 `학생 + 오답 원본 + JSON`입니다.

학생 오답 사진을 ChatGPT/Claude에서 처리하여:

```
학생 오답
   ↓
ChatGPT / Claude
   ├─ 편집용 자료 → 다음 학원 수업에서 사용
   └─ JSON → Wiki 저장
```

합니다. 이미 학생과 시험 Context를 선택했다면 학생명·시험명·유형·문제번호 등을 사용자가 반복 입력하게 하지 않습니다. 세부 정보는 JSON 내부에서 확장 가능하게 합니다.

축적된 학생 오답을 선택해서 Word 2007로 내보낼 수 있어야 합니다. 가능하면 기존 제작 문제의 Word 2007 export 구현을 찾아 재사용합니다.

---

## 6. 수업 인사이트

다음 두 가지를 하나로 통합합니다.

```
박원장 수업 인사이트
+
학교 선생님 시험 힌트
```

사용자에게는 **수업 인사이트** 하나만 보여줍니다. 필요하면 내부적으로 `source = academy_teacher` / `source = school_teacher` 정도만 구분합니다.

학생 개인에게 해야 할 지시도 특정 학생과 연결할 수 있어야 합니다. 예: "민준이는 관계대명사 다시 시킬 것", "Final 11번 다시 풀게 할 것".

## 7. 일반 사용자 화면과 AI 작업 화면을 구분

### 일반 원장 화면

```
STEP 1 자료 모으기
       ↓
STEP 2 수업 기록
       ↓
STEP 3 문제 준비
       ↓
STEP 4 FINAL / 직보
```

### Work / Claude Admin 화면

AI에게는 오히려 4 CORE 구조가 유용합니다.

```
FINAL WORKSPACE

시험 Context

① 제작 문제
② 학교 프린트
③ 학생 오답
④ 수업 인사이트
```

4 CORE 데이터 구조는 없애지 않습니다. 일반 사용자에게 처음부터 DB처럼 보여주지 않을 뿐입니다.

---

## 8. FINAL Workspace

Work/Claude가 시험기간에 특정 시험 Context로 들어오면 다음 자료를 한곳에서 탐색할 수 있어야 합니다.

```
FINAL WORKSPACE
────────────────────

신구중2
2026 · 2학기 · 중간

제작 문제       87
학교 프린트     12
학생 오답       64
수업 인사이트   19
```

모든 원본을 AI Context에 한꺼번에 넣지 않습니다. AI 작업 순서는:

```
시험 Context 확인
        ↓
4 CORE 목록/JSON 확인
        ↓
중요 신호 선별
        ↓
필요한 원본만 열기
        ↓
기존 제작 문제 검색
        ↓
선별 / 변형
        ↓
부족한 부분만 신규 제작
        ↓
FINAL / 직보
```

토큰 절약과 품질 유지를 위해 이 원칙이 중요합니다.

---

## 9. FINAL 제작 철학

Claude/Work는 새로운 문제집을 처음부터 만드는 역할이 아닙니다. 먼저 다음을 판단합니다.

**무엇이 시험에 나올 가능성이 높은가**
- 학교 프린트
- 학교 선생님의 최근 힌트
- 박원장 수업 판단

**학생들이 무엇을 어려워하는가**
- 학생 오답
- 반복 오답
- 공통 취약점

그 다음 기존 제작 문제에서 적합한 문제를 찾습니다.

```
기존 문제 적합
→ 선별

조금 수정 필요
→ 변형

적합한 문제 없음
→ 신규 제작
```

---

## 10. 직보 제작 철학

직보는 FINAL을 다시 줄여놓은 자료가 아닙니다. 시험 직전의 최신 신호를 강하게 반영합니다.

우선순위:

```
학교 선생님의 마지막 힌트
        ↓
박원장의 최근 수업 인사이트
        ↓
학생 반복 오답
        ↓
FINAL 핵심 문제
```

짧고 압축적으로 구성합니다.

---

## 11. 향후 학생 개인 코칭 콘텐츠 (이번 개발 범위 아님)

이번 개발에서는 영상 기능을 구현하지 않습니다. 하지만 향후 다음 데이터를 이용합니다.

```
박원장 Brain
+
Wiki Brain
+
AI Brain
        ↓
학생 개인별 시험 코칭
```

학생별로 지금까지 무엇을 공부했는지, 무엇을 반복해서 틀렸는지, 학교에서 무엇을 강조했는지, 박원장이 무엇을 다시 하라고 했는지, 앞으로 시험 전 무엇을 해야 하는지를 3~15분 정도의 개인 코칭 콘텐츠로 만들 수 있어야 합니다.

초기에는 LMS를 만들지 않고 학생/학부모에게 영상 링크를 전달할 수 있습니다. 따라서 다음 관계를 보존합니다.

```
학생
↔ 오답
↔ 수업 인사이트
↔ 시험 Context
↔ FINAL 문제
```

이 항목은 지금 구현하지 않지만, 지금 짜는 데이터 구조가 이 관계를 나중에도 보존할 수 있어야 한다는 뜻에서 기록해 둡니다.

## 12. GitHub 작업 규칙

Claude가 Private Repository 접근이 가능해지면 다음 순서로 작업합니다.

```
최신 main 확인
     ↓
기존 구현 검색
     ↓
작업 branch
     ↓
코드 수정
     ↓
테스트
     ↓
GitHub에 push
```

**Claude는 배포하지 않습니다.**

Claude 작업이 끝나면 다음만 보고합니다.

```
1. Branch
2. Commit SHA
3. 변경 파일
4. 변경 내용
5. 기존 기능 재사용 내용
6. DB/API 변경 여부
7. 테스트 결과
8. Work가 병합/배포할 때 주의할 점
```

그 이후 Work가 main 병합 → 기존 EC2 배포 → 실제 사이트 검증을 담당합니다.
