## 4. 536개 자료 운영 적재 방법

### 4.1 사실
- #865의 적재는 **ADMIN 전용 HTTP API**다: 고유 316개를 `POST /api/studio/files`로 올린 뒤(SHA 중복 제거라 재시도·이어하기 가능) `POST /api/studio/source-import`가 고정 카탈로그(`production-09d62dee.json`, 커밋 `09d62dee…`)와 SHA·크기를 대조하고 **한 트랜잭션**으로 536경로를 등록한다. 30번째 컷 실패 시 전부 롤백됨을 독립 확인했다. 재실행은 추가 쓰기 0건.
- 운영에는 `studio_projects` 행이 없다. 첫 단계는 ADMIN의 프로젝트 초기화(`POST /api/studio/project`, "《AI AGENT》 1부").
- 승인 포인터 5건은 #863 `MANIFEST.md`/`APPROVAL_HISTORY.md`의 **기존 사용자 승인 5종**을 이관하는 것이다(컷 승인 0, 원작 대조 0/68, PASS 0). 새 승인이 아니므로 사용자가 "이관해도 된다"고 확인해야 한다(§8).

### 4.2 결함: 적재 스크립트가 운영에 쓸 수 없다
`scripts/ai-agent-studio/import-production.py --apply`는 `http://127.0.0.1:18090` **루프백 격리 인스턴스에만** 허용한다(운영 실수 방지용 의도적 제한). 따라서 현재 상태로는 운영에 적재할 방법이 없다.
**필요한 코드 변경(별도 구현·검수, 승인 후):**
1. `--production` 모드: HTTPS 기본 URL(`https://feel2real.co.kr`)만 허용, 기본은 dry-run, 실제 적용은 `--confirm-snapshot <스냅샷명>`과 `--confirm-sha <배포 SHA>`가 있어야 진행.
2. 요청 `Origin` 헤더를 기본 URL과 동일하게 설정(앱의 Origin 검사 통과).
3. 인증: 사용자가 브라우저로 ADMIN 로그인 후 만든 쿠키를 0600 파일로 전달(명령행·로그에 남기지 않음).
4. 사전 점검: `GET /api/studio/source-import`의 등록 경로 수가 0이거나 536인지, 프로젝트 초기화 여부.
5. 업로드는 316개 순차·SHA 재조회 대조, 실패 시 중단(이미 올린 파일은 보존·재시도 가능), 마지막에 register 1회.
6. 결과 영수증(경로 수·SHA 표·시각, 쿠키 제외)을 저장하고 PR/보고서에 첨부.

### 4.3 운영 적재 후 검증(읽기)
- `GET /api/studio/source-import`: 등록 경로 536, 고유 316, 컷 대조 0, PASS 0.
- 승인 캐릭터 5종: 갤러리 표시 + 원본 다운로드 SHA가 `MANIFEST.md`의 5개 SHA와 일치.
- 68컷 모두 미승인, 승인 대기함에 보관용 536경로 제외, 공동 기억에 인계 문서 4개 복원.
- 운영 저장소(로컬 디스크 또는 S3 — **운영 설정 미확인**)의 여유 공간·권한: 약 164MB(고유 원본) 추가. S3면 요청·저장 비용은 미미하나 실측 전이다.
