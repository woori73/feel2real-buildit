핵심 안전 설계(승인 전 쓰기 차단, 해시 승인, 원자적 claim, 재조회 검증, 학원·사업체 격리)는 견고하다.
다만 사용자가 요청한 업무 중 **출결 조회·출결 정정·공지 초안이 지원되지 않거나 잘못 처리**되고(P1),
**Muse 호출 사용량 제한이 없다**(P1, 현재 local 한정 ON이라 운영 영향은 없음).
P1 수정 전에는 사용자에게 노출하지 말고, local/Draft 상태 유지를 권고한다.

## 2. 첫 방문 사용자 안내

코드상 구현됨: 최초 `firstVisit` 감지 → 6단계 투어 → 단계별 메뉴 강조(`ua-tour-target`, `aria-current`) → 서버에 진행 저장(버전 충돌 409) → 새로고침/재방문 시 재개 → 일시중지·다시보기. E2E가 PC에서 "다음 → 강조 → reload 후 2/6 유지"를 검증했다.

문제:
- **P2** 투어는 "강조"만 한다. 메뉴 링크를 눌러 실제로 이동해도 단계가 자동으로 진행·연동되지 않고 "다음" 버튼으로만 진행한다. 요청한 "안내와 실제 화면 상태 연결"에는 못 미친다. 메뉴는 `/academycraft/screens/*.html` 등 다른 페이지로 완전 이동하므로, 돌아왔을 때 단계가 어디인지 사용자가 알기 어렵다.
- **P2** 사용 목적에 맞는 메뉴 추천(2단계 요구)은 없다. 모든 사용자가 동일한 6단계를 본다(역할별 문구 1줄만 다름).
- **P3** 모바일 투어 강조(390px)는 E2E에서 투어 UI 자체를 검증하지 않는다(모바일은 명령→승인과 가로 넘침만 확인). 실기기 확인 필요(PR 본문도 "실기기 키보드" 향후로 명시).

## 3. AcademyCraft 업무

| 업무 | 결과 |
|---|---|
| 학생 등록 초안(자연어·CSV) | 지원. 이름 필수, 20행 제한, 열 중복·열 개수 오류 안내 |
| 반 배정 | 지원(CLASS_ASSIGN, 학생·반 스냅샷 + 재조회 검증) |
| 출결 조회 | **미지원, 오작동 (P1)** — 아래 |
| 출결 정정 요청 | **미지원, 오작동 (P1)** — 아래 |
| 상담 내용 정리 | 지원(CONSULT_CREATE/MESSAGE). 단 "정리"는 요약이 아니라 입력 그대로 저장 |
| 공지 작성 초안 | **미지원 (P1/P2)** — 파서·모델 허용 업무 목록 모두에 없음 |

파서 재현 결과(실행 확인):

| 입력 | 결과 |
|---|---|
| `학생 ID 5 출결 조회해줘` | `ATTENDANCE_RECORD {eventType=CHECK_IN}` ← **조회가 등원 기록 쓰기 초안이 됨** |
| `학생 ID 5 출결 정정해줘 결석으로` | `ATTENDANCE_RECORD {eventType=ABSENT}` ← **정정이 아니라 새 이벤트 추가(기록 중복)** |
| `이번 달 공지 작성해줘` | 빈 operation(안내 문구만) |
| `학생 ID 5 오늘 출석 확인` | 빈 operation |
| `이번달 지출 현황 알려줘` | OVERVIEW(정상) |

승인 단계가 있어 무단 저장은 아니지만, 사용자가 "조회"를 말했는데 "등원 기록" 카드가 뜨는 것은 업무 실패다. 또한 메뉴 설명이 "출결 기록·정정·월별 조회"라고 약속하는데 비서는 정정·조회를 못 한다.
**권고(Codex)**: 파서에서 `조회/확인/보여/알려`가 있으면 쓰기 분기 전에 OVERVIEW(또는 출결 조회 읽기 전용 응답)로 분기. 정정은 기존 AcademyCraft 정정 API가 있는지 조사 후 있으면 CORRECTION 업무 추가, 없으면 "기존 출결 화면에서 정정" 안내로 막기. 공지는 쓰기 없이 "초안 텍스트 제안"만 하는 읽기 전용 업무로 분리 권고.

학원 격리: 모든 학원 쓰기는 `academy.owner()`가 AcademyCraft context에서 `academyId` 일치 + `ACADEMY_OWNER`를 확인하고, 승인·재승인·히스토리 조회 시마다 재확인한다(권한 회수 후 재생 차단). E2E에 타 학원(academyId=8) 403, 권한 회수 403 케이스 있음. **양호.** 단, `CLASS_CREATE.teacherId`가 같은 학원 강사인지는 이 PR이 검증하지 않고 상위 API에 위임한다(E2E는 존재하지 않는 ID 거절만 확인). 상위 API가 타 학원 강사를 막는지 AcademyCraft 쪽 확인 필요 → 미검증.

## 4. 이지장부 업무

CSV 업로드·분석·분류·증빙 유형 보존·미리보기·승인·저장·재조회(거래 ID/일자/금액/방향 대조)·중복 방지는 기존 `EasyTutorImportService` 재사용으로 구현. E2E가 동일 CSV 재업로드 시 `duplicates=1, saved=0`, 동시 승인 6회 → 저장 1회, 타 사업체 403/404를 검증. 사업체 격리는 `requireAllowedBusiness` + 초안 소유자·역할 이중 확인. **양호.**

개선:
- **P2** CSV 업로드/`LEDGER_ENTRY` 초안 생성 시점에 이미 import 배치와 원본 행이 DB에 저장된다(승인 전). 거래(txn)는 아니지만 "승인 전 저장 없음"을 엄격히 해석하면 위반이다. 만료·취소된 초안의 고아 배치 정리 정책이 없다. 의도된 설계라면 문서에 명시하고 정리 배치를 계획할 것.
- **P3** `LEDGER_ACCOUNT`의 `accountId`는 `selectAccount`에서 활성 계정만 확인한다. 사업체별 계정 소속 검증은 해당 서비스 내부 로직에 의존(이 PR 범위 밖, 확인 권장).
- 금융자료 수집 자동화(작업 B) 중복 구현 없음. **확인.**

## 5. Muse 연결·응답

- 경로: `AssistantIntentAnalyzer` → 기존 `MetaMuseSparkLlmTransport`(Bearer 키는 기존 설정 `config.getApiKey()`로 주입, 코드·YAML에 키 없음). 기본 OFF(`model-analysis-enabled:false`), `application-local.yaml`에서만 ON.
- 출력 검증은 엄격하다: 키 2개 고정, operation별 필드 화이트리스트, 단일 값만, ID/금액 정수·양수, **ID는 원문에 실제 등장해야 함**(환각 ID 차단), `academyId/businessId/planHash/URL` 출력 불가, 삭제·승인·실행 문구는 모델 호출 전에 차단. 모델 출력은 초안만 만들 뿐 실행 권한 없음. 프롬프트 인젝션 대응 **양호**.
- 장애 시: `completion.ok()`가 아니거나 파싱 실패면 규칙 파서로 폴백하고 "AI 연결·응답 확인 필요"를 표시. **양호.**
- **실제 응답: 미검증.** 자격증명 없음. 필요한 조건: 환경변수/비밀 저장소에 Muse API 키와 base URL 주입(`/etc/f2r/env` 패턴), 비용 상한 승인.
- **P1(운영 ON 전 필수)** 사용량 제한 없음. `/conversation` 호출마다 Muse 1회이고, **TXT 업로드는 줄마다 `intents.analyze`를 호출**해 최대 20줄 → 요청 1건당 20회 호출 가능하다. 사용자별 분당/일일 한도, 업로드당 모델 호출 수 상한, 사용량 로깅이 없다. 비용 폭주·남용 위험.
- **P2** 원문(학부모 이름·연락처 포함 가능)이 마스킹 없이 외부 LLM에 전송된다. 개인정보 최소 노출 원칙상 연락처 패턴 마스킹 또는 동의 고지를 권고. 현재 local 한정이라 즉시 위험은 아님.

## 6. 권한·보안

양호: ADMIN/TUTOR 한정(`@PreAuthorize` + SecurityConfig), STUDENT·익명 차단(E2E 확인), 초안 소유자+역할 일치, 해시 위변조 409, 만료·취소·동시 승인(조건부 UPDATE claim), UNKNOWN 시 자동 재실행 금지, 인증키가 결과에 저장되지 않음, 업로드 256KB/확장자 제한/NUL 검사, 쓰기 기본 OFF.

지적:
- **P2** 쓰기 요청 방어가 `Origin` 헤더 화이트리스트(`http://localhost:8080`, `https://feel2real.co.kr`) **하드코딩**이다(전역 CSRF는 비활성이며 SameSite=Lax에 의존 — 기존 정책). 스테이징·`www` 도메인에서는 모든 쓰기가 403이 된다. 설정값(프로퍼티)으로 분리 권고.
- **P2** 감사로그는 `DRAFT_CREATED/APPROVED/상태`만 기록하고 operation·학원/사업체 ID·대상 ID가 없다. 사후 추적(누가 어느 학원의 무엇을 바꿨나)이 불충분. 승인 시 operation·scope 포함 권고.
- **P2** 실행 중 프로세스가 죽으면 초안이 `EXECUTING`에 영구 잔류하고 사용자에게 복구 경로가 없다(재승인 409). 일정 시간 후 UNKNOWN으로 전환하는 정리 작업 권고.
- **P2** `TUTOR`는 원장 연결이 아니면 모든 학원 쓰기가 403이다(의도된 설계, 투어 문구에 명시됨). 다만 PR 본문 "ADMIN·TUTOR가 업무 처리"는 강사에게 읽기 전용임을 더 분명히 쓸 것.
- 마이그레이션 `V1094`: 번호 정책(V909+ 순차) 충족, 신규 테이블만 생성. 운영 영향 없음.

## 9. 병합 가능 여부

**조건부 가능.** 안전 설계는 병합 가치가 있으나, (a) 요청 업무 3종의 오동작/미지원, (b) Muse 호출 상한 부재는 사용자 노출 전 수정이 필요하다. Draft 유지, 병합·배포는 사용자 승인 후. 수정은 Codex 브랜치에서 하도록 전달하며, 본 검수는 해당 브랜치를 변경하지 않았다.
