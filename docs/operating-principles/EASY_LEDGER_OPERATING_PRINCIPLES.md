# EASY LEDGER OPERATING PRINCIPLES

**핵심 원칙은 2026-09-17부터 유지**

## DAILY START HARD GATE

모든 에이전트는 EASY 작업 시작 전에 이 문서를 읽는다.

> **COLLECT → LEDGER SAVE → CLASSIFY**

이 순서를 바꾸지 않는다. 분석·검증·테스트·parser·dedupe·회계구조 개선 때문에 `LEDGER SAVE`를 미루지 않는다.

## 1. 실제 거래를 먼저 중앙 장부에 저장

실제 거래자료를 수집하면 즉시 운영 EASY 중앙 장부에 저장한다. 사업장·계정과목 등이 불확실해도 거래를 누락시키지 않고 `UNKNOWN`, `미분류`, `REVIEW_REQUIRED` 등 기존 허용 상태로 먼저 보존한다.

> **COLLECTED ≠ DONE / LEDGER SAVED = DONE**

PC나 에이전트가 바뀌기 전에 실제 거래가 중앙 운영 DB에 남아 있어야 한다.

## 2. 고정 작업 순서

잘못된 순서: `수집 → 장시간 분석 → parser 검증 → 분류 → handoff → 나중에 입력`

고정 순서: `수집 → 원본 보존 → 최소 중복 방지 → 장부 저장 → 자동분류 → 예외 검토`

파일 하나를 확보하면 모든 자료가 모일 때까지 기다리지 않고 그 자료부터 저장한다.

## 3. EasyShop 과거자료가 분류 기준

과거 EasyShop에서 실제 신고·장부에 사용한 분류, 계정과목, 사업장 귀속을 우선 기준으로 사용한다. AI가 새로운 논리로 과거 자료를 임의 재해석하지 않는다. 동일·유사 거래는 과거 패턴을 우선 적용하고 예외만 REVIEW한다.

## 4. 학원과 출판사 분리

일상 장부에서 `ACADEMY`와 `PUBLISHING`을 분리한다. 귀속이 불확실해도 거래는 저장하고 `UNKNOWN/REVIEW_REQUIRED`로 둔다. 종합소득세 신고 단계에서 필요한 사업소득을 합산한다. 현재 재무제표 주 대상은 학원이다.

## 5. 최종 목적

최우선 목표는 **다음 해 종합소득세 신고를 위한 정확하고 누락 없는 회계·증빙 데이터 구축**이다.

`실제 거래 누락 방지 → 사업장 귀속 → 수입/지출 → 계정과목 → 장부 검증 → 신고자료`

재무제표와 복식부기는 검증 수단이며 실제 거래 저장보다 앞서지 않는다.

## 6. 주요 수집원

신한은행, KB국민은행, 신한카드, KB카드, 여신금융협회 카드매출, 홈택스 현금영수증·세무자료. 어느 PC에서 수집했든 실제 거래를 로컬에만 장기간 두지 않는다.

## 7. 불확실한 거래

불확실성은 누락 사유가 아니다. `실거래 확인 → 장부 저장 → REVIEW_REQUIRED → 이후 검토` 순서다. REVIEW는 장부 미입력을 뜻하지 않는다.

## 8. 중복 회계 금지

- 카드 사용 = 비용 발생 + 카드미지급금.
- 카드대금 은행 출금 = 미지급금 상환. 비용 재계상 금지.
- 카드매출 = 매출.
- 카드사 정산입금 = 기존 카드매출 정산. 매출 재계상 금지.
- 대출금 입금 = 부채 증가. 매출 아님.
- 대출 원금 상환 = 부채 감소. 비용 아님.
- 이자 = 이자비용.

## 9. 원본 보존

`RAW 원본 → 장부거래 → 분류/수정 이력`을 추적 가능하게 보존한다. 재수집으로 기존 원본·장부를 임의 삭제/덮어쓰기하지 않는다. 최소 dedupe는 하되 dedupe 분석으로 신규 거래 전체 저장을 지연시키지 않는다.

## 10. 복식부기

최종적으로 차변=대변이어야 한다. 그러나 복식부기 구조 개선을 이유로 실제 거래 저장을 보류하지 않는다.

## 11. 완료 판정

`분석 완료`, `parser PASS`, `수집 완료`, `테스트 성공`만으로 완료를 선언하지 않는다.

반드시 보고: 수집 N / 장부 저장 N / 기존 중복 N / 미분류·REVIEW N / 분류 완료 N / 실패 N.

실제 신규 거래를 수집했는데 **장부 저장 0이면 핵심 작업 미완료**다.

## 12. 임의 변경 금지

사용자 명시 승인 없이 핵심 순서 변경, 분석을 저장보다 앞선 장기 단계로 확대, EasyShop 분류 임의 왜곡, 불확실 거래 누락, 로컬 분석만 남기고 종료, PC 이동 때 처음부터 재분석하지 않는다.

## 최종 원칙

> **실제 자료를 수집하면 즉시 EASY 중앙 장부에 저장하고, 과거 EasyShop 분류를 기준으로 자동분류하며, 판단할 수 없는 거래만 REVIEW로 남긴다. 분석이나 분류를 이유로 장부 저장을 미루지 않는다.**
