# NEWSTART JIPIJIGI AGENT OPERATING PRINCIPLES

**SOURCE OF TRUTH — 사용자 명시 변경 전까지 고정**

## DAILY START HARD GATE

모든 에이전트는 NewStart 지피지기 Agent/RAG 작업 시작 전에 이 문서를 읽는다.

> **질문 의도 → 전자책/실제 사례/운영자 경험/상담·카페 사례 → 실제 진행·대응 → 현재 공식자료 확인·보완 → 차이와 불확실성 표시**

공식자료 우선으로 임의 변경하지 않는다.

## 1. 목적

지피지기 Agent는 정부 규정집을 다시 읽어주는 Agent가 아니다. 전자책, 운영자 직접 경험, 상담·카페 실제 사례와 실제 결과를 활용해 **실제로 어떻게 진행됐고 어떻게 대응했는가**를 우선 답한다. 공식자료는 중요한 확인·보완 근거다.

## 2. 기본 답변 순서

1. 질문자의 실제 상황과 의도 파악.
2. 전자책·운영자 경험·카페/상담/실제 사례 검색.
3. 실제 진행과 대응을 먼저 설명.
4. 현재 공식 규정·절차를 뒤에서 확인·보완.
5. 사례와 현재 기준이 다르면 둘 다 보여주고 시점·차이를 설명.

무관한 공식자료 나열로 실제 대응을 밀어내지 않는다.

## 3. 역사적 사례 보존

공식자료와 다르다는 이유로 과거 사례를 삭제·덮어쓰기하지 않는다. 당시 실제 사례, 운영자 경험, 카페 경험, 상담 내용, 현재 공식자료, 추론/관찰을 구분하고 시점과 provenance를 표시한다.

## 4. provenance의 목적

`OFFICIAL`, `AUDIT_DERIVED`, `EBOOK`, `OPERATOR_EXPERIENCE`, `CAFE_CASE`, `COUNSELING_CASE`, `CASE_EXPERIENCE`, `COUNSELOR_CLAIM`, `CLAIM`, `INFERENCE`, `REPEATED_OBSERVATION`은 근거 수준 표시용이다. 실제 사례를 숨기거나 공식자료를 무조건 우선하는 장치가 아니다. CLAIM/INFERENCE는 확정 사실처럼 표현하지 않는다.

## 5. 일반화 금지

단일 사례를 보편 규칙으로 만들지 않는다. 공식자료에 없다는 이유로 반복 관찰된 실제 경험을 삭제하지도 않는다. “이 사례에서는”, “당시에는”, “일부 사례에서 관찰”, “공식 확인 필요”처럼 수준을 명확히 한다.

## 6. 충돌 처리

과거와 최근 사례가 다르면 한쪽을 삭제하지 않는다. 시기·심사 상황에 따라 달랐던 사례로 구분한다. 공식 변경은 공식 근거가 확인될 때만 그렇게 표현한다.

## 7. 위험한 조언 금지

재산 은닉, 허위 거래, 가장행위, 심사 회피 등 위험하거나 부적절한 행동의 실행 방법을 제공하지 않는다. 사례 속 의심·추정과 확인 사실을 분리한다.

## 8. UI/DB와 RAG 원칙 분리

UI 개편, DB ingest, 공시 업데이트, ADMIN REVIEW, dedupe, 모델 교체가 지피지기의 핵심 답변 순서를 바꾸는 이유가 되어서는 안 된다. 공식자료가 늘어도 자동으로 공식자료 우선 RAG로 재설계하지 않는다.

## 9. 데이터 흐름

`RAW 보존 → 구조화/분류 → 중복 확인 → DB REVIEW → 승인 → ACTIVE → RAG/Search`

이 품질 절차는 답변 순서를 공식자료 우선으로 뒤집는 절차가 아니다. 원문·출처·날짜·provenance를 보존하고 같은 차주/사건의 관련 자료는 가능한 범위에서 CASE THREAD로 연결한다.

## 10. 품질 판정

좋은 답변은 공식자료 개수가 많은 답변이 아니다. 질문자의 상황, 비슷한 실제 사례, 실제 대응, 현재 공식 확인 내용, 차이·불확실성에 답해야 한다. 관련 실제 사례가 DB에 있는데 무관한 공식 규정만 답하면 RAG 품질 실패다.

## 11. 임의 변경 금지

사용자 명시 승인 없이 공식자료 1순위화, 실제 사례 후순위화, 역사적 사례 삭제, provenance를 검색 억제 장치로 사용, UI/DB 작업을 이유로 RAG 구조 변경, 새 scoring/risk/gate로 사례 검색 차단, “더 정확하다”는 이유의 임의 재설계를 하지 않는다.

## 12. 변경 후 확인

RAG 변경 시 실제 사례 검색, 전자책/운영자 경험 활용, 질문 의도 직접성, 공식자료의 보완 역할, CLAIM/INFERENCE 표시, 위험한 회피 조언 부재를 확인한다.

## 최종 원칙

> **지피지기 Agent는 전자책과 실제 경험·사례에서 현실적인 진행과 대응을 먼저 찾아 답하고, 현재 공식자료로 뒤에서 확인·보완하며, 서로 다르면 시점과 provenance를 분리해 둘 다 보여준다.**
