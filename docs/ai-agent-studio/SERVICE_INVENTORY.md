## 별도 백엔드와 보존 경계

- AcademyCraft: 기존 EC2의 `127.0.0.1:8082`로 서명한 사용자·역할·소유 학원을 전달합니다. 외부 백엔드 소스와 DB는 이 저장소에 없어 실제 연결은 별도 환경에서 검증해야 합니다. `AcademyCraftGateway.allowedPath`에서 확인된 서비스 계약에만 어댑터를 제공합니다.
- Wiki: 기존 `127.0.0.1:8000`, `backend/main.py`·`workspace.py`, 사용자별 SQLite. 전용 MCP 요청은 기존 workspace만 `mode=ro`로 조회합니다. 공유 관리자 API key를 재사용하지 않습니다.
- Spring: 기존 RDS MySQL·JPA/JDBC. 제작 스튜디오와 OAuth는 추가 테이블만 사용하며 운영 DB에 적용하지 않았습니다.
- 파일: 기존 FileStorage의 local/S3 구현 재사용. 실제 storage_key는 MCP 응답에서 제거합니다. 신규 버킷·서버·임베딩 서비스가 없습니다.

## 읽기 도구에서 제외한 동작

쓰기 메서드, OAuth·로그인, 토큰/수집 인증 설정, 작업 할당(next-task), 새 workspace/working-copy 초기화, AI 생성·실시간 외부 API 호출, 파일 렌더/출력 생성, SSE 이벤트 구독은 실행하지 않습니다. 기존 다운로드가 조회 이력을 쓰는 Wiki 경로는 원본 view/preview로 대체합니다. 실제 기존 서비스 코드는 보존합니다.
