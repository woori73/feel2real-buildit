# EP01 원본 등록·복원 사용법

1. ADMIN이 프로젝트 제작 권한을 부여한다. 파일 탭에서 JSON 또는 ZIP 원본을 업로드한다. 먼저 원본으로 보관되며 업로드만으로 컷이나 승인본이 바뀌지 않는다.
2. 같은 파일 탭의 **EP01 68컷 일괄 등록 원본**에서 보관한 파일을 선택해 등록한다. 아래 형식으로 1~68컷을 정확히 한 번씩 넣는다. 실제 작품 내용은 사용자가 제공하며 빈 컷을 AI가 창작하지 않는다.
3. 등록 결과의 68개 미승인 버전을 검토한다. 승인 권한자가 각 자료의 **검수·사용자 승인**을 실행한 후에만 승인 포인터가 바뀐다. 새 원본을 추가 등록해도 기존 승인본과 이력은 보존한다.

```json
{
  "episode": 1,
  "cuts": [
    {
      "cutNumber": 1,
      "title": "사용자가 제공한 컷 제목",
      "content": "사용자가 제공한 본문·설정",
      "dialogue": "사용자가 제공한 대사",
      "direction": "사용자가 제공한 연출",
      "file": "assets/cut-01.png"
    }
  ]
}
```

위는 필드 설명을 위한 **불완전한 1컷 예시**다. 실제 등록에는 68개가 필요하다. `file`은 ZIP 안의 원본을 연결할 때만 쓰며 JSON 단독이면 생략한다. JSON/ZIP 원본 20 MiB 이하, manifest 2 MiB 이하, ZIP 항목 100개 이하·해제 합계 20 MiB 이하. ZIP 최상위에 `manifest.json`을 두고 `assets/cut-01.png` 같은 상대경로로 연결한다. `..`, 절대경로, 역슬래시, 중복 파일명은 거부한다. PDF/HTML/JSON/MD/ZIP/PNG/MP4만 연결할 수 있으며 서버가 형식과 내용을 검사한다. origin/승인 권한 필드를 manifest로 지정할 수 없다.

4. 이전 버전을 보려면 이력을 더 불러오거나 비교 탭에서 선택한다. 컷 보드는 이력 페이지와 별도로 현재 68개 head 전체를 읽는다. 수정 이력이 200개를 넘어도 컷이 빠지지 않는다.
5. 되돌릴 자료의 **이 버전으로 복원 초안 만들기**를 누른다. 선택한 내용·연결 파일을 참조하는 새 USER_EDIT·REVIEW 버전을 추가한다. 원본과 기존 revision은 바꾸지 않으며 기존 승인본도 유지한다. 화면에 `미승인`인 복원 초안을 검토해 별도로 승인한다. 다른 사용자가 먼저 새 버전을 저장했으면 409로 차단하므로 최신 상태에서 다시 선택한다.

파일·버전 삭제 또는 기존 byte 덮어쓰기는 제공하지 않는다. 실패 때의 파일/DB 분산 저장 한계와 합성 68컷 검증 범위는 [검수 반영 보고서](REVIEW_FIXES.md)를 참고한다. 실제 EP01 원본은 아직 제공되지 않아 등록하지 않았다.
