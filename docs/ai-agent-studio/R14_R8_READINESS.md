# 기존 r14 ~ r8 산출물 업로드 가능 여부

**결론: 형식·라벨 규칙상 수용 가능 / 실물을 받지 못해 실제 파일로는 검증하지 못함.** 임의 데이터를 만들어 등록하지 않았다.

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| 버전 라벨 `r14`, `r13` … `r8`, `r7`, `r7.final-2` | 허용 (`[a-zA-Z0-9._-]{1,40}`) | `StudioServiceTest.givenVersionLabelsR14ToR8_whenValidated_thenAllAccepted` |
| 문서 md / html / json / pdf | 업로드·열람 가능. html은 텍스트로만 표시하고 실행하지 않음, json은 문법까지 검사 | `StudioServiceTest` (json 정상·깨짐), 기존 브라우저 QA |
| 묶음 zip | 보관·목록 열람 가능 | 기존 업로드 경로 |
| 이미지·영상 png / mp4 | 가능. jpg·webp·mov 등은 **미지원**(변환 필요) | `StudioService.upload` 확장자 허용목록 |
| 파일당 100 MiB | 초과 시 413. 서버 multipart 설정은 prd 200MB이나 프록시/nginx 한도는 별도 확인 필요 | 코드, 운영 구성 미확인 |
| 같은 내용 재업로드 | SHA-256 중복이면 기존 파일을 재사용하고 기존 파일명을 응답에 포함 | 통합 테스트 |
| **컷 단위 자동 등록** | `manifest.json`(또는 JSON 단독) 형식에 **EP01 1~68컷이 빠짐없이** 있어야 함. ZIP은 항목 100개·해제 합계 20 MiB 이하. [사용법](BULK_AND_RESTORE.md) | `StudioBulkImport.importEp01` |
| 기존 산출물이 위 형식이 아닌 경우 | 파일 단위 보관·열람만 가능. 컷 연결은 매니페스트로 변환 필요 | 설계 |
| 20 MiB를 넘는 ZIP | 보관은 되지만 **일괄 등록은 불가**(413) — 이미지가 많은 r14~r8 ZIP이면 분할 필요 | `EXPANDED_LIMIT` |

미확인: 실제 r14~r8 파일의 크기·내부 구조·문자 인코딩(UTF-8이 아니면 md/html/json 업로드 거절), 컷 수가 정확히 68인지.
실물을 받으면 (1) 파일 탭에 업로드해 SHA-256을 기록하고 (2) 일괄 등록 전에 컷 수·크기를 확인하세요. 등록 결과는 모두 미승인이며 승인 권한자의 개별 승인 전까지 정본이 바뀌지 않습니다.
