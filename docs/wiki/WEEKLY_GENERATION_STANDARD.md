# BUILD IT WIKI WEEKLY 문제지 제작 기준

> Canonical source for ChatGPT WIKI WEEKLY production.
> 사용자가 ChatGPT 채팅에서 WIKI WEEKLY 제작을 요청하면 이 문서와 같은 디렉터리의 `WEEKLY_REFERENCE.html`을 먼저 읽고, 그 다음 이번 HALF/원문을 읽어 제작한다.

## 기본 체제
- 고3 수능 영어형 WIKI WEEKLY는 14문항을 기본으로 한다.
- A4 세로, 2단 편집.
- 폰트·행간·페이지 여백·단 간격은 고정한다.
- 기본 본문은 9.8pt, line-height 1.39, 페이지 padding 9mm 10mm 8mm, 단 간격 8mm를 기준으로 한다.
- 페이지당 문항 수를 기계적으로 고정하지 않는다. 문항 전체 높이와 페이지 밀도를 함께 보고 배치한다.
- 문항 수를 맞추기 위해 폰트나 기본 페이지 여백을 줄이지 않는다.
- 문항번호 + 발문 + 지문/제시문 + 각주 + 선택지는 하나의 조판 단위로 취급하며 부자연스럽게 분리하지 않는다.
- 최종 판단은 단순 문항 수가 아니라 **페이지별 시각적 밀도와 문항 사이 호흡이 균형적인가**를 기준으로 한다.

## 최종 샘플 기준
- `docs/wiki/WEEKLY_REFERENCE.html`은 WIKI WEEKLY 01 최종 문제지 자체이며, 추상 예시가 아니라 실제 조판 샘플이다.
- 새 WIKI WEEKLY 제작 시 이 샘플의 문항 간 여백, 지문-선택지 간격, 페이지 밀도, 2단 사용 방식을 우선 참고한다.
- 한 페이지는 지나치게 빽빽하고 다른 페이지는 큰 공백이 남는 식의 임의 배치를 피한다.
- 공간이 남는 경우 해당 페이지 안에서 문항 사이 여백을 자연스럽게 조절할 수 있으나, 폰트·행간·페이지 기본 여백을 임의 축소하지 않는다.
- 짧은 문항과 긴 문항의 실제 높이를 고려하여 좌우 단의 시각적 무게를 맞춘다.

## 문항 순서
1. 수능 21번형 — 밑줄 친 표현의 함축 의미
2. 제목
3. 수능 29번형 — 어법
4. 수능 30번형 — 문맥상 어휘
5~8. 빈칸 추론
9~10. 글의 순서
11~12. 문장 삽입
13~14. 공통지문 2문항

2번은 제목 문제를 기본으로 한다.

## 유형별 표시
- 함축 의미: 실제 영어 표현에 얇고 연한 단일 밑줄.
- 어법: 번호가 아니라 실제 판단 대상 영어 단어/표현에 단일 밑줄.
- 어휘: 번호가 아니라 실제 판단 대상 영어 단어에 단일 밑줄.
- 빈칸: 원문을 확인해 실제 생략 위치에 빈칸을 둔다. 블록 경계만 보고 추측하지 않는다.
- 순서/삽입: 제시문은 일반 지문과 같은 폰트·크기·굵기. 볼드 금지.
- 삽입 위치는 `( ① )` 형식.
- `(a)~(e)` 판단형은 실제 대상 단어에 밑줄을 긋는다.
- 짧은 선택지는 공간이 충분할 때 가로 간격을 충분히 둔다.

## 선택지 압축 규칙
- 9~10번처럼 선택지 자체가 짧은 순서 문제는 필요하면 **2열 선택지**를 사용한다.
- 예: `① ...   ② ...` / `③ ...   ④ ...` / `⑤ ...`처럼 한 행에 두 선택지를 두어 세로 공간을 절약할 수 있다.
- 이 압축은 본문 폰트나 지문 행간을 줄이는 대신 선택지의 불필요한 세로 점유를 줄이기 위한 것이다.
- 압축 후 확보된 공간은 9~12번처럼 긴 순서·삽입 문항을 같은 페이지에 균형 있게 배치하는 데 활용한다.

## 13~14 공통지문 규칙
- 반드시 `[13~14] 다음 지문을 읽고, 물음에 답하시오.`로 공통 세트를 시작한다.
- 공통지문은 **한 번만** 출력한다.
- 최종 샘플처럼 공통지문을 먼저 제시한 뒤 13번 발문과 선택지를 배치한다.
- 따라서 13번 제목 발문은 지문 뒤에 있을 때 `13. 위 글의 제목으로 가장 적절한 것은?`으로 쓴다.
- 14번은 같은 공통지문을 반복하지 않고 발문과 선택지만 이어서 배치한다.
- 14번 발문에 `13번과 같은 지문` 같은 불필요한 교차 참조를 넣지 않는다.
- 공통지문 아래 각주/단어가 있으면 **오른쪽 정렬**한다.
- 공통지문과 13번 선택지 사이에는 충분한 시각적 공간을 확보한다.

## Typography / Pagination
- 원칙: **Fixed Typography + Fixed Margin + Balanced Flexible Pagination**.
- 영어 지문은 양쪽 정렬.
- 공간이 남는다고 전체 자간을 임의 확대하지 않는다.
- 다음 문항 전체가 왼쪽 단에 들어가지 않으면 오른쪽 단 상단으로 이동한다.
- 오른쪽 단에도 들어가지 않으면 다음 페이지 왼쪽 단으로 이동한다.
- 지문과 선택지가 서로 다른 단/페이지로 부자연스럽게 분리되지 않게 한다.
- 단순히 `페이지당 3문항/4문항`을 먼저 정한 뒤 끼워 넣지 않는다.
- 각 페이지 완성 후 **좌우 단 하단 위치와 문항 사이 여백을 육안으로 비교**하여 밀도 차이가 과도하지 않은지 검수한다.
- 여백이 큰 페이지에서는 문항 사이 간격을 늘려 읽기 호흡을 확보할 수 있다. WIKI WEEKLY 01의 3번과 4번 사이 조정이 대표 예시다.
- 반대로 긴 문항 페이지에서는 짧은 선택지의 2열 배치처럼 내용 손실 없는 압축을 먼저 사용한다.

## 문항 사이 가독성
- 문항끼리 붙어 보이지 않도록 Question Card 사이에 명확한 세로 간격을 둔다.
- 발문 → 지문 → 선택지의 단계가 눈에 구분되도록 각각 일정한 간격을 유지한다.
- 모든 페이지에 동일한 수치만 기계적으로 적용하는 것이 목적이 아니라, 샘플과 같은 **일관된 시각적 리듬**을 만드는 것이 목적이다.
- 특정 페이지에 여백이 많이 남는다면 그 페이지의 문항 사이 공간을 합리적으로 넓혀 전체 페이지의 밀도를 맞춘다.

## 밑줄
- 얇고 연한 단일선만 사용한다(약 0.65~0.7px 수준).
- `text-decoration`과 `border-bottom` 등을 중복 적용해 이중 밑줄을 만들지 않는다.
- 번호보다 실제 판단 대상 표현을 강조한다.

## 각주
- 각주는 본문보다 작게 표시한다.
- 지문 아래 각주 단어는 오른쪽 정렬을 기본으로 한다.
- 각주 때문에 지문과 선택지가 과도하게 붙지 않도록 최소 간격을 유지한다.

## 금지
- 고정 3등분/4등분 Grid에 문항을 강제로 넣지 않는다.
- 페이지를 맞추기 위한 본문 폰트 축소·페이지 기본 여백 축소 금지.
- 제시문 임의 볼드 금지.
- 공통지문 반복 금지.
- OCR 잔여 문자 및 내부 메타데이터 출력 금지.
- 페이지별 밀도를 확인하지 않은 채 문항 번호만으로 페이지를 임의 분할하지 않는다.

## ChatGPT 제작 절차
WIKI WEEKLY 제작 요청을 받으면 GitHub 연결을 통해 아래 순서로 실제 파일을 조회한다.
1. `docs/wiki/WEEKLY_GENERATION_STANDARD.md` — 제작 규칙
2. `docs/wiki/WEEKLY_REFERENCE.html` — WIKI WEEKLY 01 최종 시각 레퍼런스
3. 사용자가 지정하거나 첨부한 이번 HALF/원문 — 실제 출제 내용

대화 기억만으로 포맷을 재구성하지 않는다. 1·2번 파일을 조회할 수 없는 경우에는 이를 사용자에게 알리고 기준을 추측하여 제작하지 않는다. 원문 내용과 제작 규칙을 임의로 섞거나 원문 내용을 추측하지 않는다.

## 최종 검수 체크
1. A4 세로 / 2단 / 고정 본문 크기와 여백인가?
2. 문항 사이가 지나치게 붙어 있지 않은가?
3. 페이지별 밀도가 크게 들쭉날쭉하지 않은가?
4. 짧은 선택지는 필요 시 2열로 압축했는가?
5. 순서/삽입 제시문을 임의 볼드 처리하지 않았는가?
6. 각주가 지문 아래 오른쪽에 정렬되어 있는가?
7. 13~14 공통지문을 한 번만 제시했는가?
8. 13번 발문이 공통지문 뒤에 위치하며 `위 글의 제목...` 형식인가?
9. 14번에 공통지문 교차 참조 문구가 없는가?
10. 인쇄 미리보기에서 좌우 단과 페이지 하단의 시각적 균형을 확인했는가?

## 유지 원칙
- 이 MD와 `WEEKLY_REFERENCE.html` 두 파일을 WIKI WEEKLY 제작의 공식 기준으로 관리한다.
- 기준이 변경되면 이 두 파일을 함께 갱신한다.
- Wiki 화면의 DOM/sessionStorage 자동 주입은 공식 기준이 아니며 필요하지 않다.
- 이 저장소 문서는 ChatGPT가 GitHub 연결을 통해 명시적으로 조회하는 canonical reference다. 저장소에 있다는 사실만으로 모든 새 채팅에 자동 첨부되는 것은 아니므로, WIKI WEEKLY 제작 작업에서는 반드시 위 조회 절차를 수행한다.
