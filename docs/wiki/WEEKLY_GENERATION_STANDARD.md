# BUILD IT WEEKLY 문제지 제작 기준

> Canonical source for ChatGPT WEEKLY production.
> 사용자가 ChatGPT 채팅에서 WEEKLY 제작을 요청하면 이 문서와 같은 디렉터리의 `WEEKLY_REFERENCE.html`을 먼저 읽고, 그 다음 이번 HALF/원문을 읽어 제작한다.

## 기본 체제
- 고3 수능 영어형 WEEKLY는 14문항을 기본으로 한다.
- A4 세로, 2단 편집.
- 폰트·행간·페이지 여백·단 간격은 고정한다.
- 페이지당 문항 수는 고정하지 않고 문항 전체 높이에 따라 보통 3~4문항을 유연하게 배치한다.
- 문항 수를 맞추기 위해 폰트나 여백을 줄이지 않는다.
- 문항번호 + 발문 + 지문/제시문 + 각주 + 선택지는 하나의 분리 불가능한 조판 단위로 취급한다.

## 문항 순서
1. 수능 21번형 — 밑줄 친 표현의 함축 의미
2. 제목
3. 수능 29번형 — 어법
4. 수능 30번형 — 문맥상 어휘
5~8. 빈칸 추론
9~10. 글의 순서
11~12. 문장 삽입
13~14. 공통지문 2문항

2번은 제목 문제를 기본으로 한다.

## 유형별 표시
- 함축 의미: 실제 영어 표현에 얇고 연한 단일 밑줄.
- 어법: 번호가 아니라 실제 판단 대상 영어 단어/표현에 단일 밑줄.
- 어휘: 번호가 아니라 실제 판단 대상 영어 단어에 단일 밑줄.
- 빈칸: 원문을 확인해 실제 생략 위치에 빈칸을 둔다. 블록 경계만 보고 추측하지 않는다.
- 순서/삽입: 제시문은 일반 지문과 같은 폰트·크기·굵기. 볼드 금지.
- 삽입 위치는 `( ① )` 형식.
- 공통지문은 한 번만 출력하고 그 뒤에 13번, 14번을 이어 배치한다.
- `(a)~(e)` 판단형은 실제 대상 단어에 밑줄을 긋는다.
- 짧은 선택지는 공간이 충분할 때 가로 간격을 충분히 둔다.

## Typography / Pagination
- Fixed Typography + Fixed Margin + Flexible Pagination.
- 영어 지문은 양쪽 정렬.
- 공간이 남는다고 전체 자간을 임의 확대하지 않는다.
- 다음 문항 전체가 왼쪽 단에 들어가지 않으면 오른쪽 단 상단으로 이동한다.
- 오른쪽 단에도 들어가지 않으면 다음 페이지 왼쪽 단으로 이동한다.
- 지문과 선택지가 서로 다른 단/페이지로 부자연스럽게 분리되지 않게 한다.

## 밑줄
- 얇고 연한 단일선만 사용한다(약 0.65~0.7px 수준).
- `text-decoration`과 `border-bottom` 등을 중복 적용해 이중 밑줄을 만들지 않는다.
- 번호보다 실제 판단 대상 표현을 강조한다.

## 금지
- 고정 3등분/4등분 Grid에 문항을 강제로 넣지 않는다.
- 페이지를 맞추기 위한 폰트 축소·여백 축소 금지.
- 제시문 임의 볼드 금지.
- 공통지문 반복 금지.
- OCR 잔여 문자 및 내부 메타데이터 출력 금지.

## ChatGPT 제작 절차
WEEKLY 제작 요청을 받으면 GitHub 연결을 통해 아래 순서로 실제 파일을 조회한다.
1. `docs/wiki/WEEKLY_GENERATION_STANDARD.md` — 제작 규칙
2. `docs/wiki/WEEKLY_REFERENCE.html` — 확정 시각 레퍼런스
3. 사용자가 지정하거나 첨부한 이번 HALF/원문 — 실제 출제 내용

대화 기억만으로 포맷을 재구성하지 않는다. 1·2번 파일을 조회할 수 없는 경우에는 이를 사용자에게 알리고 기준을 추측하여 제작하지 않는다. 원문 내용과 제작 규칙을 임의로 섞거나 원문 내용을 추측하지 않는다.

## 유지 원칙
- 이 MD와 `WEEKLY_REFERENCE.html` 두 파일을 WEEKLY 제작의 공식 기준으로 관리한다.
- 기준이 변경되면 이 두 파일을 함께 갱신한다.
- Wiki 화면의 DOM/sessionStorage 자동 주입은 공식 기준이 아니며 필요하지 않다.
