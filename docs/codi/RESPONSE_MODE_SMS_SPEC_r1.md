# 코디 응답 모드 — 부재중 AI 문자 응대 (경량) 빌드 스펙 r1

2026-11-28 KST · 차원연산4(기획/검수) · 목표: **음성·텔레포니 없이**, 수업 중 못 받은 전화를 코디가 **문자 + 링크 응대**로 챙긴다.

## 0. 범위 (경량 1단계)
- **원장 '응답 모드' ON** 상태에서 **부재중 전화**가 나면 → 코디가 **자동 문자**로 안내하고, **링크 안 웹 챗**에서 용건·상담예약을 받아 **F2R에 기록** + 원장에게 요약.
- **안 하는 것**: 음성 통화 응대·클라우드 텔레포니·착신전환·녹취 (= (b)/음성 응답모드는 별도 대형 과제).

## 1. 흐름
1. 원장 앱: **"응답 모드" 토글**(수업 중 ON).
2. ON 중 **부재중 발생** → 앱이 발신번호 감지 → 우리 서버에 통지(번호·시각).
3. 서버: 발신번호로 **자동 문자** — *"○○학원입니다. 수업 중이라 전화를 못 받았어요. 문의·상담 예약 👉 [코디 링크]"*
4. 링크 = **코디 웹 응대 페이지**(우리 서버): AI가 용건 듣고 상담시간·FAQ 안내 + **상담/콜백 접수**.
5. 접수 → **F2R 기록**(기존 상담/parent-notice 경로 재사용) + 원장에게 **"부재중·요청 요약"** 알림.
6. **응답 모드 OFF** → 문자 안 나감.

## 2. 아키텍처
- **앱(원장 폰)**: 부재중 감지 → 서버 통지. (문자 발송은 앱이 직접 안 함 — 아래 주의.)
- **서버**: ① SMS 제공자로 문자 발송(발신번호=학원 사전등록 번호) ② 코디 웹 응대 페이지(AI 챗/예약) ③ F2R 기록 ④ 원장 요약 알림.
- **엔진**: 응대 챗은 자유대화 엔진 또는 Claude(학원 맥락·FAQ). 멀티 프로바이더 어댑터 재사용.

## 3. 현실적 의존성·주의 (솔직)
- **문자 발송**: Android **SEND_SMS 앱 직접 발송은 Google Play 정책상 제약**(기본 SMS 앱 아니면 거의 승인 불가). → **서버측 SMS 발송 제공자**(문자 API) + **발신번호 사전등록(학원 번호)**이 현실적. (이게 "경량"의 유일한 인프라 — 통신사 텔레포니/음성과는 다름, 가벼움.)
- **부재중 감지**: `READ_PHONE_STATE`/`READ_CALL_LOG` 또는 `CallScreeningService` 필요 → **Play 민감권한 심사** 대상(용도 설명 필요). 발신번호 취득.
- **카카오 알림톡**: 비즈채널·템플릿 승인 필요 → **2단계**(먼저 SMS).
- **개인정보**: 발신번호는 **문자 발송·응대에만** 사용, 저장 최소. 응대 문자는 **광고 아님(안내)** → 스팸 규제 가벼움.

## 4. 검수 기준 (연산4)
1. **응답 모드 ON**에서 부재중 1건 → 문자 **정확히 1회**(같은 번호 단시간 중복 발송 차단=멱등).
2. **응답 모드 OFF** → 문자 **미발송**.
3. 링크 열면 **코디가 응대·상담/콜백 접수**.
4. 접수 → **F2R 기록** + 원장 요약 1건.
5. 발송 실패·접수 실패 시 **중복/유실 없이** 상태 관리.
6. 개인정보: 발신번호 저장·사용 최소(로그에 원문 과다 저장 금지).

## 5. 단계
- **M-light-1(지금)**: 토글 + 부재중 감지 + 서버 SMS + 링크 웹 챗/예약 + F2R.
- **확장**: 카카오 알림톡, 양방향, 음성 응답모드(별도 대형).
