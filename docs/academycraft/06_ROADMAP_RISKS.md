# 06. P1~P3 구현 순서와 위험 분석

> 모든 구현 단계는 **별도 승인**을 받고, 단계마다 별도 PR(병합·운영 배포는 다시 별도 승인)로 진행한다. 이 문서는 순서와 선행조건만 정한다.

## 1. 선행조건과 순서

원칙: **안전한 쓰기 승인(1단계)이 끝나기 전에는 새 쓰기 도구를 만들지 않는다.**

| 단계 | 내용 | 저장소 | 선행조건 | 완료 기준(검증) |
|------|------|--------|----------|-----------------|
| P1-a | 승인 프로토콜: 계획 테이블·`AgentPlanService`·`AgentTool.preview`·`writeApproved` 외부 입력 거부 | AcademyCraft | 사용자 승인, DB 마이그레이션 로컬 리허설 | 04번 §11의 단위·통합·보안 테스트 통과, 기존 `AgentExecutorTest` 등 회귀 통과 |
| P1-b | 게이트웨이 정확 경로 5개 허용(양쪽 동시) | BuildIt + AcademyCraft | P1-a 병합·배포 | 02번 §5.3 검증 유지 확인, 허용 안 된 경로 403 회귀, STUDENT 403 |
| P1-c | AI 오케스트레이터(읽기 도구만): Muse 호출, 제안 파싱, 서버 검증, 실패 시 `CommandParser` 대체 | BuildIt | P1-b | 읽기 도구 5개 실제 응답, Muse 실패·시간 초과 대체 경로, 도구 결과 모델 미재전송 |
| P1-d | AI 비서 홈 화면(390px/1440px), 읽기 카드 | BuildIt | P1-c | 실화면 캡처, 접근성(reduced-motion, 대비), 수동 화면 이동 |
| P1-e | 기존 쓰기 3개 도구를 승인 카드로 연결 | BuildIt(+AcademyCraft) | P1-a~d | 승인 전 미변경 확인, 만료·취소·중복·무효화 동작 |
| P2 | 대시보드 레이아웃 저장·복원(사용자·학원별) | BuildIt 또는 AcademyCraft | P1-d | 저장 위치 결정(아래), 재접속 복원, 학원 격리 |
| P3 | 쓰기 도구 확장: 반 생성 → 출결 입력 → 상담 기록 → 반 종료(마지막) | AcademyCraft | **P1-a·e 운영 안정화** | 도구별 정책표(03번) 확정 후 하나씩, 도구마다 승인·감사 테스트 |

배포 순서 주의(P1-b): AcademyCraft를 먼저 배포하고(새 경로를 허용하지만 BuildIt이 아직 호출하지 않음), 그다음 BuildIt을 배포한다. 반대 순서이면 BuildIt이 허용하는 경로가 업스트림에서 403이 된다.

## 2. P2 저장 위치 후보 [결정 필요]
| 안 | 장점 | 단점 |
|----|------|------|
| BuildIt DB(사용자별 설정 JSON) | 로그인 문맥·사용자 단위 저장이 쉽다 | 학원 단위 공용 설정은 AcademyCraft와 이중 관리 |
| AcademyCraft DB(학원·회원별) | 학원 격리가 같은 곳에서 보증 | AcademyCraft 마이그레이션 추가, 연결(binding) 회원이 없는 경우 처리 필요 |
권장은 설계 단계에서 확정하되, **설정은 위젯 ID와 순서만 저장**하고 코드·HTML·스크립트는 저장하지 않는다(모델이 만든 화면을 그대로 실행하지 않는다).

## 4. 결정이 필요한 항목
1. 강사(TUTOR)의 쓰기 도구 허용 범위 — 03번 §1 (권장: 초기에는 원장 전용으로 시작).
2. 계획 만료 시간(10분 제안, 5~15분 범위).
3. AI 비서 홈의 위치: BuildIt 템플릿(권장) vs AcademyCraft 화면.
4. P2 설정 저장 위치(BuildIt vs AcademyCraft).
5. `writeApproved` 제거 시 기존 AcademyCraft 자체 로그인 사용자의 호환 기간.
6. 구현 단계 PR 분할 단위(위 P1-a~e를 각각 별도 PR로 권장).

## 5. 구현 단계에서 지킬 저장소 규칙 (BuildIt 쪽 변경 시)
- 스키마·엔드포인트 변경은 `API.md`·`FLOWS.md`·`DOMAIN.md`를 코드와 **동시에** 수정한다(CLAUDE.md).
- 함수 생성 시 단위 테스트를 given/when/then 구조로 함께 만든다. 새 테스트는 `build-check.yml`의 `--tests` 목록에 등록한다.
- 병합·운영 배포·운영 DB 변경은 단계마다 별도 승인.
- 운영 검증(390px·1440px, ADMIN·TUTOR 로그인, 학원 격리)은 배포 후 별도로 수행하며, 현재 **[미검증]** 이다.
