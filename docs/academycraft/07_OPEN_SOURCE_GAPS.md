# 07. 오픈소스 후보 미확보 항목 목록

## 1. 현재 상태
지시서가 말한 **"오늘 오전 뮤즈가 확보한 오픈소스 목록·자료"는 이 세션에서 찾지 못했다.** 확인한 곳: 이 세션의 대화 기록, `/root/.claude/uploads`의 첨부 파일, 로컬 `buildit2` 저장소, 이 저장소의 `docs/`.

찾은 것(모두 다른 주제이며 이번 선정에는 쓰지 않았다):
| 자료 | 위치 | 주제 | 비고 |
|------|------|------|------|
| 템플릿 후보 30종 | `buildit2/references/candidates-30.md`(2026-10-12) | 학원 홈페이지 템플릿 | 채팅·도구 호출·워크플로 자료 아님 |
| Shopify UI 연구 ZIP | `/root/.claude/uploads/…/shopify-ui-study-2026-10-13.zip` | UI 연구 | 같은 이유로 제외 |
| 자동수집 오픈소스 조사 | `docs/easy/auto-collection/05_OPEN_SOURCE_RESEARCH.md` | 이지장부 자동수집 | AcademyCraft AI 비서와 무관 |

**설치·도입한 것은 없다.** 외부 오픈소스의 선정·설치·도입은 자료 확인 후에만 진행한다.

## 2. 필요한 영역과 현재 확보 상태

| 영역 | 필요한 이유 | 확보 상태 | 목록을 받으면 확인할 것 |
|------|-------------|-----------|--------------------------|
| 채팅 UI | AI 입력·응답 카드 | **미확보** | 순수 JS/웹 컴포넌트 여부(BuildIt은 Thymeleaf SSR), 접근성 |
| 동적 컴포넌트(업무 카드) | 응답을 카드·표·단계 화면으로 표현 | **미확보** | 서버가 준 **데이터**만으로 렌더링(모델이 만든 HTML 실행 금지) |
| 파일 분석(PDF·엑셀·문서) | P4 자료 업로드 구조화 | **미확보** | 서버 측 파싱 라이브러리의 라이선스·취약점 이력, 파일 크기 제한 |
| AI 도구 호출 | 도구 선택·파라미터 추출 | **미확보(대안 있음)** | 이미 `AgentTool` 구조가 있어 **라이브러리 없이** 가능할 수 있음. 도입 이유가 있어야 함 |
| 워크플로 관리 | 계획·승인 상태 전이 | **미확보(대안 있음)** | 04번의 단순 상태 전이(DB+CAS)로 충분할 가능성. 외부 엔진은 과할 수 있음 |
| 모바일 애니메이션 | 진행 상태 표시 | **미확보** | CSS만으로 가능한지, `prefers-reduced-motion` 지원 |

## 3. 선정 기준 (목록 확보 후 적용)
1. **라이선스**: 상용 서비스에 쓸 수 있는지(MIT·Apache-2.0 등), 고지 의무, 하위 의존성 라이선스.
2. **유지보수**: 최근 릴리스·이슈 대응, 알려진 보안 취약점.
3. **기존 코드와 호환**: Spring Boot 4 + Thymeleaf SSR + 순수 JS, 번들 크기, 별도 빌드 체인 필요 여부.
4. **필요성**: 기존 구조(`AgentTool`, `MetaMuseSparkLlmTransport`, 기존 CSS)로 해결되지 않을 때만 도입.
5. **보안·개인정보**: 외부 서비스로 데이터를 보내지 않는지, 클라이언트에서 임의 코드를 실행하지 않는지.
6. **접근성**: 키보드·스크린리더·reduced-motion 지원.

## 4. 요청 사항
- 오전 목록(링크·라이선스·메모) 또는 첨부 ZIP을 다시 전달해 주세요. 받으면 위 기준표를 채운 검토표를 이 폴더에 추가하겠습니다.
- 그 전까지 설계(01~06)는 외부 오픈소스에 **의존하지 않는** 구조로 작성되어 있다.
