# 03. 도구별 권한·승인·감사 정책표

## 0. 전제
- 게이트웨이 통과 후 에이전트 사용자는 **ADMIN 또는 TUTOR**뿐이다. STUDENT 연결은 에이전트 경로가 허용되지 않는다(`BuildItGatewayFilter.allowed`에서 학생은 본인 조회만). **[실제 코드]**
- AcademyCraft 내부 역할은 연결된 **회원 레코드**에서 정해진다(`ACADEMY_OWNER` 또는 `TEACHER`). TUTOR가 `ACADEMY_OWNER`로 해석되는 것은 실제 BuildIt 소유 학원일 때만이다. **[실제 코드]** → 아래 표의 "원장 / 강사"는 이 내부 역할이다.
- 학원 ID는 모든 도구가 `ctx.academyId()`(인증 컨텍스트)에서 가져온다. 입력의 학원 ID는 받지 않는다.
- 감사 행위 종류는 현재 `AGENT_TOOL_EXECUTED` 하나뿐이다. 계획 생애주기를 구분하려면 행위 종류 추가가 필요하다(04번).

| `getHomeworkIncomplete` | 읽기 | 허용 | 허용 | 불필요 | 실행 기록 | |
| `analyzeGradeChanges` | 읽기 | 허용 | **[결정 필요]** | 불필요 | 실행 기록 | 강사에게 학원 전체 성적 분석을 허용할지 |

[결정 필요] 강사 권한: (가) 현재 코드 유지(강사도 쓰기 허용, 승인 필수), (나) 쓰기 도구는 원장 전용, (다) 도구별 개별 지정. 권장은 (다)를 기본으로 하되 초기에는 **(나)** 로 시작해 필요한 도구만 강사에게 여는 방식이다. 결정 전에는 현재 동작을 바꾸지 않는다.

| 도구(안) | 읽기/쓰기 | 기존 API | 원장 | 강사 | 위험도 | 메모 |

만들지 않는 것: 삭제, 비활성화(`students/inactive`, 회원 비활성), 비밀번호·인증키 갱신(`renew-key`, `credentials`), 권한 변경(`users/{id}/role`), 외부 메시지 발송(`messages/send`), CSV 가져오기·내보내기(대량 쓰기 → 별도 검토), 회원·학원 설정 변경.

## 3. 공통 감사 항목 (모든 계획 이벤트)
| 항목 | 내용 |
|------|------|
| 누가 | 주체 ID·이름, BuildIt 사용자 ID, 역할(계획 시점과 승인 시점) |
| 어느 학원 | 학원 ID |
| 무엇을 | 도구 이름, 입력의 **해시와 요약**(전체 입력이 아니라 개인정보 최소화) |
| 어떻게 | 계획 ID, 이벤트 종류(생성/승인/거부/만료/실행/실패/취소/무효화), 결과 코드 |
| 언제 | 서버 시각 |
| 출처 | `ASSISTANT`(Muse 제안) / `RULE`(CommandParser) / `MANUAL` |

## 4. 입력 검증 공통 규칙
- 도구 이름은 `AgentDispatcher`에 등록된 것만(대소문자 정확 일치).
- 스키마에 없는 키는 거부. 숫자 ID는 양의 정수, 문자열은 길이 상한, 날짜는 ISO 형식.
- 한 계획의 대상 건수 상한(초기 50). 초과 시 분할 요청 안내.
- 학생·반 ID는 서버가 **해당 학원 소속인지** 다시 조회해 확인한다(모델이 준 ID를 신뢰하지 않음).
