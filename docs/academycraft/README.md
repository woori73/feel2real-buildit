## 한눈에 보는 결론
1. AcademyCraft에는 이미 **도구 8개 + 실행 엔진 + 쓰기 승인 플래그 + 감사 로그**가 있다. 새로 만들지 않고 확장한다.
2. 가장 큰 결함은 **승인이 클라이언트가 보내는 불리언(`writeApproved`)** 이라는 점이다. 서버가 보관한 실행 계획 ID를 승인하는 2단계 구조가 쓰기 기능 확장의 선행조건이다.
3. 게이트웨이는 **BuildIt 쪽과 AcademyCraft 쪽 두 곳의 허용 목록**에 모두 `/agent`가 없다. 정확 경로만 양쪽에 동시에 추가한다. 경로 허용은 권한 검증을 대체하지 않는다.
4. 구현은 승인 프로토콜 → 게이트웨이 → 읽기 전용 AI 비서 → 쓰기 도구 순으로 진행한다.
