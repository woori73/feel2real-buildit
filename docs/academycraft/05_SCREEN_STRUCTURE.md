# 05. 모바일·PC 화면 구조 (설계)

> **구현 전 설계다.** 아래 화면은 아직 존재하지 않는다. 구현되지 않은 기능을 작동하는 것처럼 보이게 하지 않는다: 도구가 없는 업무 카드는 "AI로 처리"가 아니라 **"직접 처리"(수동 화면 링크)** 로만 표시한다.
> 기존 화면 사실 **[실제 코드]**: 현재 `/dashboard`의 AcademyCraft 항목은 `/academycraft`로 이동하고, `/academycraft`는 `OPS-02-dashboard.html`로 리다이렉트한다. AcademyCraft 화면은 별도 정적 HTML(`frontend/screens/*.html`)이며 BuildIt 게이트웨이가 중계한다. AI 채팅 화면 `CHAT-01-ai-chat.html`이 이미 있으나 게이트웨이 허용 목록에는 없다.

## 1. 원칙
1. 첫 화면 중심은 **AI 입력창**. 복잡한 사이드바 대신 업무 카드.
2. 항상 보이는 **"직접 관리"** 진입(학생·반·출결·상담·공지 수동 화면). AI가 실패해도 업무가 멈추지 않는다.
3. 변경은 **승인 카드**를 거친다. 승인 전에는 아무것도 바뀌지 않았음을 문구로 명시.
4. 다음 행동을 화면마다 하나의 주 버튼으로 안내.

## 2. 모바일 390px (우선)

### 2.1 AI 비서 홈
```
┌────────────────────────────┐ 390
│ 학원 현황 · 오늘            │  ← 헤더(상태 한 줄)
├────────────────────────────┤
│ 무엇을 도와드릴까요?        │  ← 본문 18px
│ ┌────────────────────────┐ │
│ │ 예: 오늘 결석한 학생     │ │  ← 입력창 (높이 56px, 16px+)
│ └────────────────────────┘ │
│ [ 보내기 ]                  │  ← 주 버튼 56px
│  최근 요청 칩: 결석 학생 · 숙제 미제출 │
├────────────────────────────┤
│ ▢ 학생   ▢ 반               │  ← 업무 카드 2열 (각 최소 96px)
│ ▢ 출결   ▢ 상담             │
│ ▢ 공지                      │
│  각 카드: [AI에게 요청] [직접 관리] │ ← 버튼 각 48px
└────────────────────────────┘
```
- 글씨: 본문 16px 이상, 제목 18~20px, 보조 14px 이상(대비 4.5:1 이상).
- 터치 영역 48~56px, 버튼 간격 8px 이상.
- 카드의 [직접 관리]는 현재 허용된 수동 화면으로 이동(예: 학생=`MBR-01`, 반=`CLS-01`, 출결=`ATT-03`, 상담=`CNS-01`, 공지=`NTC-01`).
- **현재 AI로 실행 가능한 범위(도구 기준)**: 학생 조회, 결석 조회, 숙제 미제출, 성적 변화, 운영 리포트(읽기) + 학생 등록·반 배정·공지 초안(쓰기, 승인 필요). 상담 기록·출결 입력·반 생성/종료는 P3 전까지 **[AI 미지원 — 직접 관리]** 로 표시.

### 2.2 응답 카드 (읽기)
```
┌────────────────────────────┐
│ 오늘 결석 · 3명             │
│ ─ 김민수  월수금반          │
│ ─ …                        │
│ [출결 화면에서 보기] [닫기] │
└────────────────────────────┘
```
- 표는 모바일에서 카드 목록으로 접힘. 개인정보는 화면에만 표시.

### 2.3 승인 카드 (쓰기, 계획 PENDING)
```
┌────────────────────────────┐
│ ⚠ 아직 저장되지 않았어요     │  ← 승인 전 상태 명시
│ 학생을 반에 배정합니다       │
│  김민수(ID 12) → 월수금반    │  ← 서버가 만든 미리보기
│  현재 소속: 없음            │
│ 10분 안에 승인해 주세요 07:42│
│ [ 승인하고 실행 ]  (56px)   │
│ [ 취소 ]           (48px)   │
│ AI 설명(참고): …            │  ← 모델 문장은 '참고'로 구분
└────────────────────────────┘
```
- 변경 내용은 **서버 미리보기**만 사용. AI 문장은 "참고" 라벨로 분리.
- 승인 버튼은 한 번 누르면 비활성화(중복 방지), 서버도 1회 보증.

### 2.4 상태 화면
| 상태 | 표시 | 다음 행동 |
|------|------|-----------|
| 로딩 | 스켈레톤 + "확인하는 중" (reduced-motion이면 정지 상태) | 취소 가능 |
| AI 실패 | "AI 연결에 문제가 있어요. 직접 관리로 이어갈 수 있어요" | [직접 관리] [다시 시도] |
| 이해 못함 | "요청을 이해하지 못했어요" + 예시 칩 | 예시 선택 |
| 지원 안 함 | "아직 AI로 처리할 수 없어요" + 해당 수동 화면 | [직접 관리] |
| 권한 부족 | "원장 권한이 필요한 작업이에요" | 읽기 대체 제안 |
| 승인 취소 | "취소했어요. 바뀐 내용은 없어요" | 새 요청 |
| 만료 | "시간이 지나 취소됐어요. 다시 요청해 주세요" | 새 요청 |
| 실행 실패 | "실행하지 못했어요. 바뀐 내용을 확인해 주세요" (자동 재시도 없음) | [직접 관리] 확인 |
| 실행 결과 불명(`FAILED(UNKNOWN)`) | "결과를 확인하지 못했어요. 목록에서 직접 확인해 주세요" | [직접 관리] |
| 성공 | 결과 카드 + "완료" | 다음 업무 칩 |
| 허용되지 않은 화면 | #825의 안내 페이지(복귀·이전·다시 시도) | 기존 동작 유지 |

## 3. PC 1440px
```
┌ 헤더 ─────────────────────────────────────────────┐
├ 좌: 업무 카드 세로 목록(학생·반·출결·상담·공지) ┬ 중앙: AI 대화·응답 카드 ┬ 우: 진행 중 계획/최근 결과 ┤
└───────────────────────────────────────────────────┘
```
- 중앙 열이 주 영역(최대 폭 760px). 좌측은 **보조 내비게이션**(수동 화면 링크), 우측은 대기 중 계획(승인 필요/만료 임박)과 최근 실행 이력.
- 키보드: 입력창 포커스 기본, Enter 전송(IME 조합 중에는 전송하지 않음), 승인 버튼은 Tab으로 도달, Esc는 취소 확인.

## 4. 접근성·모션
- `prefers-reduced-motion: reduce` → 모든 전환·스켈레톤 애니메이션 제거(정지 상태 표시). 진행은 텍스트로도 제공.
- 상태 변화는 `aria-live="polite"` 영역으로 읽어 줌. 승인 카드는 `role="group"` + 제목 연결.
- 색만으로 상태를 구분하지 않음(아이콘+텍스트). 포커스 링 표시. 대비 4.5:1 이상.
- 입력창에는 보이는 라벨 또는 `aria-label`. 오류는 입력창 아래에 텍스트로.

## 5. 기술 제약 (구현 시)
- BuildIt 프런트는 Thymeleaf SSR + 순수 JS가 기본이다. 새 프런트 빌드 체인을 추가하려면 07번의 선정 기준을 통과해야 한다.
- AcademyCraft 화면은 별도 정적 HTML이므로, AI 비서 홈을 BuildIt 쪽 템플릿으로 둘지 AcademyCraft 쪽 화면으로 둘지는 **[결정 필요]** (06번): 권장은 BuildIt 쪽 홈(Muse 호출과 같은 곳, 로그인 문맥 공유) + AcademyCraft 수동 화면 링크.

## 6. 미구현 표시 규칙
- 아직 구현되지 않은 카드·버튼은 비활성 + "준비 중" 대신 **실제 가능한 대체 경로(직접 관리)** 를 제공한다.
- 운영 전 검증 항목(390px·1440px 실화면, ADMIN·TUTOR 로그인 후 확인)은 **[미검증]** 이며 구현 PR의 검증 보고서에 별도로 남긴다.
