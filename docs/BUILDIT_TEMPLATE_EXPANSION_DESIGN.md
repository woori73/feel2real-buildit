# BuildIt 템플릿 확장 설계 (2단계, 별도 변경)

> **원칙**
> - 기존 5종 프리셋(EXAM, ENGLISH, ARTS, STUDY, ONLINE) 유지 — 운영 배포에 영향 없음
> - 색상 변경이 아닌 레이아웃·섹션 구성의 실질적 차이
> - 기존 builderDraft 키 형식 호환 유지 (편집기·게시 파이프라인 변경 없음)
> - Lovable 디자인은 참고만, 코드·이미지 직접 복제 금지

## 1. 기존 5종 (유지)

| 프리셋 | 용도 | 핵심 레이아웃 |
|--------|------|--------------|
| EXAM | 입시학원 | 성적 향상 그래프, 합격 실적 |
| ENGLISH | 어학원 | 레벨 테스트, 커리큘럼 단계 |
| ARTS | 예체능 | 작품 갤러리, 강사 프로필 |
| STUDY | 보습/공부방 | 시간표, 학습 관리 |
| ONLINE | 온라인 교육 | 강의 목록, 수강 신청 |

## 2. 신규 템플릿 (5종 추가 제안)

### 2.1 EXAM_INTENSIVE (입시 집중형)

**차별점**: 기존 EXAM이 종합 입시학원이라면, INTENSIVE는 재수/N수·특목고 등 집중 과정 특화

| 섹션 | 구성 |
|------|------|
| 히어로 | D-Day 카운터 + 합격자 인터뷰 영상 |
| 섹션 1 | 월별 성적 추이 차트 (시각적 강조) |
| 섹션 2 | 합격 대학 로고 월 (그리드) |
| 섹션 3 | 집중 프로그램 (기숙/반수/독학) 탭 |
| CTA | 입학 테스트 신청 |

**데이터 키**: 기존 키 재사용 + `sec-counter.target-date`, `sec-logos.items`

### 2.2 LANGUAGE_KIDS (어린이 어학원형)

**차별점**: 기존 ENGLISH가 성인/중고생 중심이라면, KIDS는 유아·초등 학부모 타겟

| 섹션 | 구성 |
|------|------|
| 히어로 | 밝은 파스텔 배경, 캐릭터 일러스트 영역 |
| 섹션 1 | 연령별 프로그램 (4-7세/8-10세/11-13세) 카드 |
| 섹션 2 | 학부모 후기 (사진 + 인터뷰) |
| 섹션 3 | 셔틀버스 노선 안내 |
| CTA | 무료 체험 수업 신청 |

**데이터 키**: 기존 키 재사용 + `sec-age-groups.items`, `sec-shuttle.routes`

### 2.3 ARTS_PORTFOLIO (포트폴리오형)

**차별점**: 기존 ARTS가 학원 소개 중심이라면, PORTFOLIO는 학생 작품 전시 중심

| 섹션 | 구성 |
|------|------|
| 히어로 | 풀스크린 작품 슬라이더 |
| 섹션 1 | 포트폴리오 갤러리 (메이슨리 그리드) |
| 섹션 2 | 입시 실적 (합격 학교 리스트) |
| 섹션 3 | 강사진 (작품 + 약력) |
| CTA | 포트폴리오 상담 신청 |

**데이터 키**: 기존 키 재사용 + `sec-gallery.items` (이미지 배열)

### 2.4 STUDY_CAFE (스터디카페형)

**차별점**: 기존 STUDY가 수업 중심이라면, CAFE는 공간·시설 중심

| 섹션 | 구성 |
|------|------|
| 히어로 | 시설 파노라마 이미지 |
| 섹션 1 | 좌석 타입 (1인실/다인실/카페존) 요금표 |
| 섹션 2 | 시설 갤러리 |
| 섹션 3 | 이용 시간·위치 (지도) |
| CTA | 당일 이용권 구매 |

**데이터 키**: 기존 키 재사용 + `sec-pricing.tiers`, `sec-hours.table`

### 2.5 ONLINE_LIVE (라이브 강의형)

**차별점**: 기존 ONLINE이 VOD 중심이라면, LIVE는 실시간 수업 중심

| 섹션 | 구성 |
|------|------|
| 히어로 | 다음 라이브 카운트다운 |
| 섹션 1 | 주간 라이브 스케줄 (요일별 시간표) |
| 섹션 2 | 강사진 (라이브 전문) |
| 섹션 3 | 수강 후기 (별점) |
| CTA | 라이브 체험 신청 |

**데이터 키**: 기존 키 재사용 + `sec-schedule.weekly`, `sec-countdown.target`

## 3. 호환성 보장

### 3.1 데이터 형식

- 모든 신규 템플릿은 기존 builderDraft 키를 재사용
- 신규 섹션 키는 `sec-{name}.*` 네이밍 규칙 준수
- 기존 편집기가 모르는 키는 무시 (하위 호환)

### 3.2 편집기 호환

- 신규 템플릿도 동일한 GrapesJS 컴포넌트 구조 사용
- `planChanges`의 componentId 해석 방식 변경 없음
- 기존 홈페이지 렌더링 파이프라인 변경 없음

### 3.3 마이그레이션 불필요

- DB 스키마 변경 없음
- 기존 5종 프리셋 동작 변경 없음
- 신규 템플릿은 `designPreset` allowlist에 추가만 하면 됨

## 4. 구현 단계 (별도 PR)

1. **Phase 1**: `designPreset` allowlist에 5종 추가 (백엔드 1줄)
2. **Phase 2**: 각 템플릿의 기본 섹션 구성 JSON 정의
3. **Phase 3**: 미리보기 검증 (PC + 모바일 390px)
4. **Phase 4**: `AcademyAiCreateService`의 템플릿 선택 로직에 신규 타입 매핑
