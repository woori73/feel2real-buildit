## 2. 구현 내용

| 구성요소 | 역할 |
|---|---|
| `AdmissionsKnowledgeBuildService` | 전형·일정·공식자료 행 → 지식 항목 생성. dedup_key 멱등(재실행 무중복, 본문 변경 시에만 갱신+version 증가, 승격 상태 보존), 본문에 "근거 자료: {출처 제목}" 포함, DRAFT 생성(자동 승격 없음), 학년도 ≤2027이면 year_confirmed |
| `AdmissionsEmbeddingService` | 임베딩 생성·upsert((knowledge_id, model_version) 1행 유지), L2 정규화 보장, 차원 검증, 단건/지정/전체/미적재분(ACTIVE 중 벡터 없는 항목) 재색인, 실패 사유 집계 반환, 트랜잭션 커밋 후 인덱스 reload |
| 관리자 API | `POST /api/admin/admissions/knowledge/build`, `POST /api/admin/admissions/knowledge/reindex` (mode=MISSING 기본/ALL/ITEM) |

## 4. 검수 시 결정이 필요한 사항

1. **제출서류 데이터 부재**: 로더가 전형 details를 모집인원·지원자격·전형방법·수능최저 4필드로만 합성해
   제출서류가 데이터에 없다. 골든 ④는 전형방법으로 대체 검증했다. 제출서류 수집·합성은 별도 과제.
2. **벡터 유사도 하한 없음** (기존 설계): 무관한 질문에도 최근접 항목이 반환될 수 있다.
   답변 제한 판정은 현재 LIKE·사실 검색 경로가 담당한다. 임계값 도입 여부를 결정해 달라.
3. **임베딩 서버 운영 구축**: service-url 미설정 상태. 서버를 어디에 세울지(별도 인스턴스 등) 결정 필요.
   설정 전까지 벡터 경로는 LIKE 폴백으로 안전하게 동작한다.
4. 지식 항목 승격 경로: build 항목은 DRAFT이며, 일괄 승격(activate-all)은 구조화 행 전용이다.
   항목 승격은 기존 검수 API(/knowledge/{id}/review) 단건 경로만 있다 — 일괄 승격 확장이 필요하면 별도 과제.
