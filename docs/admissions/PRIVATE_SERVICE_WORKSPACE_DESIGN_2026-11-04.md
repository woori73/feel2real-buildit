# 입시상담 대학 탐색·비교 — 1차 구현과 후속 설계

사용자 요청: 사설 유료 상담의 공개 UI·기능을 조사하고 Feel2Real 입시상담 AI에서 사용하기 편하게 구축한다. 공개 배치점수표도 수집하되 공식 입결과 구분한다.

## 1. 구현

- 기존 `/admissions/guide`·`/admissions/workspace`를 대학 찾기/입결 비교/내 성적/AI 상담 네 메뉴로 확장한다. 기존 관리자 적재·검수와 회원 상담은 재사용한다.
- 대학→모집단위→공식자료 상세, 최대 3개 모집단위 비교, 후보 삭제/전체 비우기, 선택 대학/학과로 기존 AI 상담을 연결한다.
- 성적은 모의고사·가채점·확정 성적을 구분해 국어/수학 선택과목·표준점수·백분위·등급, 탐구2과목, 영어·한국사 등급, 내신을 입력한다. 기존 정시 계산 API(#981)를 연결하며 확정 수능 성적일 때만 계산한다. 성적은 브라우저 저장소에 저장하지 않고 상담 전송 때 기존 요약에 포함한다.
- 비교 후보는 탭 sessionStorage에 모집단위 ID/이름·대학명·학년도만 저장한다. 추가/조회/삭제/전체 비우기를 제공한다. 회원 DB CRUD는 후속으로 분리한다.
- 새 조회는 LLM 대신 `AdmissionsExplorerService`가 기존 DB를 읽는다. 행/출처 모두 ACTIVE, 같은 대학 ID·같은 학년도 자료만. 이전 결과는 resultYear=academicYear−1, 검증 연결명 또는 원문 모집단위명 정확 일치. 원문 지표·값·출처·쪽을 그대로 돌려준다.
- 대학 전체 전형·일정을 선택 학과의 전형으로 단정하지 않는다. 화면에 대학 전체임을 표시한다. 현재/과거 모집인원·결과학년도·점수 체계도 혼합하지 않는다.
- 공개 조회는 기존 공개 API 스위치 기본 OFF를 유지하며 꺼져 있으면 DB 전에 503. 기존 IP 제한을 별도 explore 키로 적용한다. 기존 회원 ADMIN/TUTOR 및 실제 DB role·소유 학원 검증을 유지한다. 운영 쓰기·마이그레이션은 없다.
- 검색 최대 80행·입결 200행·전형 60행·일정 80행이며 초과 여부를 명시한다. 와일드카드는 문자로 검색한다. API 응답은 no-store.

## 3. 정시 계산 연결과 후속 기능

작업 중 최신 main에 #981(`74a59bd`)의 공식 계산식 엔진·V1100·공개 계산 API가 병합되어 새 엔진을 만들지 않고 재사용한다. 회원은 기존 DB 권한 확인을 거친 `/api/dashboard/admissions/explore/score`, 공개는 기존 `/api/admissions/jeongsi/score`를 호출한다. 선택 모집단위·대학 이름과 실제 입력 점수를 보내며 국어/수학 선택과목, 탐구 사회/과학I/과학II/직업 계열 및 제2외국어 응시 표시를 명시한다. 이름만으로 탐구 계열을 추측하지 않는다.

CALCULATED는 환산점수·만점, NEEDS_INPUT은 학생 누락값과 공식표 미확보값을 분리하고, WITHHELD_NEEDS_REVIEW는 검토 사유, ERROR는 계산 불가 안내를 표시한다. 전형명·적용범위·지원자격·수능 외 요소·원문쪽을 함께 표시한다. 공식 최고점/변환표는 브라우저에서 입력하거나 추정해 넣지 않는다. 학년도 변경 시 성적 문맥을 초기화하며 2028은 달라진 수능 체계 때문에 2027 성적 입력표를 사용하지 않는다.

#16 식 데이터의 원문 검토·적재/승격, 공식 변환표 연결은 운영 데이터 작업으로 별도다. 현행 계산 엔진이 있다고 모든 대학·전형에 바로 점수가 나오는 것은 아니다. 필요한 값이 없으면 상태를 보여주며 합격 가능성을 산출하지 않는다. 올해 환산점수와 지난해 입결의 스케일/공식이 다르면 차이값·안정도를 만들지 않는다. 사설 배치자료는 기관·학년도·기준시험·가/실채점·발표일·점수단위·사용범위를 별도 메타로 보관하며 기존 OFFICIAL/FACT에 넣지 않는다.

후속 순서: 계산식/변환표 운영 연결→교과/수능최저→전형/군별 후보·일정·본인 저장 CRUD→공식 면접/논술→자체 모의지원/예측 연구. 학생부 AI 업로드는 최신 서비스 제한·처리범위 확정 후 별도 설계한다. 공식 입결만으로 사설 모의지원자 순위를 만들지 않는다.

## 4. 검증과 배포

- JS 신규 3개+기존 적재 24개 통과, `node --check`·`git diff --check` 통과.
- jsdom fixture 동선 검사: 대학 조회→상세/원문지표→후보 비교→성적→공식 계산 요청/세 결과 상태→기존 상담 payload→초기화 통과. 실제 브라우저/운영 데이터 검증과 구분한다.
- Java SQL 테스트: 승인/초안·연도·대학·캠퍼스·학과 연결·원문/빈값·검색 입력 검증. Controller 테스트: 기본 OFF 503, 429, no-store, AI 일일 카운트 미소비.
- 두 Java 테스트와 JS 테스트를 기존 Build Check allowlist에 등록한다. 실제 실행 결과는 PR 검증에 기록한다.
- 운영 DB 적재 없음. 기본 공개 스위치 변경 없음. 배포 후 실제 대학 조회→상세→후보 3개/삭제→성적 적용/삭제→기존 AI 상담·관리자 도구 회귀 확인이 필요하다.

## 5. 입결 비교 탭 — 군별 정리·후보 일정 (2026-11-07)

API·DB 변경 없이 기존 상세 응답(`department.quotaInfo`, `universitySchedules`, `round`)만 쓴다.

- **입결 보기 선택**: 수시·정시 모두 / 수시만 / 정시만. 상세 API의 `round` 값을 그대로 보낸다.
- **정시 군별 정리**: `quotaInfo`(모집요강 전형별 인원 JSON)에서 이름에 '정시'가 있고 인원이 1 이상인 전형을 전형명의 군 표기(`(나군)`)로 가·나·다군에 나눈다. 합계·소계 행은 뺀다. `(가·다군)`처럼 군이 둘 이상 적힌 전형, 군 표기가 없는 정시 전형(재직자 전형 등), 읽을 수 없는 모집인원표는 "원문 확인"으로 따로 적고 한 군으로 단정하지 않는다. 같은 군에 후보가 둘 이상이면 복수지원 제한 문장을 보여 준다(근거: 동국대 2027 정시모집요강 25쪽, 홍익대 2027 정시모집요강 12쪽 "모집기간 군이 같은 대학… 복수지원 할 수 없음", 교육대학 포함·산업대학·전문대학 제외). 같은 대학 안 같은 군 여러 모집단위 지원 가능 여부는 대학마다 달라 각 요강 확인으로 안내한다. 수시만 보기에서는 군별 정리를 숨긴다.
  - 2027 시드 7,003개 학과 중 정시 모집 학과 4,856개: 전형명 군 표기와 시드 `jeongsi_group`이 일치 4,800, 군 표기 없는 정시 전형만 있음 50, 시드 필드만 있음 5, 두 군 표기 1(약학과 가·다군 — 표기대로 두 군에 표시).
- **후보 대학 전형 일정**: 후보 대학의 대학 전체 일정을 날짜순으로 합친다(같은 대학은 한 번). 오늘(한국 시간) 이전에 끝난 일정은 기본으로 숨기고 "지난 일정도 보기"로 펼친다. 날짜 없는 일정은 맨 뒤. 모집단위·전형 해당 여부는 원문 확인으로 안내한다.
- 검증: `src/test/js/admissions_explorer.test.js` 신규 5개(군 나누기 3, 한국 날짜 1, 일정 합치기 1). 실제 `guide.html`·JS·CSS를 Playwright로 띄우고 API만 고정 응답으로 바꿔 비교 탭 동선(군별 정리·같은 군 경고·두 군 표기·지난 일정 펼치기·수시만/정시만 재조회·390px 가로 넘침 없음)을 확인했다. 운영 데이터 화면 확인은 배포 후.
- 후보 수(최대 3개)와 탭 임시 보관은 그대로다. 회원 DB 저장(CRUD)은 별도.
