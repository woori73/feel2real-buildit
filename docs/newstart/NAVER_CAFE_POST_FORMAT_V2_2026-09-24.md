## 1. 서식 v2 스펙 (필수)

### 1-1. 타이포그래피 (단위: 네이버 스마트에디터 글자크기 = px)

**허용 크기(실측): `fs11 fs13 fs15 fs16 fs19 fs24 fs28 fs30 fs34`.** 이 집합 밖의 값(fs18·fs20·fs22)은 `setDocumentData`에서 거부되지 않고 그대로 저장되지만 렌더/발행 HTML에서 **15px로 붕괴**한다. 따라서 아래 표는 허용 집합 안에서만 고른다.

| 용도 | 크기 | 굵기 | 색 |
|---|---|---|---|
| 본문·불릿 내용 | **fs16** | 보통 | `#333` |
| 섹션 헤더 (`- N. "[라벨]"`, 대주제) | **fs19** | **굵게** | 섹션 고유색 (§1-3) |
| 권두/권미 대헤더 (`[○월 관측에서 보인 공통점]` 등) | **fs24** | **굵게** | `#B02A30` |
| 라벨 접두어 (`[실제 질문]` 등) | fs16 | **굵게** | 섹션 고유색 또는 `#8C6D1F` |
| 이미지 캡션 | **fs13** | 보통 | `#767676` |
| 구분선 | fs16 | 보통 | `#A0A0A0` |

- 본문에 fs13·fs15 혼용 금지. **fs16으로 통일**이 1차 목표(fs13은 이미지 캡션 전용).
- 구분선 문자: `──────────────────────────────` (U+2500 ×30).
- 발행 HTML 검증 기준: 본문은 `se-fs-fs16`가 지배, `se-fs-fs13` 잔존 수 = 캡션 수.

### 1-2. 여백 리듬 (8월 글이 가장 위배한 항목)

- 섹션 헤더 앞/뒤: 빈 문단 1개씩.
- 라벨 불릿 블록과 리드 문장 사이: 빈 문단 1개.
- 섹션과 섹션 사이: 빈 문단 1개.
- **이미지 캡션 다음에도 빈 문단 1개**를 두어 캡션이 아래 본문과 붙어 읽히지 않게 한다.
- 빈 문단도 fs16 (fs13 빈 줄 섞이면 줄간격이 튀어 보인다).
- **본문 들여쓰기**: 불릿은 앞공백 대신 full-width space + `·`(`　· `)로 시작한다. 마크다운 하이픈(`- `)은 에디터에서 자동 리스트로 변환되어 문서 모델이 깨지므로 쓰지 않는다. 세로로 긴 목록에서도 줄이 붙어 읽히지 않는다.
- **한 문단에 라벨을 연속으로 박지 않는다.** `[주의]`·`[현재 확인 필요]`는 행을 새로 써서 분리한다. 단, 문장 중간에 붙은 인라인 각주형 라벨(`[공식 확인].` 등)은 새 행으로 빼면 안 된다 — 분리 정규식에 `(?!\s*[.])` lookahead를 두어 막는다.

### 1-3. 섹션 색상 팔레트 (Tableau10 계열, 순서대로 1섹션 1색)

`#4E79A7` `#E15759` `#F28E2B` `#76B7B2` `#59A14F` `#B8860B` `#AF7AA1` `#C44E70` `#9C755F` `#17BECF`
- 같은 섹션 안에서는 헤더·라벨·강조어가 **모두 같은 색** 계열로 묶이도록 한다(섹션 단위 시각 덩어리 인지). **인용 각주 토큰(`(5904)`, `P788341`)도 예외가 아니다** — 본문 `#333`과 섞어 다른 섹션 색을 물리면 오독한다(6030 12번에서 초록이 섞인 채로 발행됐다가 9/24 수정).
- 8월 글처럼 대주제가 4개면 팔레트도 **앞의 4색만** 쓴다(6031: `#4E79A7` `#E15759` `#F28E2B` `#76B7B2`). 항목마다 색을 바꾸면 "섹션 단위 덩어리"가 성립하지 않는다.

### 1-4. 항목 내부 구조 — 9월과 8월을 같은 골격으로 묶지 않는다

**원칙을 좁힌 사유**: 8월 두 글은 원문 자체가 짧은 사례 요약이다. 9월용 골격(`[실제 질문]→[카페 답변]→[정리]`)을 8월에 그대로 덮으면 **원문에 없는 `[정리]`를 만들어 내는 작업**이 된다. 권위 부여 금지(§5)와 어긋나므로 8월은 아래처럼 처리한다.

- **6029(9월)**: 아래 골격 유지. 하는 일은 서식(크기·색·여백)과 그래픽뿐, 문구는 손대지 않는다.
- **6030·6031(8월)**: **원문을 최소한으로 편집해 가독성만 높인다.** 항목별로
  ```
  fs19 굵게 섹션색 | - N. [등급 라벨]            ← 대주제 아래 소항목
  fs16 빈 줄
  fs16 | 　· 내용 1 (~140자, 인용·수치·회차는 볼드+섹션색)
  fs16 | 　· [주의] / [현재 확인 필요] / [정정] 는 반드시 새 행
  fs16 빈 줄
  ```
  골격만 따른다. **항목별 `[정리]`는 쓰지 않는다** → 전체를 묶는 `[정리]`는 권미의 `[N월 관측에서 보인 공통점]` 1개(또는 글 마지막 요약 블록)로 충분하다.
- **라벨 어휘(실제 사용분으로 확정)**: `[실제 질문] [카페 답변]`는 9월 전용. 8월은 등급 라벨 `[공식 확인] [운영자 장기 경험] [운영자 확인] [실제 사례] [커뮤니티 의견]` + 서술 라벨 `[주의] [정정] [현재 확인 필요] [꼭 기억할 것]`. 이 밖에 새 라벨을 만들지 않는다.
- 한 라벨 불릿은 **2~3행(약 140자) 이내**. 길면 두 불릿으로 쪼갠다(단, §1-2의 인라인 각주형 라벨은 분리 금지).
- 8월 글의 강점인 **출처 글번호 각주(`5916`, `P777149`)는 반드시 유지**하고, 불릿 끝에서 **볼드+섹션색**(fs13 회색은 이미지 캡션 전용이므로 각주에는 쓰지 않는다).
- **금액 관련 필수 강조**: 감면 이후 상환액은 `감면받은 금액 + 재산가액`이다. 순부채·감면율만 언급해 "감면율이 크면 다 줄어든다"로 읽히는 항목에는 `[꼭 기억할 것]` 라벨로 총 상환식 `총 상환액 = 순부채 × (1 − 감면율) + 재산가액`, `순부채 = 원금 − 재산가액`을 명시한다(6030 2번에 적용).

### 2-2. 기존 글 수정 화면

- URL: `https://cafe.naver.com/ca-fe/cafes/31312978/articles/{articleId}/modify`
  (목록→본문→`수정` 클릭과 동일 도착지. 구형 `ModifyArticle.nhn` 경로는 "서비스 접속 불가"이므로 쓰지 않는다.)
- 편집기 인스턴스: `const ed = window.SE.launcher.getEditor('cafepc001');`
  - `ed.getDocumentData()` → `{document:{version,theme,language,id,components:[…]},documentId}`. components은 text뿐 아니라 **`@ctype:'image'`를 섞어 갖는다**(사진 1장 = top-level image component 1개이고, 그 자리에 본문 text component가 둘로 나뉜다). 즉 이미지를 넣은 뒤 문서를 다시 조립하려면 **text 문단 배열과 image component를 번갈아 배치**해야 한다.
  - paragraph = `{id:'SE-<uuid>', '@ctype':'paragraph', nodes:[textNode…]}`
  - textNode = `{id:'SE-<uuid>', value:'문자열', style:{'@ctype':'nodeStyle', fontSizeCode:'fs16', fontColor:'#333', bold:true}}`
    - `fontSizeCode`는 `fs` + px 숫자(fs16 = 16px, 실측 확인). **허용값은 §1-1의 9종뿐**(`fs18/fs20/fs22`는 저장되는 듯 보이다 15px로 붕괴). `fontColor`는 대문자 hex. 굵게는 `bold:true`.
    - 한 문단에서 라벨만 색+볼드, 나머지는 `#333` 보통으로 하려면 **nodes를 2개로** 넣는다.
    - 문서 객체를 `JSON.parse(JSON.stringify(x))`로 복제하면 문단이 증식/소실하는 경우가 있었다. **조립한 문단 배열(`window.__b3` 같은)을 명시적으로 components에 넣어** setDocumentData 한다.
  - `ed.setDocumentData(data)` → 재렌더 확인 완료. **호출과 검증을 같은 evaluate에 섞지 말 것**(94문단 재렌더는 15초를 넘긴다. set → 별도 호출에서 read).
  - **렌더러 웨지(wedge) 주의**: 사진 툴바 클릭, 130문단 이상 재렌더가 겹치면 CDP `evaluate`가 전부 타임아웃되고 `navigate_page`는 ERR_ABORTED, `list_pages`·`select_page`·`press_key`만 동작한다. 대화상자도 안 잡힌다. **6~12분 방치하면 저절로 풀리고 그때 문서에는 변경이 반영돼 있다.** 지연을 줄이려면: 스크립트를 작게, 이미지 component JSON은 조립 전에 `window.__imgs`로 백업, 웨지 중에는 재시도 사격을 하지 않는다.
  - 저장 후 발행 HTML에서는 클래스가 `se-fs-fs16` 형태로 변환되고 색은 inline `style="color:#f28e2b;"`로 내려간다(검증은 클래스가 아니라 inline 색 문자열로).

### 2-3. 이미지 첨부 (실측 성공 절차)

1. `document.querySelector('button.se-image-toolbar-button').click()` → 에디터가 `input#hidden-file`(dynamic, `multiple`, accept에 png)을 만든다. **클릭 후에야 생성되므로 클릭 전에는 탐색하지 않는다.**
2. 그 input에 `aria-label`을 붙이고 `position:fixed`+크기+`opacity:1`로 **화면에 드러나게** 한다(가려진 input은 upload 도구가 잡지 못한다).
3. 페이지 snapshot을 파일로 저장 → 그 파일에서 `aria-label` 문자열을 grep해 `uid`를 얻는다(본문을 컨텍스트에 올리지 말고 `-o`로 uid 라인만 뽑는다).
4. `upload_file({uid, filePath})` **1회 1장**. 업로드가 끝나면 input은 소멸하므로 다음 장은 1번부터 다시(이 반복이 웨지 확률을 높인다 → 연속으로 몰지 않고 매번 component 수만 확인).
5. 업로드된 image component는 `fileName`으로 식별해 배치하고, 캡션 문단(fs13 `#767676`)은 **그 이미지 바로 뒤 text component의 첫 문단**으로 넣는다.
- 실패 시: `ed.execCommand('insertImagesByUrl', …)` / `SmartEditor.COMMAND.IMAGE.INSERT_IMAGE_FILES`는 이번 세션에서 동작을 확인하지 못했다. 30초 안에 포기하고 위 툴바 경로로 바꾼다.
- 이미지가 아예 실패하면 §1-5 텍스트 그래픽 대체로 즉시 전환(글 전체 저장을 막는 장애로 취급하지 않는다).

### 2-4. 저장과 검증

1. `ed.setDocumentData(새 문서)` → (별도 호출) 렌더 확인
2. `등록` 버튼 클릭
3. 별도 호출로 §2-1 fetch 재실행 → `contentHtml`에서 검증(발행본 `<p>`/`<img>`/`<b>` 수와 `se-fs-*` 분포, inline 색):
   - `se-fs-fs16` 본문 지배, `se-fs-fs13` 수 = 이미지 캡션 수(±0)
   - 헤더 `se-fs-fs19` 수 = (대주제 + 소항목 헤더) 수, 권두·권미 대헤더 `se-fs-fs24` ≥ 1
   - 색상 종류 ≥ 6, 볼드 노드 수가 문단 수의 30% 이상
   - 빈 문단(fs16)이 섹션 경계와 캡션 뒤에 존재

   - 한 섹션 안의 인용 각주 토큰 색 = 그 섹션 헤더 색 (색 문자열 대조로 감사)
4. 실패 항목은 보고의 `미진` 칸에 남긴다.

## 4. Phase 2 — 6030·6031(8월) 재편집

Phase 1 완료 검증 후 착수. 기준은 "6029의 실제 렌더"이고, 이 문서의 숫자 스펙과 어긋나면 **6029를 기준으로 삼고 이 문서를 수정**한다.

1. 6030/6031의 항목 21·22개는 **압축 요약**이다. 다만 압축을 푼다며 9월식 `[정리]`를 항목마다 붙이는 일은 **하지 않는다**(§1-4). 원문을 조금 편집해 **가독성만 올리는 것이 목표**이고, 전체를 묶는 정리는 권미 1개다.
2. 근거를 손에 잡히게 만드는 순서는 이렇다: ① 항목마다 본문에 박힌 근거 글번호(`5916`, `P782989` …)를 §2-1로 열어 **큰따옴표 인용과 댓글 문장을 회수**한다 ② 회수한 문장으로 한 줄에 섞인 "사실/추정/경고"를 서로 다른 라벨 행으로만 나눈다 ③ **원문을 열 수 없거나 인용이 없는 항목은 확장하지 말고 `[현재 확인 필요]`를 그대로 둔다**. 이번 실행에서 6031은 항목별 원문 재확인을 새로 하지 않고 라벨 분리·여백·색인으로만 편집했다(숫자를 하나도 더하지 않았다).
