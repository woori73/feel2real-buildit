## 확장 시 예상 문제 (100개/1,000개 게시글)

### 기술적 이슈
1. **네이버 카페 iframe 구조**: 메인 페이지와 실제 콘텐츠가 별도 iframe(cafe_main)에 있어 이중 탐색 필요
2. **동적 로딩**: 게시글 목록/본문이 JavaScript로 렌더링되어 정적 크롤링 불가
3. **페이지네이션**: 게시판당 페이지 수 많음 (페이지당 20-50개, 1000개면 20-50페이지)
4. **속도 제한**: 연속 요청 시 차단/캡차 위험 (적절한 딜레이 필요: 2-5초/요청)
5. **세션 만료**: 장시간 실행 시 로그인 세션 갱신 필요
6. **댓글 페이지네이션**: 댓글 많은 글은 "더보기" 클릭 필요 (AJAX 로드)

### 데이터 품질 이슈
1. **개인정보 마스킹**: 전화번호, 계좌번호, 이름 등이 `000` 등으로 마스킹됨
2. **광고/스팸 필터링**: 파워링크 광고 iframe 별도 존재
3. **삭제/비공개 글**: 접근 권한 없는 글 스킵 처리 필요
4. **이미지/첨부파일**: 별도 다운로드 로직 필요 (CDN URL, 인증 필요할 수 있음)

## AI 모델 토큰 사용 최소화 설계

### DOM 추출만으로 처리 가능 (AI 불필요)
- 게시글 목록에서 글번호, 제목, 작성자, 작성일, 조회수, 댓글수 추출
- 게시글 본문 텍스트 전체 추출 (iframe 내 DOM 파싱)
- 댓글 리스트 텍스트 전체 추출
- 첨부파일 링크/파일명/크기 메타데이터 추출
- URL, 게시판명, 카페명 등 구조적 메타데이터
- HTML → 정제된 텍스트 변환 (태그 제거, 줄바꿈 정리)

### AI 토큰 실제로 사용해야 하는 부분
1. **본문 구조화/분류**: 
   - 질문/답변/공지/후기 등 글 유형 분류
   - 본문 내 핵심 엔티티 추출 (금액, 날짜, 기관명, 상품명 등)
   - 개인정보 탐지/마스킹 검증

2. **댓글 분석**:
   - 질문글에 대한 답변 댓글 매칭 (작성자 댓글 vs 타인 댓글)
   - 댓글 감정 분석 (긍정/부정/중립)
   - 해결 여부 판정 (질문자에게 도움이 되었는지)

3. **충돌 판정/중복 제거**:
   - 동일 내용 중복 게시글 탐지 (제목/본문 유사도)
   - 수정/삭제된 글 변경 이력 추적

4. **요약/인사이트 생성**:
   - 게시글/댓글 요약 (한 줄 요약, 핵심 키워드)
   - 트렌드 분석 (기간별 키워드 빈도, 이슈 발굴)

## 비용 최소화 전략
- **1단계 (수집)**: Playwright만으로 HTML/DOM 수집 → 로컬 저장 (토큰 0)
- **2단계 (정제)**: 정규식/룰 기반 텍스트 클리닝 → 구조화된 JSON (토큰 0)
- **3단계 (AI 처리)**: 필요한 최소 단위만 LLM 호출 (글당 ~500-1000 토큰)

  - 캐싱으로 동일 패턴 재사용
